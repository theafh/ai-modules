# Give the gate a citation form for absence claims the verifier can keep

## Goal

When `auto_gate_task` clears a content-lens item because the task body holds no instance of what the lens looks for, its `## Checklist` line cites the sections it read in full and names what it looked for. `auto_verifier_task`'s citation mode keeps that claim when the named sections, read in place, hold no instance, and refutes it when they hold one or name fewer sections than the item covers. A task that is clean on first read can then pass `task_auto_check`'s immediate-ready refutation.

## Context

All agent paths are under `plugins/ai_dev/agents/`.

- **The gate can cite only a span.** The `## Checklist` template in `auto_gate_task.md` gives a cleared content-lens line one form: `clean — cited: <artifact read> :: "<verbatim span that settled the item>"`. Its walk rule keeps "the citation to that pointer plus the span it turns on" and adds that existence checks "never on their own clear the content lens".
- **The verifier refutes existence spans.** The citation-mode rule in `auto_verifier_task.md` refutes a claim whose span "establishes only an existence fact for an item the gate's own contract holds that existence checks cannot clear".
- **Absence claims have no span.** Several base `<readiness_checklist>` lenses in `plugins/ai_dev/skills/task/SKILL.md` clear only when the body lacks something, such as **Restated standing rules**, **Rule-waiving exclusions**, and **Sensitive or user-specific detail**. No single verbatim span shows that something is absent, so the gate cites a span that exists, and the verifier refutes it under the rule above.
- **Evidence.** Runs of `immediate_ready_citations_survive` on both vendors on 2026-11-15 show the gap:
  - A Cursor run refuted 8 citations.
  - After the fixture fix, a later Cursor run still refuted the three absence lenses above. Their spans were a `CLAUDE.md` line, the `## Approach` heading, and the Goal sentence, and each refutation reason says the span shows only that something exists.
  - A Claude run, on the fixed fixture, refuted the same three lenses. Its spans were the `CLAUDE.md` line "run the bundled task linter after edits", an Approach sentence about editing `build_throttle_response()`, and the `reported-by` frontmatter field, and its reasons say the first two show only that something exists and the third lies outside the body the item judges.
- **Where citations came from.** [The gate-evidence task](archive/task-family_gate-evidence-and-refutation.md) introduced the citation on every cleared line and the existence rule. This task adds the absence form that task left out.

[The return-layout task](archive/task-family_gate-verifier-return-layout.md) edits the same two agents' output contracts, so land this task after it.

## Approach

1. In `auto_gate_task.md`, rewrite the content-lens line of the `## Checklist` template in place so it carries a second cleared form for an item cleared on absence: the task path, the section headings read in full, and what the gate looked for and did not find, as in `clean — absent: tasks/<file>.md :: ## Goal … ## Acceptance :: no **Out of scope:** entry`. Rewrite the walk rule's citation sentence in place, so a presence claim keeps the span form and an absence claim takes the new form, covering every section the lens judges. Rewrite the `<output_contract>` paragraph after the template in place as well, replacing its sentence "The content-lens line's `clean` value carries its citation in the template's two parts (the artifact read and the verbatim span that settled the item)" with a statement that the `clean` value carries either the span form or the absence form the template defines. Define the covered set in one place: the body sections from `## Goal` through `## Acceptance`, `## Context` and `## Approach` included and the frontmatter and `# Title` excluded; the gate's absence citation names exactly that set, and both that `<output_contract>` paragraph and `auto_verifier_task.md`'s citation-mode rule state it. On a scoped re-check, where the walk rule judges only the prior blocking issues and the changed text, the absence form names the changed sections the gate read and labels the round in the citation, as in `clean — absent: tasks/<file>.md :: changed text in ## Approach (scoped round) :: no **Out of scope:** entry`; the full-round form names every section the lens judges, and the scoped form names only the changed sections and says so, so neither form overstates what was read.
2. In `auto_verifier_task.md`, rewrite the citation-mode rule and the citation-mode `citation:` field of its return template in place so both carry the absence form beside the span form, keeping one field rather than adding a second. The rule judges an absence citation by reading the named sections in place: it keeps the claim when they hold no instance of what the claim names and refutes it when they hold one or omit a section of the covered set Approach step 1 defines, while the existence-fact refutation stays for span citations. When a claim's named sections both hold an instance and omit a section of the covered set, the instance ground leads and the reason names the found instance. Judge a citation carrying the scoped-round label against the sections it names, without the fewer-sections refutation: that label marks those sections as the set the round judged, so the claim is kept when they hold no instance and refuted only when they hold one. The field's one line takes either value, `<artifact read :: verbatim span, as the gate verdict recorded it>` for a span citation and `<artifact read :: section headings read :: what was looked for and not found, as the gate verdict recorded it>` for an absence citation. In the same file's `<inputs>`, add the live task path and the standing-rule sources the absence lenses compare against — the repo rules, and `CHARTER.md` for a waived guardrail boundary — to the citation-mode input list, and state there that an absence claim is judged against the live task file read at call time, with `frozen-task.txt` staying the record of the frozen text. Make the same input-list addition to the citation-mode prompt rule in `plugins/ai_dev/skills/task_auto_check/SKILL.md`, which today admits the gate return, `frozen-intent.txt`, and `frozen-task.txt` only.
3. In scenario s15 of `tests/task_auto_check/script_tests/run.sh`, add `assert_contains` pins for the new template form and both rewritten rule sentences, add `assert_contains` pins for the scoped-round sentence in step 1 and the scoped-round keep sentence in step 2, and pin each replaced sentence's removal with the harness's existing `assert_not_contains_re`, escaping that sentence's regex metacharacters (`**`, backticks, parentheses) so the pattern matches the superseded text literally.
4. In `tests/task_auto_check/evals/fixtures/absence_citation_refuted/`, stage a task body that holds an instance for each of the two absence lenses below — a repo standing rule restated in `## Context`, and a rule-waiving `**Out of scope:**` entry in `## Approach` — beside a citation-mode gate return holding two absence claims, each naming its lens and the "no X" it looked for. The first reads `clean — absent: tasks/<file>.md :: ## Goal … ## Acceptance :: no **Out of scope:** entry`, clearing **Rule-waiving exclusions** over the whole covered set, so its named sections hold the `## Approach` waiver and only the instance ground can fire. The second reads `clean — absent: tasks/<file>.md :: ## Goal and ## Approach :: no restated repo standing rule`, clearing **Restated standing rules** over an explicit two-heading list that deliberately names fewer sections than the covered set, so its named sections hold no restated standing rule and only the omission ground can fire. Run `auto_verifier_task` on that pair once on the default vendor and commit its citation-mode return in the same directory. Pin in scenario s15 of `tests/task_auto_check/script_tests/run.sh` that the recorded return refutes each claim, its reason naming the `## Approach` `**Out of scope:**` entry for the first and the omitted `## Context` and `## Acceptance` sections for the second.

## Acceptance

1. `auto_gate_task.md`'s template and walk rule carry the absence form beside the span form, the `<output_contract>` paragraph after the template names both forms in place of its span-only sentence, and `auto_verifier_task.md`'s citation-mode rule and return-template `citation:` field carry it, the rule judging an absence citation as Approach step 2 describes. Both files name the same covered set, and the citation-mode input lists in `auto_verifier_task.md`'s `<inputs>` and in `task_auto_check/SKILL.md` name the live task path and the standing-rule sources, and state that an absence claim is judged against the live task file read at call time.
2. `bash tests/task_auto_check/run_all.sh` passes, including the new pins.
3. `immediate_ready_citations_survive` runs on the default vendor, every citation survives, and the verdict is recorded in `tests/task_auto_check/evals/README.md`. If a citation is still refuted, the record names its item and reason, and the task stays open.
4. A round-labelled absence citation naming only the changed sections is kept when those sections hold no instance and is not refuted for naming fewer sections than the lens covers, pinned in scenario s15.
5. `tests/task_auto_check/evals/fixtures/absence_citation_refuted/` holds the staged body, the gate return with its two absence claims as step 4 states them, and the verifier's citation-mode return, and that return refutes the **Rule-waiving exclusions** claim naming the whole covered set with a reason naming the `## Approach` `**Out of scope:**` entry, and refutes the **Restated standing rules** claim naming `## Goal` and `## Approach` with a reason naming `## Context` and `## Acceptance` as omitted sections. Scenario s15 pins both recorded verdicts.
