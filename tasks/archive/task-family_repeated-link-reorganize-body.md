# Answer a repeated-link warn by reorganizing the task body

## Goal

The task linter's `repeated-link` warn fires when one task body links the same local target more than once. After this task, the `task_*` family reads that warn as a sign that the body is poorly organized: material that belongs together has spread across several sections, and each section links the target again. Every surface that writes a task body, the create path included, answers the warn by re-reading the body, judging whether its sections should be grouped better, and reorganizing them so that what belongs together sits together. Fewer links are the result of that reorganization rather than its aim. The judgement concerns how the body is organized and never whether a single link makes sense on its own, and only the user decides to leave a repeat in place.

The user-visible outcome is that a create, update, auto-check, or backlog-repair run that meets the warn reports either a reorganized body or a finding surfaced to the user with an organizational reason, and never a finding kept because each link earns its place.

## Context

The linter needs no change. `check_repeated_links` in `plugins/ai_dev/skills/task/scripts/lint.py` already describes the count as "a hint that material about it sits in several places and the body may have grown organically; re-read those sections and gather what belongs together". The gap lies in the prose that tells agents how to react.

The base `task` skill, `plugins/ai_dev/skills/task/SKILL.md`, turns that hint into a judgement about single links:

- The `<markdown_policy>` bullet led by **Gather what the body says about one link target into one place: the grouping rule.** carries a sentence beginning "Keep a further link to the same target where that site earns it on its own", which names its carve-outs: an edit site named in Approach that Context introduced as background, and an `**Out of scope:**` deferral naming the owner of excluded work. The bullet's closing sentence hands the question to the value test of the cross-reference bullet before it.
- The `<lint>` warn bucket says "Treat each `repeated-link` warn as a candidate, not a verdict" and asks for triage "matching the soft-pointer warning", which frames the warn like a check that produces false positives.
- The paragraph led by **Repeated-link react protocol.** gathers material only "Where two or more sections carry the same account", keeps "each surviving link where its site earns it on its own", and reports a count above the floor "as kept because each site earns its link". Under its sentence beginning "A link travels with the clause that carried it", the pointer a gathering leaves behind keeps its link, so the count can stay where it was. The sentence beginning "Four surfaces own the regroup" names the writing owners without the create path, and the sentence beginning "The mechanically fixable set omits `repeated-link`" repeats that owner count. The block led by **Repeated-link disposition line.** spells the kept value as `kept because each site earns its link` and names `task_fix` and `task_auto_check` as the consumers of the line shape.
- The `<body>` rule led by **Declare exclusions as an Out of scope boundary** says a deferral "links the sibling task that owns it", so a sibling that Context also introduces always draws a second link.

The siblings and agents that apply the protocol repeat the per-link framing:

- In `plugins/ai_dev/skills/task_fix/SKILL.md`, the **Remediate.** step applies the regroup by "gathering the repeated account into its owning section and leaving the surviving links each site earns". The `<surface_for_review>` entry led by **Repeated-link findings** lists the cases left to a human, and the `<output_contract>` lists the kept disposition and explains it in a sentence beginning "A kept finding enters neither count".
- In `plugins/ai_dev/skills/task_auto_check/SKILL.md`, the Grouping advocate stance in `<plan_repairs>` proposes "gathering the body's repeated account of the counted target into the section that owns it by the `<body>` anatomy". The rule led by **Repeated-link disposition filter.**, the `<finalize_mechanical_lint>` step, and the `<output_contract>` all carry the kept disposition.
- In `plugins/ai_dev/agents/`, the Grouping advocate stance of `auto_reviewer_task` proposes "gathering a repeated account into the section that owns it", `auto_verifier_task` judges regroup proposals and plans against the protocol, and the `auto_shaper_task` `<remediate>` sentence beginning "For a repeated-link regroup" gathers "the repeated account into the section that owns it".

The paths that write a body from scratch never answer the warn. The hub's `<lint_after_create>` and the **Lint.** step of `plugins/ai_dev/skills/task_create/SKILL.md` fix blocking findings only, and the `task_create` **Write.** step names the cross-link discipline and the soft-pointer rule but not the grouping rule. The hub's `<update>` workflow is a named owner in the protocol, yet its own text only says to re-run the linter after the edit.

The framing fails in practice. On 2026-10-07, a backlog update in another repository ended with five repeated-link warns, and the agent kept all five as `kept because each site earns its link`, since each second link was "either a deferral to the owning task or a file to edit". Those are the grouping rule's carve-outs: four of the five paired a Context mention with an `**Out of scope:**` entry, and the fifth paired it with an edit site in Approach. The owner's correction is the rule this task installs: the links are a sign that the task needs reorganizing and clearer writing, so the judgement is whether the sections should be grouped better, never whether a single link makes sense. The archived [regroup-owners task](task-family_repeated-link-regroup-owners.md) introduced the account test and the kept disposition that this task replaces, along with the guard against converting a link to plain text without moving material, which this task keeps in reworded form.

The live tasks below edit the same passages for other purposes, and whichever task lands second rewrites its sentences against the text it finds:

- [The live-only body-checks task](../task-family_live-only-body-checks.md) qualifies the warn bucket as live-only, replaces the react protocol's closing routing of archived findings, and removes the archived count line from the disposition-line block and from the `task_fix` `<output_contract>`. Its Acceptance requires the per-finding disposition line shape to survive for live findings, and this task keeps that shape while changing only the values its disposition field takes.
- [The stamp-consequence task](../task-family_stamp-consequence-on-any-rewrite.md) makes the react protocol leave `implemented` and `audited` bodies alone, adds a re-gate to the repeated-link round of `task_auto_check`, and rewrites the status expectation of the `regroup_immediate_ready` eval. Its sentences and eval branches for a kept or surfaced outcome narrow to the surfaced outcome once this task lands.

These test surfaces pin the per-link framing:

- The `tests/task_fix/evals/` eval `kept_each_site_earns_link` stages a body whose Context describes the current sections of a reference page and whose Approach edits one of them, and it expects the finding kept. Its id also appears in `tests/task_fix/evals/stage.sh`, `tests/task_fix/README.md`, `tests/task_fix/RUNBOOK.md`, and `tests/README.md`, and `tests/task_fix/evals/README.md` calls it the counterweight to the linter proxy under its heading `## Why the grader reads the linter, not the prose`.
- The `tests/task_auto_check/evals/` eval `regroup_immediate_ready` accepts a disposition that reads regrouped, kept, or surfaced, and its grader comment beginning "This fixture's Approach names throttle.py as the edit site" calls the fixture the contested edge of the edit-site carve-out. The fixture comments of `regroup_via_reviewer` and `regroup_immediate_ready`, and the grader comment above `no_repeated_link_finding`, explain their outcomes by whether a repeat earns its link.
- Scenario `s11` in `tests/task_auto_check/script_tests/run.sh` pins protocol sentences this task rewrites; the Acceptance item whose check begins `bash tests/task_auto_check/script_tests/run.sh` selects every `s11` needle whose pinned sentence the base-skill rewrite replaces.

The standing repo rules place a rule the whole family shares once in the base skill, so the reframe is written there and the siblings and agents point at it.

## Approach

1. **Rewrite the rule in the base `task` skill.** Rewrite each passage in place so one canonical statement remains.
   - Rewrite the grouping-rule bullet so it states that a target linked from several sections is a sign that material belonging together has spread across the body, and that the author answers it by reorganizing the sections until that material sits together under one link. Delete the sentence beginning "Keep a further link to the same target where that site earns it on its own". Replace the closing sentence about the value test with the division of labour it implies: the cross-reference bullet decides whether the body links a target at all, and the grouping rule decides how the body organizes what it says about a linked target. Keep the sentence about naming the target again in plain text inside a paragraph that already links it.
   - Rewrite the warn-bucket sentence beginning "Treat each `repeated-link` warn as a candidate, not a verdict" so it states the warn as a sign that the body may need reorganizing and points at the react protocol.
   - Rewrite the **Repeated-link react protocol.** paragraph as a reorganization procedure. The writing surface reads every mention of the counted target, linked or plain, and asks which of the body's statements about it belong together, such as a file's current state and the edit this task makes to it, a sibling's background and the work that sibling owns, or one handoff narrated in several sections. It gathers that material into the one passage where it reads as one account, in the section whose job the combined material mostly serves under the `<body>` anatomy, and rewrites the affected passages for clarity where the move calls for it. The anatomy decides where a gathered account sits and never justifies splitting one subject across sections by role. The protocol's existing protection of `## Goal` and the Acceptance contract stays, including the case where Goal and an Acceptance item each carry a load-bearing copy, while the sentence beginning "That is surfaced rather than kept" goes, because it argues from the carve-outs this task removes.
   - Replace the sentence beginning "A link travels with the clause that carried it" with the reorganization's link rule: each link moves with the material it carried, a pointer left behind names the target in plain text, and stripping link syntax from a passage whose material stayed reorganizes nothing and resolves nothing.
   - Close the disposition set at two values. A finding is `regrouped` when the reorganization clears the warn, and `surfaced because <reason>` when the warn stands because the reorganization would change Goal or the Acceptance contract, because it reveals separate concerns and takes the existing route to the `<split_at_300>` split guidance, or because the writing surface finds no grouping that keeps the body's meaning. Every surfaced reason describes how the body is organized, and the value of a single link is never a reason. Delete the sentences that keep surviving links by site and report a count above the floor as kept.
   - Rewrite the owner sentence beginning "Four surfaces own the regroup" without a count and add the create path to the owners: the hub's `<create>` workflow and `task_create` reorganize a new file before reporting it created. The reorganization belongs to the creation, so `created` and `updated` keep the one timestamp the create step captured. Rewrite the reporting-surface sentence ending "leave the regroup to those four" and the sentence beginning "The mechanically fixable set omits `repeated-link`" so they refer to the writing owners without a count.
   - Rewrite the **Repeated-link disposition line.** block so the disposition reads `regrouped` or `surfaced because <reason>` and its closing sentence names every writing owner that reports the line. Keep the line shape itself.
   - In the **Declare exclusions as an Out of scope boundary** rule, rewrite the deferral sentence so a deferral names its owner, carries the link when the entry holds the body's account of that sibling, and names the owner in plain text when the grouping rule gathers that account elsewhere in the body. The rest of the sentence stays: the implementable detail lives in the owner, the entry stays a one-line pointer, and the pointer marks ownership, never ordering.
2. **Make the create and update paths answer the warn.** Rewrite the hub's `<lint_after_create>` and the `task_create` **Lint.** step so they fix every blocking finding and answer each `repeated-link` warn on the new file through the react protocol before the file is reported created. Rewrite the `task_create` **Write.** sentence beginning "When filling `## Context` and any cross-references" so it applies the grouping rule beside the cross-link discipline and the soft-pointer rule while drafting, and rewrite the `task_create` `<output_contract>` so the report carries each `repeated-link` finding in the disposition-line shape. Rewrite the hub `<update>` sentence "Re-run `python3 scripts/lint.py --quiet` after the edit." so the update round also answers each `repeated-link` warn on the edited file through the protocol, under the one `updated` bump that round already makes.
3. **Carry the reframe into the siblings and agents.** Each passage below points at the base protocol rather than restating it.
   - In `task_fix`, rewrite the **Remediate.** clause "gathering the repeated account into its owning section and leaving the surviving links each site earns" so it names the reorganization the protocol defines, keeping the phrase "apply the meaning-preserving regroup from the base `<lint>` **Repeated-link react protocol**" that a script test pins. Rewrite the **Repeated-link findings** entry so it lists the protocol's surfaced reasons. In the `<output_contract>`, list the two dispositions, count each regrouped finding in `N issues resolved` and each surfaced one in `K flagged for review`, and delete the sentence beginning "A kept finding enters neither count".
   - In `task_auto_check`, rewrite the Grouping advocate stance so it proposes the reorganization and surfaces a finding only with an organizational reason. Rewrite the **Repeated-link disposition filter.** and the `<finalize_mechanical_lint>` sentence about a finding "this run regrouped or kept" so only a regrouped finding leaves the surfaced-but-not-fixed line and the stuck channel, and rewrite the `<output_contract>` sentence that lists "regrouped, kept, or surfaced".
   - Rewrite the Grouping advocate stance of `auto_reviewer_task` so it proposes a reorganization and returns `no_proposal` only with an organizational reason. Rewrite the regroup rules of `auto_verifier_task` so it approves a reorganization that gathers the material and keeps Goal and the Acceptance contract, and rejects a proposal that only strips link syntax. Rewrite the `auto_shaper_task` `<remediate>` sentence beginning "For a repeated-link regroup" so it reorganizes the body per the protocol.
4. **Prove the reframe on the evals.**
   - Rewrite the `tests/task_fix/evals/` eval `kept_each_site_earns_link` in place as a reorganization eval on the same fixture body. Rename its id and fixture directory to `regroup_state_and_edit_site`, update every file that names it, and rewrite its fixture comment, `expected_output`, expectations, and grader arm. The eval passes when the run gathers the reference page's current state and its edit into one passage with one link, the linter reports no `repeated-link` finding on the file, `updated` changes, Goal and the Acceptance contract keep their meaning, and the report's disposition line reads `regrouped`. A run that reports kept or leaves the file as staged fails it. Rewrite the counterweight paragraph in `tests/task_fix/evals/README.md`, the kept failure shape in `tests/task_fix/RUNBOOK.md`, and the kept mentions in `tests/task_fix/README.md` and `tests/task_fix/evals/grade.sh` to match.
   - Rewrite the `regroup_immediate_ready` expectations and grader so the disposition must read regrouped or surfaced, a surfaced line carries its organizational reason, and a kept line fails. Rewrite each fixture and grader comment under `tests/task_auto_check/evals/` that explains an outcome by whether a repeat earns its link.
   - Rewrite each `s11` needle whose pinned sentence the base-skill rewrite replaces, so it pins the new sentence.
   - Add an eval `create_regroup_owner_account` to the whole-family suite in `tests/task/evals/`, beside `create_scope_trim`. Its request asks for a task that builds on one live sibling's work and leaves a named piece of work to that same sibling, the Context-plus-deferral shape from the observed failure. The eval grades the created file: the linter reports no `repeated-link` finding on it, the sibling is linked once, the excluded work still names the sibling as its owner, and the body's account of the sibling sits in one section. A created file that links the sibling from Context and again from its `**Out of scope:**` entry fails it.

   The Test Integrity section of `TESTING.md` governs each edited check, and every check this task edits pins behaviour the task supersedes.
