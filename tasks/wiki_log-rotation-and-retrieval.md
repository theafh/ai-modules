# Enforce log rotation and make log reads entry-aware

## Goal

`log.md` never grows large enough to overflow a tool result or exceed the Read token cap, and the orientation step that reads recent log entries does so by entry boundary instead of a fixed line count. Two coupled problems are fixed: the rotation rule that exists on paper is actually enforced, and the read idiom prescribed across the skill and agent stops dumping the whole tail of an oversized log.

## Context

The wiki convention is "rotate `log.md` at 500 entries" (stated in [skills/wiki/references/template_log.md](../plugins/knowledge_management/skills/wiki/references/template_log.md), whose rotation preamble this task rewrites, and the `<rotate_log_at_500>` rule in [skills/wiki/SKILL.md](../plugins/knowledge_management/skills/wiki/SKILL.md)). But the linter's rotation check, `check_log_rotation` in `skills/wiki/scripts/lint.py`, emits the over-500 finding at **info** severity only. Info never blocks and is routinely accepted, so in practice the log is allowed to grow without bound, well past a thousand entries and tens of KB. Layer 1 `l45_lint_two_field_survives_volatile_message` in `tests/wiki/layer1/run.sh` accepts `log — log.md` beside `size` and `stale`; Accepted finding suppresses `SEV_INFO` only, so escalating rotation above info leaves that accept path unable to acknowledge a live rotation finding unless the scenario is rewritten.

Co-edit ownership with [wiki_family-inheritance-blocks.md](wiki_family-inheritance-blocks.md): that ready sibling owns stating the orientation quantity once in hub `<resuming_an_existing_wiki>` as the last 20 to 30 entries by entry boundary, and having `wiki_import` / `wiki_wrapup` (and pitfall `<orient_first>`) cite that tag. This task owns the entry-anchor + bounded-slice retrieval recipe (stated in that same `<resuming_an_existing_wiki>` block beside the sibling-settled quantity), rotation enforcement, the agent's `<read_recent_log>`, and rewriting other hub `tail -n 350` sites (including `<searching>`) into one-clause citations of `<resuming_an_existing_wiki>`, so quantity wording / front-end citations and the retrieval mechanism stay one coordinated rule without either task rewriting the other's owned surfaces. Hub `<searching>` citation of `<resuming_an_existing_wiki>` after retiring its `tail -n 350` example stays this task's edit.

Once the log is that large, the prescribed read idiom breaks:

- The `tail -n 350` log-read idiom in that same SKILL.md (both `<resuming_an_existing_wiki>` and the `<searching>` block), the auto-shaper's `<read_recent_log>` step (`tail -n 350 "$WIKI/log.md"`), and the "roughly the last 350 lines of `log.md`" orientation wording in `wiki_import` (three sites: `<orient_first_top>`, `<orient_first>`, and its orientation step) and `wiki_wrapup` (two sites: `<orient_first>` and its orientation step) all reach for a fixed line count. Quantity wording inside `<resuming_an_existing_wiki>` and front-end citation rewrites belong to that ready sibling; this task supplies the retrieval recipe in `<resuming_an_existing_wiki>`, the hub-internal citation bridge for other hub `tail -n 350` sites (including `<searching>`), and the agent citation of that hub tag.
- On an oversized log, `tail -n 350` produces a result large enough to trip the "output too large" handling, and a `Read` with offset/limit can exceed the 25000-token cap that the same SKILL.md itself warns about (the `exceeds maximum allowed tokens (25000)` caution under `<too_large_to_read_in_one_shot>`). Every orientation pass pays this.

Rotation also interacts with the auto-shaper's incremental audits: the agent scopes its page walk from the newest prior `audit` entry in `log.md` that records a usable git baseline (the `Audit baseline:` line written by `<append_audit_log_entry>`). Rotating moves every prior audit entry into `log-YYYY.md`, so the first audit after a rotation finds no baseline in the fresh log and falls back to the full cold walk.

**Severity is coupled to the agent's clean-exit bar.** The `auto_shaper_wiki` agent's `<lint_clean>` objective and `<relint_until_clean>` verify step both finish only when lint "exits 0 with no blocking findings and no warn findings other than every `quality` warn whose message is the contested dispute signal (`contested: true — reconcile or document the dispute`)" on contested pages per `<lint_clean>`, and the agent ships no fix move that rotates a log: `<fix_log_preamble_drift>` restores preamble lines and leaves the entries below untouched. Escalating `check_log_rotation` to `warn` without also giving the agent a rotation move therefore hands it a finding it cannot clear while `<run_until_done>` tells it not to stop early. That is the same unreachable-bar hazard [wiki_auto-shaper-internal-contradictions.md](archive/wiki_auto-shaper-internal-contradictions.md) resolves for the contested-page warn, and its carve-out is deliberately contested-only, so a rotation warn gets no relief from it. That task also rewrites the clean-bar statement this task's new finding must stay clearable under, so read it before wording the severity change.

Agents have independently rediscovered an entry-aware idiom (`grep -n '^## \[' log.md` to get entry anchors, then read a bounded slice). That idiom should be baked into the prescribed steps, and rotation should be enforced so the log never reaches the failure size in the first place.

Prior art: [wiki_log-heading-uniqueness-and-repair.md](archive/wiki_log-heading-uniqueness-and-repair.md) already shipped the timestamped `## [YYYY-MM-DD HH:MM]` Format line and the `Repair:` carve-out into that same `template_log.md`, plus the agent's `<fix_log_heading_duplicate>` remediates move. Word this task's rotation-rule preamble edit against that current template—the existing `When this file exceeds 500 entries, rotate…` line—and keep the new `<remediate>` rotation move a distinct sibling of `<fix_log_heading_duplicate>`.

## Approach

1. **Give rotation teeth on both channels in one change: escalated severity and an agent rotation move.** Escalate the over-threshold finding in `check_log_rotation` beyond bare info so it stops being accepted forever: `warn` when `entries > 500` and `blocking` when `entries > 1000`, kept consistent with the rotate-at-500 convention in `template_log.md`. Rewrite `lint_checks.md` and hub `<narrow_inline_checks>` in place so each surface's **info** / **warn** / **blocking** severity bullets (and `lint_checks.md`'s `log` category row) match those thresholds (drop "log over 500 entries" from info on both; document warn-at-500 and blocking-at-1000 in the matching buckets). Retire the Accepted-finding path for rotation findings in the same change: rotation clears them via the new `<remediate>` move; `Accepted finding:` does not. Drop `log` from `TWO_FIELD_CATEGORIES` and from the two-field whitelist in `lint_checks.md` so the whitelist matches the remaining info-only two-field categories (`size`, `stale`, `log-scope`). Rewrite `l45_lint_two_field_survives_volatile_message` in place so it proves volatile-message survival only on `size` and `stale`, and cover the new warn/blocking rotation severities with dedicated script tests rather than an accept bullet. In the same change, add a rotation fix move to the agent's `<remediate>` phase: `git mv` the log to `log-YYYY.md`, start a fresh `log.md` carrying the canonical preamble from `template_log.md`, and record the rotation as the new log's first entry. The fix move is what makes the escalated finding clearable, per the clean-exit coupling in Context. The severity alone would strand every audit on a wiki whose log has already grown, so the two halves ship together rather than as alternatives. Rotation deliberately accepts a one-time post-rotation cold walk from the incremental-audit mechanism, which is rare (once per 500 entries) and self-healing, since the first audit after rotation records a fresh baseline in the new log; the rotation rule states that fallback so it is designed rather than accidental. Co-update the Layer 2 pins that freeze that one-liner: rewrite `A2_rotation_rule_present_at_template_text` in `tests/wiki/layer2/evals.json` and the matching `STALEPRE` / AS-16 staging literal in `tests/wiki/layer2/setup_scenarios.sh` so each expects the post-change rotation-rule text rather than `> When this file exceeds 500 entries, rotate: rename to log-YYYY.md, start fresh.`
2. **Replace the fixed-line-count read idiom with entry-aware retrieval** in hub `<resuming_an_existing_wiki>` and the agent's `<read_recent_log>`. Rewrite the `tail -n 350` passage inside `<resuming_an_existing_wiki>` into the entry-anchor recipe: get entry anchors with `grep -n '^## \[' "$WIKI/log.md" | tail -<N>`, then `Read` a bounded slice from the earliest needed offset, where `<N>` is the quantity that ready sibling settles (20–30). Rewrite every other hub `tail -n 350` site (including the `<searching>` example) into a one-clause citation of `<resuming_an_existing_wiki>` by that verbatim tag, restating neither the recipe nor a fixed line count. Rewrite the agent's `tail -n 350 "$WIKI/log.md"` step in `<read_recent_log>` into a citation of that same hub tag, with no parallel recipe. In the same change, rewrite the Layer 1 `agent_contract.py` require that currently pins `tail -n 350 "$WIKI/log.md"` so it asserts the post-change citation shape (agent carries the hub-tag citation and no longer embeds that fixed-line command) rather than treating the retired idiom as a contract. Add Layer 1 `l73_entry_aware_log_read_bounds_slice` in the same change: stage an oversized log with `append_log_entries`, run that recipe, and assert a 20–30 entry-heading slice. Leave the orientation quantity wording and the front-end (`wiki_import` / `wiki_wrapup` / pitfall `<orient_first>`) citation structure to that sibling; this step supplies the mechanism and clears hub + agent `tail -n 350` sites.
3. **Cross-reference the cap warning.** Tie the new idiom to the existing 25000-token caution in SKILL.md (`<too_large_to_read_in_one_shot>`) so the two are coherent.

## Acceptance

- `check_log_rotation` reports `warn` when `entries > 500` and `blocking` when `entries > 1000`, so an unbounded log is no longer silently tolerated.
- `lint_checks.md` severity bullets and two-field whitelist, and hub `<narrow_inline_checks>` severity bullets, match those thresholds; `lint_checks.md` no longer lists `log` as an Accepted-finding two-field category; searching hub `<narrow_inline_checks>` for `log over 500 entries` returns no match under **info**.
- `auto_shaper_wiki` carries a `<remediate>` rotation fix move that renames the log to `log-YYYY.md`, starts a fresh `log.md` with the canonical preamble, and records the rotation as the new log's first entry.
- The rotation rule (the `template_log.md` preamble and the `<rotate_log_at_500>` statement) names the post-rotation audit behaviour: the next audit cold-walks once and records a fresh baseline in the new log. Searching `tests/wiki/layer2/evals.json` for `A2_rotation_rule_present_at_template_text` and `tests/wiki/layer2/setup_scenarios.sh` for the `STALEPRE` rotation one-liner finds each pin matches that rewritten preamble text (not the pre-change `> When this file exceeds 500 entries, rotate: rename to log-YYYY.md, start fresh.` line).
- Hub `<resuming_an_existing_wiki>` carries the entry-anchor + bounded-slice recipe (no fixed line count); `auto_shaper_wiki`'s `<read_recent_log>` cites that hub tag and restates no parallel recipe; hub `<searching>` cites that tag and embeds no `tail -n 350`; searching the hub skill and agent for `tail -n 350` and `350 lines` returns no log-read idiom. Front-end quantity and citation proofs stay with that ready sibling.
- The orientation recipe's concrete commands (`grep -n '^## \['` … `| tail -<N>`, then bounded `Read`) appear in hub `<resuming_an_existing_wiki>` (greppable file state).
- Hub `<resuming_an_existing_wiki>` also cites `<too_large_to_read_in_one_shot>` (or the greppable failure string `exceeds maximum allowed tokens (25000)`) beside that recipe.
- Layer 1 scenario `l73_entry_aware_log_read_bounds_slice` in `tests/wiki/layer1/run.sh` stages a wiki whose `log.md` has well over 350 entries (via `append_log_entries`), applies the hub entry-anchor recipe (`grep -n '^## \['` … `| tail -<N>` with `<N>` in the sibling-settled 20–30 range, then a bounded Read from that earliest offset), and asserts the returned slice contains between 20 and 30 `## [` entry headings inclusive; `tests/wiki/run_all.sh` passes with that scenario registered.
- `l45_lint_two_field_survives_volatile_message` no longer stages or accepts `log — log.md`; it still proves two-field volatile-message survival for `size` and `stale` only, and `log` is absent from `TWO_FIELD_CATEGORIES` and from the two-field whitelist in `lint_checks.md`.
- `tests/wiki/layer1/agent_contract.py` no longer requires `tail -n 350 "$WIKI/log.md"` in the agent; its `<read_recent_log>` pin instead requires a citation of hub `<resuming_an_existing_wiki>` (and fails if that fixed-line command remains).
- Script unit tests under `tests/wiki/` cover both escalated rotation severities (`warn` past 500 and `blocking` past 1000) as live findings that acceptance cannot suppress, and `tests/wiki/run_all.sh` passes with that L45 rewrite and those severity tests in place.
