# Make the agent_spinner ledger hold what the skill says it holds

## Goal

Every mechanism the skill and its references attribute to the run ledger exists and is checked at `close`. A helper's beyond-brief finds become ledger records, its own-authority calls and dropped suspicions need a disposition before a clean close, recall provenance holds when a brief pastes a producer's finding, the repair list fills from failed verification, shared rules are compared between a producer and its checker, and the report lint the references describe flags uncited assertions. Today each of these is stated in the skill and missing from `scripts/run_ledger.py`, so a run that ignores them still closes cleanly.

## Context

All paths are under `plugins/ai_dev/skills/agent_spinner/`. The coverage audit of 2026-11-14 confirmed each gap by reading or running the ledger.

- **Beyond-brief and own-authority records.** SKILL.md `<aggregation>` says "The ledger imports every return in full", and `<reporting>` requires the report to separate what a helper found beyond its brief from what it decided on its own authority. `RECORD_LISTS` in `run_ledger.py` leaves out `beyond_brief`, although the return template lists it, so those finds never become records. `close` condition 2 asks for a disposition only for findings, incidents, alternatives, and objections, so `own_authority` and `dropped_suspicions` records need none.
- **Recall provenance.** SKILL.md `<confirmation_provenance>` defines recall-confirmed. `references/run-protocol.md` lets a brief paste the producer's material below a stated cap instead of relaying it. The ledger tags a confirmation recall-confirmed only when the row has a producer, which only `brief --relay` sets, so a checker whose brief pastes the finding is tagged independently surfaced.
- **The repair list.** SKILL.md `<remediation>` says the repair list holds every item that failed verification. `run.json`'s `repair_list` is initialised empty and read by `rows --from-repair-list` and `status`, but no verb ever fills it, and `accept` stores no verdict on the row it accepts, writing `state`, `source`, `returned_at`, `model_obs`, and `effort_obs` only, so nothing in `run.json` records which return failed.
- **Shared rules across phases.** SKILL.md `<prompt_assembly>` requires a producer and its checker to share the rules file byte for byte. `cmd_brief` compares shared blocks only within one phase, while a producer and its checker usually sit in different phases.
- **The report lint.** `references/run-protocol.md` says "The report lint flags an assertion word, such as verified or complete" that carries no ledger citation, and `references/checks.md` and `references/report-shapes.md` rely on the same lint. The ledger has no report lint; `close` condition 7 only checks that `report.md` carries the current tally block. The skill states the citation rule in four places, so the ledger implements the lint rather than the references dropping it.

**Prerequisite order.** Four live tasks edit the same ledger file and `tests/agent_spinner/script_tests/ledger_run.sh` and land before this one: [report-packet enforcement](archive/ai-dev_agent-spinner-report-packet-enforcement.md), [unanswered-fork holds run](ai-dev_agent-spinner-unanswered-fork-holds-run.md), [stamped-write routing](ai-dev_agent-spinner-stamped-write-routing.md), and [ledger coverage gates](ai-dev_agent-spinner-ledger-coverage-gates.md). Land this one last, because each of those also edits `cmd_brief` or `cmd_accept`, or the `close_open_items` condition numbering this task extends. The terminal-states and brief-contract ledger tasks are archived `finished` ([terminal states](archive/ai-dev_agent-spinner-ledger-terminal-states.md), [brief contract](archive/ai-dev_agent-spinner-ledger-brief-contract.md)), so their work is already in the tree and imposes no order.

## Approach

1. Add `beyond_brief` to `RECORD_LISTS` so each entry becomes a record, and extend `close` condition 2 to require a disposition for `beyond_brief`, `own_authority`, and `dropped_suspicion` records. A beyond-brief find is a record type in this ledger, disposed one record at a time with `dispose --id`. `dispose --flag LABEL --reason TEXT` keeps its shipped role of flagging a roster row so `close` condition 9 accepts that row's depth, and it disposes no record, so a depth flag leaves every beyond-brief record on that label open. Add `beyond_brief` and `dropped_suspicion` (the singular type `import_records` derives) to `DISPOSITION_TYPES` so `dispose --id` reaches them. An `own_authority` record that `dispose --fork ID --own-decision TEXT` writes carries its decision in `own_decision`, so that record satisfies condition 2 as its own disposition and the shipped own-decision route keeps closing clean; an `own_authority` entry imported from a return takes an ordinary `dispose --id` disposition.
2. Let `brief` record a producer when its body pastes a producer's accepted finding, through an explicit `--pasted-from LABEL` option, and tag the resulting confirmation recall-confirmed the way `--relay` does. Store that label in a separate `pasted_from` map and read it beside `producers` where the confirmation provenance is set, leaving `producers` to `--relay` alone: condition 9 in `close_open_items` and the `close` advisory read `producers` against `depths`, so a pasted checker whose depth sits below its producer's would be refused as if it had been relayed, a refusal the paste never earns.
3. Persist the verdict `accept` already validates (`pass` or `fail`) on the row as `row["verdict"]`, adding `verdict` to `COLUMNS` so the roster round-trips it, since `write_rows` writes only `COLUMNS`, and fill `repair_list` from every row whose persisted verdict is `fail`, so `rows --from-repair-list` and `status` read real entries.
4. Compare the shared rules block of a checker's brief with its producer's brief, wherever the two rows sit, and refuse a mismatch the way the same-phase comparison does.
5. Add the report lint as `close` condition 11: an assertion word from the fixed list enumerated once as a table beside the tag list in `references/report-shapes.md` `## Provenance tags` — `verified`, `complete`, `confirmed`, `all`, `none` — in `report.md` must carry a ledger citation in the same sentence. Match each word as a whole word, case-insensitively, and ignore occurrences inside a hyphenated compound, so `recall-confirmed` and `independently-surfaced` are not assertion words while a sentence-initial `Verified` still counts. Exempt the tally block `close` condition 7 requires: the lint skips every line from `TALLY-BEGIN` through `TALLY-END`, because that block is printed by `tally_block` and carries `recall-confirmed %d` that the report must reproduce verbatim. Hold that same word list in one constant in `run_ledger.py`, and point `references/run-protocol.md`'s P6 paragraph and `references/checks.md` C10 item 10 at that table rather than letting either name words of its own. Take the citation form from the one place it is already defined, `references/report-shapes.md` `## Provenance tags`, and write no second definition: the lint accepts exactly those bracketed tags (`[measured: …]`, `[re-derived: …]`, `[taken on a helper's word: …]`, `[blind by log: …]`, `[blind by prompt: …]`). Convert the closing-report template above that section to the same tags in this change — its `Established.` paragraph's "(measured by the gate, record check:build)", its `**Found beyond the brief.**` paragraph's "Recall-confirmed by the checking pass, not independently surfaced, so it carries less weight.", and its `Verification:`, `Coverage:`, and `Confirmations:` lines — and point `references/run-protocol.md`, `references/checks.md`, and `SKILL.md` `<reporting>` at `## Provenance tags` instead of restating the form.
6. Rewrite in place each passage that describes these mechanisms, so it states what the ledger now does: `references/run-protocol.md`, `references/checks.md`, `references/report-shapes.md`, and `SKILL.md` `<aggregation>`, `<confirmation_provenance>`, and `<reporting>`. In `<aggregation>`, retire the sentence "A beyond-brief find travels as a flag, not a record type: `dispose --flag LABEL --reason TEXT` records it and `show` reads it; a flag has no `id`, so its `reason` is its whole record and needs no separate disposition." and replace it with a passage that states the ledger's record model once, as step 1 settles it, and keeps the flag role that model retains without re-describing the recording rule: `dispose --flag LABEL` marks a roster row for condition 9's depth acceptance and disposes no record, so a beyond-brief record is disposed only by id. In that same `<aggregation>` passage, also retire "Give each record one disposition: applied, refuted with its reason, surfaced, or deferred with a durable pointer." and let the one record-model passage carry the disposition rule as step 1 settles it. Then replace `references/run-protocol.md` P6's restatement of it — "P6 holds the reading rule `<aggregation>` states, one disposition per record, a decision packet per fork, and the report built from the tally block." — with "P6 holds the reading and disposition rules `<aggregation>` states, a decision packet per fork, and the report built from the tally block.", so the disposition rule is written once, in `<aggregation>`, and P6 points at it. In `<confirmation_provenance>`, retire the sentence "The ledger tags each confirmation recall-confirmed when the checker's brief relayed that record, and independently surfaced otherwise." and replace it with one sentence stating both routes as step 2 settles them: "The ledger tags each confirmation recall-confirmed when the checker's brief relayed that record or pasted the producer's accepted finding under `--pasted-from`, and independently surfaced otherwise."
