# task_auto_check: a drift gate that halts only on broadened intent, judged against the last commit

## Goal

`auto_drift_task` returns `drift` only when the frozen `# Title` or `## Goal` broadens what the task is for compared with the version in the last commit: it promises a deliverable, a goal, an edit surface, or a user-visible outcome that the committed title, Goal, and body do not, or it replaces the task's subject with a different one. Every other change classifies `clean`, however large the wording delta: narrowing (dropped scope, an added carve-out, a deferral to a sibling or into `**Out of scope:**`), refinement (clarification, precision, rewording, restructuring, added cross-references, a title widened to name deliverables the body already carries), bug fixes (a corrected path, command, name, or claim about current state), and resolved labeled open decisions. `task_auto_check` keeps human-routing a `drift` verdict through `<intent_drift_boundary>` and runs through on everything else. The user-visible outcome: the loop stops for a human only when unattended editing has widened what the task is for, and the ordinary shaping a task accumulates between commits no longer halts it.

## Context

The gate shipped through the archived [intent-drift detection task](archive/task-family_intent-drift-detection.md) with a symmetric definition. The `<policy>` in `plugins/ai_dev/agents/auto_drift_task.md` reads "Return a drift finding only when the current title or Goal changes what the task is about, narrows away the original aim, or contradicts the recovered original aim", so a narrowing is drift by specification, and its `<compare_meaning>` step compares "scope boundaries", so a tightened boundary reads as a change. The gate exists to catch unattended drift, and unattended drift in an autonomous repair loop runs one way: toward scope creep. A human shaping a task narrows it, sharpens it, and corrects it, and none of that is a reason to stop a readiness loop.

The baseline compounds this. The same `<policy>` treats "the earliest committed baseline as the origin" and compares "against the full followed history, not merely the previous commit, so intent narrowed across several commits still remains detectable". That rationale exists only to catch narrowing, so it falls with the symmetric definition. It also leaves the human no way to attest a changed intent: a task broadened deliberately and committed weeks ago is compared against its first commit on every later run, so one legitimate expansion becomes a halt on every run for the rest of the task's life. In this repository a commit is the checkpoint the user owns (standing repo rules), so the version in the last commit is the human-attested intent, and the working-tree delta since then is exactly what an unattended run may have produced.

Three smaller defects ride along. The agent's `<policy>` returns `unassessable` when "the working-tree title and Goal no longer match the freeze-time inputs", so a freeze snapshot that differs from the file by whitespace, quoting, or an excerpted Goal ends the run through `<agent_failure_policy>` as well. The classification vocabulary has drifted between the two files: `<intent_drift_boundary>` in `plugins/ai_dev/skills/task_auto_check/SKILL.md` speaks of "Clean, meaning-preserving, and `low_confidence_clean` results" as though three classes existed, the loop's spawn prompts have advertised a `meaning-preserving` class, and the agent's `<output_contract>` enumerates `clean|drift|low_confidence_clean|unassessable`. One recorded run returned the off-contract value `meaning_preserving`, which `<agent_failure_policy>` counts as a contract violation that can end a run as a helper-failure stop. And the test harness pins the boundary only at its extreme: `intent_drift_human_route` in `tests/task_auto_check/evals/evals.json` stages a wholesale subject swap, no fixture stages a changed title or Goal that must classify `clean`, and the `s9_intent_drift_boundary` scenario in `tests/task_auto_check/script_tests/run.sh` asserts the literals "earliest committed" and "not merely the previous commit", so the harness enforces the design this task replaces.

In practice the gate fires on nearly every title or Goal change, in Cursor and OpenCode runs especially: a renamed title or a tightened Goal halts the loop with the intention check. The rule text mandates that outcome. Its trigger is worded as a change predicate, "changes what the task is about", and a title is what a task is about, so a rename satisfies it literally; the deployed OpenCode copy of the agent also carries no model or reasoning-effort fields, so the harness default decides how the rule is read. The fix therefore lands in the rule text and the baseline, and the negative fixtures below make the boundary visible instead of leaving it to the model's judgement. One interaction the new rule must survive: the base `task` skill's `<readiness_checklist>` **Title/description coverage** lens repairs an under-naming title by widening it in place, so the loop's own repair widens titles, and a broadening test that read the title alone would trip on the loop's previous run.

## Approach

Rewrite `plugins/ai_dev/agents/auto_drift_task.md` in place:

- **Baseline.** Read the title and Goal from the file's content in the last commit (`git show HEAD:<path>` or an equivalent), following a staged or uncommitted rename (`git diff HEAD -M --name-status`, or `git log --follow -1` for the prior path) before giving up on the path. A file with no committed version returns `low_confidence_clean` as today. A title and Goal byte-identical to the committed version return `clean` at high confidence with no further reasoning. The earliest-commit walk and the full-history comparison go away.
- **Direction.** Define `drift` as broadening: the current title or Goal promises a deliverable, a goal, an edit surface, or a user-visible outcome that the committed title, Goal, and body do not promise, or replaces the task's subject. Judge the promise set of title and Goal together against the committed body, so a title that catches up with deliverables the body already carried is `clean`. Name narrowing, refinement, bug fixes, and resolved labeled open decisions as `clean` in the rule text. A contradiction is drift only when it replaces the aim with a different or wider one; a caveat that carves part of the aim out is narrowing.
- **Evidence bar.** A `drift` verdict quotes, in `## Classification evidence`, the current passage that carries the added promise beside the committed passage that lacks it, and names the promise in one sentence. When no added promise can be named, the classification is `clean`. `confidence` and `drifted_fields` stay as they are.
- **Attestation.** Add an optional `attested_intent` input: the user's own statement from the run prompt that a change to the title or Goal is deliberate. A broadening the attestation covers is human-owned and returns `clean`, and the report names the attestation it relied on.
- **Working tree as authority.** Read the title and Goal from the working tree and treat the freeze-time inputs as a cross-check: a difference in whitespace, quoting, or an excerpted Goal is noted in the report and the working-tree text is judged. `unassessable` stays for a task file that cannot be read.
- **Contract.** Keep the classification enum exactly `clean|drift|low_confidence_clean|unassessable`, redefine `baseline_commit` as the commit whose version served as the baseline, and keep `history_followed` for the rename follow.

Rewrite `plugins/ai_dev/skills/task_auto_check/SKILL.md` in place: `<intent_drift_boundary>` states the broadening-only rule by citing the agent and names exactly the agent's four classifications, `<inputs>` admits the optional attestation from the run prompt, `<freeze>` passes it to the agent and names the same four classifications, and the `<output_contract>` drift bullet reports the baseline commit, the juxtaposition, and any attestation relied on. `<frozen_intent>`, the human-routing, the never-auto-repair rule, and `auto_verifier_task`'s fidelity check stay as they are: they guard the loop's own edits, while this gate covers what happened before the run.

Refresh the two descriptions of the mechanism: the `**auto_drift_task**` bullet in `plugins/ai_dev/README.md`, and the sentence in `wiki/concepts/agent-delegated-automation.md` that says the drift agent catches intent that "moved away from the first" committed goal, edited through the wiki skill family.

Update the tests with the change. In `tests/task_auto_check/script_tests/run.sh`, rewrite the `s9_intent_drift_boundary` assertions that pin the old design (the "earliest committed", "not merely the previous commit", and "changes what the task is about" literals) so they pin the new rule text and baseline. In `tests/task_auto_check/evals/`, add four fixtures on the `_common.sh` pattern (`init_proj`, `commit_proj`, then an uncommitted rewrite) with their `evals.json` entries and `grade.sh` cases:

- `drift_gate_narrowing_clean`: the rewrite drops one deliverable into `**Out of scope:**` and renames the title to the narrower scope; expected `clean`, the gate runs, no intention check.
- `drift_gate_refinement_clean`: the rewrite rewords the Goal, corrects a wrong path it cited, and widens the title to name a deliverable the body already carried; expected `clean`.
- `drift_gate_broadening_drift`: the rewrite adds a second deliverable on a new surface to the Goal; expected `drift` with `drifted_fields: goal`, the Goal intention check, a halt before the gate, and an unchanged body.
- `drift_gate_committed_broadening_clean`: a second commit broadens the Goal and an uncommitted refinement follows; expected `clean`, because the committed broadening is attested.

Keep `intent_drift_human_route` as the subject-replacement case and refresh its `expected_output` where it names the earliest committed Goal. Run each new fixture once with the change; a fixture that classifies against expectation sends the rule text back for tightening before the change lands.

**Out of scope:** Renaming the premise check's `drifted` staleness label in `task_check` and `auto_gate_task`; the word it shares with this gate is a reporting concern outside the freeze-time check. Any automatic repair toward the baseline; the gate detects and the human reconciles.

## Acceptance

- `plugins/ai_dev/agents/auto_drift_task.md` states the broadening-only rule and names narrowing, refinement, bug fixes, and resolved labeled open decisions as `clean`; grepping it for `narrows away the original aim`, `earliest committed`, and `not merely the previous commit` finds nothing.
- The agent's `<policy>` names the last commit's version as the baseline with a rename follow, and keeps `low_confidence_clean` for a file with no committed version.
- The agent's `<policy>` requires a `drift` verdict to quote the added promise beside the committed passage that lacks it, and returns `clean` when no added promise can be named.
- The agent's `<policy>` returns `unassessable` only for a task file it cannot read; grepping it for `no longer match the freeze-time inputs` finds nothing.
- The agent's `<inputs>` carry an optional `attested_intent` field, and `plugins/ai_dev/skills/task_auto_check/SKILL.md` admits it in `<inputs>` and passes it in `<freeze>`.
- The skill's `<intent_drift_boundary>` and `<freeze>` name exactly the four classifications of the agent's `classification:` enum, and grepping the skill for `meaning-preserving` finds nothing.
- The `**auto_drift_task**` bullet in `plugins/ai_dev/README.md` and the drift sentence in `wiki/concepts/agent-delegated-automation.md` describe the broadening-only rule against the last commit; grepping either for `earliest committed` or `moved away from the first` finds nothing.
- `tests/task_auto_check/script_tests/run.sh` passes with the `s9_intent_drift_boundary` scenario asserting the new rule text, and no assertion in that scenario names `earliest committed`.
- `python3 tests/task_auto_check/evals/run.py drift_gate_narrowing_clean drift_gate_refinement_clean drift_gate_committed_broadening_clean` grades each run as `clean` with the gate reached and no intention check surfaced.
- `python3 tests/task_auto_check/evals/run.py drift_gate_broadening_drift intent_drift_human_route` grades each run as `drift` with the Goal intention check surfaced, zero gate calls, and an unchanged body.
