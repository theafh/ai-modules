# Make every behavioral eval grader fail an inert worker

## Goal

A behavioral eval's grader fails when the worker did nothing, so a green eval means the behaviour was observed rather than merely not contradicted. Today a large minority of evals pass on an empty response against an untouched sandbox: the checks assert only that some forbidden state is absent, and a worker that never ran leaves exactly that state in place.

The user-visible outcome: an eval whose checks are all absence-shaped cannot report PASS for a run that produced nothing. The suite stops certifying silence, and a genuinely broken worker shows up as a red eval instead of a green one.

## Context

`TESTING.md` `## Test Design Principles` states the rule this task enforces in the bullet beginning `**State the fail branch.**`: "A check proves the failure case fails, not only that the hoped-for direction passes. A fixture that cannot fail measures nothing." The graders satisfy the rule in places — `git_commit` stages every eval against a staged baseline so a no-op run fails the universal checks — and miss it in others.

Measured on 2026-10-30 by staging each eval's sandbox and grading it against an empty response file, i.e. the exact state an inert worker leaves. The count is evals that graded PASS with the worker contributing nothing. That loop is the derivation for both columns: `Inert-PASS` is the evals it grades PASS, and `Total` is the id count each harness's `evals/evals.json` yields. The table and the eval names below record the 2026-10-30 reading; the loop re-finds the members when it runs:

| Harness | Inert-PASS | Total |
| --- | --- | --- |
| `git_checkout` | 4 | 7 |
| `git_review` | 2 | 48 |
| `git_refresh` | 1 | 4 |
| `git_auto_review` | 1 | 35 |
| `task` | 8 | 46 |
| `task_auto_check` | 11 | 33 |
| `git_commit` | 0 | 9 |
| `agent_spinner`, `guardrail_audit`, `skill_doctor`, `task_create`, `task_fix` | 0 | 43 |

The Python graders carry the same defect on the same date, read the same way: `tests/natural_language/evals/grade.py` grades `chat_brevity` PASS with exit 0 on an absent `response.txt`, because both its checks (`length_at_most_120`, `no_heading`) hold on an empty string, while `connected_rewrite` already exits 1. `tests/wiki/layer2/grade.py`'s `main` returns 0 unconditionally: an all-FAIL pass grades FAIL and still exits 0, and a run directory holding no pass prints `Graded 0 pass(es)` and exits 0, so `run.py`'s `check=True` never fires and `aggregate.py`'s no-previous-benchmark path leaves the layer exit 0. `tests/language_humanizer/evals/grade.py` and both harnesses' `judge.py` already exit non-zero on an inert run and need no repair.

Two shapes produce the passes.

**Absence-only state checks.** `git_checkout` evals 3, 5, 6, and 7 grade "still on main", "no local branch was created", "worktree left as found", "no stash entry" — all of which hold on an untouched sandbox. Their positive counterpart, that the helper actually ran and reported the miss, lives in `note_response` lines that print but never decide the exit code. `git_refresh` eval 4 and `git_auto_review`'s `declines_on_detached_head` have the same shape. `git_review` eval 36 grades two stub-`gh` "no call" checks and nothing else, so a worker that never touched the stub passes; eval 7 grades "no stash", "one worktree", and "no new commit" over a sandbox that already satisfies all three.

**Response-only evals with no enforced check.** The eight `task` evals `explain`, `select`, `query`, `audit_gaps`, `implement_dep_gate`, `select_inbound_dep`, `select_dep_regression`, and `implement_boundary_cross` carry only `agent-attest` lines, which print for the operator and never count. Their observable half — a read-only run leaves the sandbox git tree unchanged — is satisfied by doing nothing, so an empty response scores full marks. The same holds for the eleven `task_auto_check` evals listed in the run: `mechanical_lint_oversized_surface`, `already_ready`, `intent_drift_human_route`, `drift_gate_narrowing_clean`, `drift_gate_refinement_clean`, `drift_gate_broadening_drift`, `drift_gate_committed_broadening_clean`, `scope_split_stuck`, `gate_failure_user_stop`, `drift_failure_user_stop`, and `interaction_scan_no_false_alarm`.

The harness-specific pieces an implementer needs are already in the tree: the `note_response` helper in `tests/git_checkout/evals/grade.sh` and `tests/git_refresh/evals/grade.sh`, the `attest` helper in `tests/git_review/evals/grade.sh`, the `script_calls.log` shim that `tests/git_review/evals/stage.sh` truncates per run, and the `report` helper in `tests/git_auto_review/evals/grade.sh`. Most of the roughly 300 `agent-attest` / `note_response` checks across the twelve shell graders' `expectations` arrays are legitimately operator-confirmed prose judgements, which this task leaves alone; the gap is the narrower one above.

## Approach

Add one enforced positive check per eval that currently passes on an inert worker, preferring a filesystem or invocation fact over a response claim, as `TESTING.md`'s `**Prefer a filesystem fact over a claim.**` bullet directs.

1. **Give each harness an invocation record where it has none.** `git_review` already writes `script_calls.log` from a shim, and `git_refresh` already carries the same record: `tests/git_refresh/evals/run.py`'s `shim_deployed_scripts` writes `script_calls.log`, `stage.sh` truncates it per run, and eval 3's `default_run_called` / `prune_gone_after_default_run` read it. Extend that treatment only to the `git_checkout` fixture, by adding a `shim_deployed_scripts(deploy, target_root)` helper to `tests/git_checkout/evals/run.py` — the shape `tests/git_refresh/evals/run.py` already implements — that rewrites every deployed `scripts/*.sh` into a shim appending `<script> <args>` to `<sandbox root>/script_calls.log` and exec'ing the untouched copy, then assert in each absence-only eval that the run reached the decision under test: the recorded call paired with the argument shape or the reported cause token the behaviour produces, in the shape `tests/git_refresh/evals/grade.sh` already carries, where `default_run_called` is paired with `prune_gone_after_default_run` so the log proves order and arguments rather than mere contact. The edit site is `run_one` in `evals/run.py`, between the `micro_deploy.micro_deploy(...)` return and the `micro_deploy.run_worker(...)` call: `stage.sh` runs before the deployment exists, and `tests/lib/micro_deploy.py`'s `run_worker` snapshots the launch `PATH` into `WORKER_PATH_VAR` with each Cursor login profile restoring exactly that value, so only a shim written into the deployed tree is visible. In `git_refresh`, eval 3's `default_run_called` / `prune_gone_after_default_run` pair already sits in that log, so leave it unchanged and extend the same record for eval 4 rather than starting a second one. Eval 4's helper call is argument-less like evals 1 and 2's, so the log proves only that the helper ran; give `tests/git_refresh/evals/run.py` the third-argument response channel `tests/git_review/evals/run.py` already passes (`grade.sh <id> <sandbox_repo> <response.txt>`) and assert eval 4's dirty-worktree cause token from that response beside the argument-less call, in the shape `tests/git_review/evals/grade.sh`'s `have_response` idiom already carries. Where a wrapper is impractical, promote the load-bearing `note_response` line into a real check with the same floor, asserting the reported cause token and giving it a fail branch. Rewrite the head comments and READMEs that state the old division in the same pass, in place, stating the division once per harness rather than once for both: the `git_checkout` passage keeps its still-true statement that response lines never decide the exit code and adds that the helper invocation is now graded from `script_calls.log` and does decide it, while the `git_refresh` passage names the eval whose invocation check now decides the exit code and the evals whose invocation lines stay operator-confirmed. The matching passage in each harness's `evals/README.md` takes the same per-harness form.
2. **Add the positive half to each absence-only state check.** An eval that asserts "no branch was created" also asserts the evidence that the run reached the decision: the helper log line, the reported cause token, or the response passage naming the blocking path. Keep the absence check beside it.
3. **Give each response-only eval at least one enforced check.** For the read-only `task` evals, grade the substance the eval exists for — the response names the specific task file, scope, or verdict the fixture plants — rather than the sandbox's unchanged git tree, which an inert worker also leaves unchanged. Read that response through the `RESPONSE_FILE` environment variable the `task_auto_check` runner already sets on its grader (`tests/task_auto_check/evals/run.py`): extend `tests/task/evals/run.py` to set it from each eval's captured `response.txt` and `tests/task/evals/grade.sh` to read it, then reuse the wrap-collapsing and subject-anchoring helpers those graders already carry. Rewrite every passage that says the grader cannot read the response, in place, to the new division: `tests/task/evals/grade.sh`'s head comment ("grade.sh cannot read the agent's response text") and its `coherence_wrote_nothing` comment, `tests/task/evals/stage.sh`'s and `tests/task/evals/README.md`'s "never sees the agent's response text" passages, and the same sentence in the four `tests/task/evals/fixtures/fix_coherence*/setup.sh` comments each become a statement that the grader reads the response through `RESPONSE_FILE` and that `coherence-report.md` remains the graded surface for the coherence evals' structured fields. Rewrite in place, in the same pass, every passage under `tests/task/` that the new `RESPONSE_FILE` read falsifies, locating them by search over that tree rather than by a fixed list: any passage stating that the grader cannot read the agent's response, or that a verdict-string expectation stays operator-confirmed for that reason, becomes the post-change division. The passages already located are `tests/task/evals/README.md`'s "the prose verdict strings are the one place free-form response text is load-bearing" passage and its "stay for you to confirm from the captured `response.txt`" passage, `tests/task/evals/grade.sh`'s head block beginning "Output-verdict expectations" and ending "the LLM-graded expectations in evals.json", `tests/task/evals/run.py`'s "prose-verdict confirmation the operator does by reading `response.txt`" and "remain operator-confirmed" passages, and `tests/task/RUNBOOK.md`'s "leave verdict-string checks to `expectations[]` (agent-attest)" line. Each becomes a statement that the grader reads the response through `RESPONSE_FILE` and that `agent-attest` covers only the judgements no check can decide. The `grade.sh` head block is a distinct passage from the `coherence_wrote_nothing` comment step 3 already names. State the unset `RESPONSE_FILE` contract in that same `grade.sh` head block, so the block carries one division rather than a second appended note: with `RESPONSE_FILE` unset the grader grades the sandbox checks and skips only the checks that read the response, while a `RESPONSE_FILE` that is set but empty fails those checks — the case Acceptance item 4 proves — and step 4's pin passes an empty `response.txt` through `RESPONSE_FILE` rather than leaving it unset. Add the two-argument hand-run sites to that step's rewrite list and rewrite each in place to both outcomes, naming `RESPONSE_FILE=<path to the captured response.txt>` for a graded response beside the unset form for a sandbox-only grade: `tests/task/evals/README.md`'s `bash tests/task/evals/grade.sh <eval_id> "$sandbox_proj"` manual-phase command and its `## Success` line, and `tests/task/RUNBOOK.md`'s `bash evals/grade.sh <id> "$sandbox_proj"` and `bash tests/task/evals/grade.sh finish "$sandbox_proj"` lines.
4. **Prove the fail branch in the harness's own script tests.** Each harness that ships a `script_tests/` layer gains one scenario there — `git_checkout`, `git_review`, `git_refresh`, `git_auto_review`, `task`, and `task_auto_check` — that stages an eval, grades it against an empty response, and asserts a non-zero exit. The two Python harnesses pin the same floor in the deterministic surface they already ship, since `tests/natural_language/README.md` states that tree has no `script_tests/` layer and `tests/README.md`'s Pattern B entry leaves `tests/wiki/` on `layer1/run.sh`: `tests/natural_language/evals/test_grade.py` gains the empty-delivery case, and `tests/wiki/layer1/run.sh` gains the scenario that drives `layer2/grade.py` over a run directory holding one empty `response.txt` pass. Add each harness's pin before that harness's grader edit: run it against the unedited grader, record the red result in the probe note the Acceptance item beginning `The probe is recorded for commit` requires, then make that harness's grader edit and re-run the same pin to green. That pin is the regression: a later edit that removes the positive check turns it red.
5. **Give the two Python graders the same floor, in their own shape.** In `tests/natural_language/evals/grade.py`, `build_checks` gains a `response_text_present` check for `chat_brevity` whose predicate is `bool(delivered.strip())`, beside the existing two, so an absent or empty `response.txt` fails through the same `return 0 if verdict["passed"] else 1` path every other check uses; mirror the `delivered_text_present` check `tests/language_humanizer/evals/grade.py` already carries. In `tests/wiki/layer2/grade.py`, `main` returns non-zero when the summary it wrote holds no pass or any pass with `passed` false, keeping the `grading_summary.json` write and the printed per-pass lines unchanged. `tests/wiki/layer2/run.py`'s grading call changes in place from `subprocess.run([sys.executable, str(GRADE), str(run_dir)], check=True)` to capture the return code with `check=False`, so an ordinary failing run still reaches `aggregate.py` and `render_report.py` and writes `benchmark.json`, `benchmark.md`, and `report.html` with the regression compare, and `main` returns non-zero when that captured grade code or the aggregate return code is non-zero. Rewrite `tests/CLAUDE.md`'s sentence beginning "The aggregator compares against the most recent prior" in place so the documented `run.py` exit contract names both signals. Extend `tests/natural_language/evals/test_grade.py` and `tests/wiki/layer1/run.sh` with the empty-input case asserting the non-zero exit, and rewrite in place any sentence in `tests/wiki/README.md`'s `grade.py` description or `tests/natural_language/README.md`'s `grade.py` paragraph that the new exit contract falsifies.

6. **Give the `task_auto_check` arms the inert-worker probe grades PASS on an empty response their own enforced check.** `tests/task_auto_check/evals/grade.sh` decides a response check only when a transcript exists: every arm whose response checks sit behind the presence guard `if [[ -s "$RESPONSE" ]] … else note_agent_attest` falls to attest on an empty `response.txt`, so the arm exits 0 on an untouched sandbox, and the arms that carry only absence-shaped sandbox checks exit 0 the same way. Replace that guard in every arm that uses it — found at implementation time by that shape, whether it grades a helper-failure stop or a citation-survival report — so a present-but-empty `response.txt` fails an enforced check that reads the transcript and asserts the substance the arm's attest notes describe: for a helper-failure arm, that the transcript names the helper the arm injects and asks the user how to proceed; for a citation-survival arm, that the transcript names the refutation pass and the surviving citations. Give every other arm the inert-worker probe grades PASS on an empty response one enforced check whose predicate is false on an untouched sandbox, preferring a sandbox or invocation fact and reading the transcript through the `RESPONSE` value the grader already resolves where only the response carries the evidence. Keep each arm's existing sandbox-state checks beside the new transcript check, and keep the attest notes for the judgements no check can decide.

Keep the added checks to one or two per eval. The aim is a floor that an inert worker cannot clear, not full enforcement of every prose expectation.

**Out of scope:** Enforcing the operator-confirmed `agent-attest` prose judgements generally, which keeps the operator's confirmation role for the expectations this task leaves unenforced; the rewritten head comments and `tests/task/evals/README.md` state that division once, in its post-change form. Adding new evals or new fixtures. Converting the `task_create` / `task_fix` graders, the `tests/language_humanizer` grader and judge, and both `judge.py` files, which already fail an inert worker, and `tests/trigger_evals/run.py`, whose `WORKER_FAILED` sentinel already keeps a dead worker out of both pass counts and whose `expected_skill: null` queries measure a deliberate non-trigger rather than an absent artefact.

**Co-edits.** This task edits three runners beside the graders: `tests/git_checkout/evals/run.py` gains the invocation record Approach step 1 needs, `tests/git_refresh/evals/run.py` gains the response channel Approach step 1 needs for eval 4, and `tests/task/evals/run.py` gains the response plumbing Approach step 3 needs. Two sibling tasks rewrite runners and must be rebased over these edits, not re-merged: [the git-review parallel-evals task](tests_git-review-parallel-evals.md) rewrites `tests/git_review/evals/run.py`, and [the task-hub parallel-evals task](tests_task-hub-parallel-evals.md) rewrites `tests/task/evals/run.py` and its `evals/test_run.py`, so that task rebases over this task's `tests/task/evals/run.py` edit whichever lands second. No sibling task changes a `grade.sh` check, so the added positive checks survive either landing order. This task's own `script_tests/` scenarios in `git_checkout`, `git_review`, `git_refresh`, `git_auto_review`, `task`, and `task_auto_check` are separate from the stage-guard scenario [the stage-guard task](tests_eval-stage-guard.md) adds to `agent_spinner`, `git_auto_review`, and `guardrail_audit`; the two overlap only on `git_auto_review/script_tests/run.sh`, so whichever lands second appends. The two Python-grader edits in step 5 touch no runner, so they land beside any sibling. The `tests/wiki/layer1/run.sh` pin and the `tests/natural_language/evals/test_grade.py` case are new, so they collide with nothing.

## Acceptance

- Running the inert-worker probe over every eval in `git_checkout`, `git_review`, `git_refresh`, `git_auto_review`, `task`, `task_auto_check`, `natural_language`, and `wiki/layer2` — stage each eval, write an empty response file, grade — returns a non-zero exit for every eval in those harnesses. The probe re-derives its before-count from Context's measurement loop, and after the change it grades PASS for no eval in any of those harnesses. For `wiki/layer2`, whose grader reads a run directory rather than one eval, the probe writes a run directory holding one pass with an empty `response.txt` and asserts a non-zero exit.
- Each harness named above gains the pin `## Approach` step 4 names for it — a `script_tests/` scenario in the six shell-grader harnesses, `tests/natural_language/evals/test_grade.py` in `natural_language`, and a `tests/wiki/layer1/run.sh` scenario in `wiki/layer2` — that performs that probe over its own eval set and fails when any eval grades PASS. For `task_auto_check`, the pin stages an arm whose response checks sat behind the presence guard before the change, so its recorded red result is that arm's inert PASS. Each pin is added and run before that harness's grader edit, and its red result — the pin's exit code and the eval id the unedited grader scored PASS — is recorded in the probe note the item beginning `The probe is recorded for commit` requires; the same pin is green after the edit. The `natural_language` and `wiki/layer2` pins assert the grader's non-zero exit on an empty delivery rather than a full-set sweep, because those harnesses grade through a Python entry point.
- Every eval that the inert-worker probe of the first item grades PASS before the grader edits carries at least one check whose predicate is false on an untouched sandbox and true only after the behaviour under test occurs. The probe re-finds that member set at implementation time, and each eval it names carries the check. The eval list in Context records the 2026-10-30 members as an illustration of the selector; it does not bound the set. For an eval whose evidence is the helper invocation, that check proves the run reached the decision the eval tests: the recorded call together with its argument shape or the reported cause token, not the invocation record alone. `tests/wiki/layer2/grade.py`'s `main` exits non-zero for a run directory holding no pass, or any pass the grader marks `passed: false`; `tests/wiki/layer2/run.py` invokes that grader without `check=True`, still writes `benchmark.json`, `benchmark.md`, and `report.html` for a run directory holding one failed pass, and returns non-zero for it.
- The eight response-only `task` evals' graders read the response the runner passes them: a grading run against the captured `response.txt` resolves the planted subject, and the same run against an empty response file exits non-zero.
- Searching `tests/git_checkout/evals/grade.sh`, `tests/git_checkout/evals/README.md`, `tests/git_refresh/evals/grade.sh`, `tests/git_refresh/evals/README.md`, and every tracked file under `tests/task/`, each read as continuous prose with leading comment markers and hard wraps collapsed to single spaces and emphasis markers stripped, returns no passage that states the pre-change blanket rule: that a response or helper-invocation expectation cannot decide the exit code at all, or that a verdict-string expectation stays operator-confirmed because the grader cannot read the agent's response. A passage that names which eval's check decides the exit code and then says what remains operator-confirmed is the required post-change division, not a match, so the search excludes any passage naming a deciding check for an eval this task converts. The literals `never decide the exit code`, `cannot read the agent's response text`, `never sees the agent's response text`, `cannot be checked here`, `cannot read out of the agent's response`, `the one place free-form response text is load-bearing`, `stay for you to confirm from the captured`, `remain operator-confirmed`, and `leave verdict-string checks to` locate the usual shapes of that concept and do not bound it.
- Each surface named in `## Approach` steps 1, 3, and 5 states the post-change division in place and separately for each harness: the `git_checkout` `grade.sh` and README keep the still-true statement that their response lines never decide the exit code and add that the helper invocation is graded from `script_calls.log` and does decide it; the `git_refresh` `grade.sh` and README name the eval whose invocation check now decides the exit code and the evals whose invocation lines stay operator-confirmed; every `tests/natural_language/` and `tests/wiki/` passage that states what its grader checks or returns states the non-zero exit on an empty delivery; and every rewritten passage under `tests/task/` states that the grader reads the response through `RESPONSE_FILE` and that `agent-attest` covers only the judgements no check can decide. This item holds independently of the negative search above, and a surface whose pre-change passage is deleted rather than rewritten fails it.
- The probe is recorded for commit as a script or a note under `tests/lib/`, naming the command that runs it and the harness set it covers, so a later change can re-measure the same property rather than re-derive it.
- `make lint` passes, and `tests/AGENTS.md` and `tests/CLAUDE.md` name the new `script_tests/` scenario in their parallel-workers and coverage prose where those files already enumerate harness scenarios.
