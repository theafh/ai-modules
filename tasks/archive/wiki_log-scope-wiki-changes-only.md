# Scope a log entry to wiki changes, with a lint check and ensure/refresh preamble convergence

## Goal

Every wiki generated from or maintained by this skill states that a `log.md` entry records changes to the wiki, and only those. The shipped log preamble and schema template carry the rule, the linter flags an entry whose subject is a file outside the wiki, and an existing wiki converges through the scaffold restore path already in place rather than through a migration sweep. The outcome an owner sees: their log stays an index into the wiki's own history instead of turning into a second changelog that drifts from git, and the drift is caught by a check rather than by the owner noticing it twice.

This task owns the **content** of one default rule: what belongs in a log entry, for every wiki. How a wiki's local divergence from a template is treated at all is the mechanism question owned by [wiki_sanctioned-template-deviations.md](../wiki_sanctioned-template-deviations.md), and the two are independently shippable in either order.

## Context

The canonical preamble in [references/template_log.md](../../plugins/knowledge_management/skills/wiki/references/template_log.md) governs when an entry exists and never says what an entry may be about. Its `Entries:` group settles the trigger, `an operation that creates or updates wiki files appends one entry`, and its `Body:` group settles selection, `list only files actually created or updated`. Both are silent on subject scope, and that silence is the hole: a change to the surrounding repository is also a file that was created or updated, so an agent writing the whole session into the log complies with the letter of both rules. The finished [wiki_log-entries-only-on-changes.md](wiki_log-entries-only-on-changes.md) closed the trigger half of this contract and deliberately left the subject half alone; this task is that half, and the same reasoning applies — fix the general behaviour definition in the skill and templates rather than point-patching one wiki.

The failure mode is not hypothetical and not confined to one wiki. In two separate wikis managed by this skill, the owner had to correct the same drift by hand. Entries had grown into commit messages: the subject of a bullet was a file in the repository's source tree, its tooling, or its test suite, with version bumps, release notes, and measured test results attached, and a single wiki-file bullet somewhere inside. Entries had also become a parking lot for findings no page carried, so knowledge that belonged on a page was filed where nobody reads it back. The cost is twofold and both halves compound: a log that duplicates git drifts from it, and the wiki's actual change history becomes unreadable underneath the noise. In the more recent case the correction removed roughly a quarter of the file's lines.

One live sibling and one shipped archive boundary bound the work:

- [wiki_sanctioned-template-deviations.md](../wiki_sanctioned-template-deviations.md) builds the general mechanism for a wiki to declare an intentional divergence from a verbatim-locked slot, so an audit stops reverting it. Its motivating incident was an owner adding exactly this scope rule to their own preamble and an audit deleting it. That task and this one are complements, not alternatives: this rule belongs in canon because it is general, and the declaration mechanism stays for the refinements that are genuinely local. Once this task lands, a wiki carrying the rule as a declared local deviation retires that declaration, because its text matches canon again. This task's convergence rewrites `<fix_log_preamble_drift>` to ensure canonical preamble units — insert absent, refresh drifted by label or greppable stem, leave wiki-only lines — per **Let convergence ride the existing path, additively.**; the general classify-versus-restore judgement on locked-slot divergences — including `check_verbatim_boilerplate` and `<linter_is_truth_for_structure>` — stays with that task. Independence versus composed durability for that either-order claim is settled under **Let convergence ride the existing path, additively.**
- [wiki_lint-accepted-info-suppression.md](wiki_lint-accepted-info-suppression.md) owns the per-finding acceptance store and scopes matching to `SEV_INFO`. The check added here emits at info, so it never blocks the agent's clean-exit bar and drives no fix loop; independence holds because the check uses distinct `Issue.category` `log-scope` (same distinct-key discipline as `log-heading` in [wiki_log-heading-uniqueness-and-repair.md](wiki_log-heading-uniqueness-and-repair.md)), so `log`'s two-field single-emit premise and this check do not collide and neither task widens to reach the other.

This task also co-edits the `template_log.md` preamble with [wiki_log-heading-uniqueness-and-repair.md](wiki_log-heading-uniqueness-and-repair.md) (timestamped heading format plus repair carve-out) and [wiki_log-session-entry-consolidation.md](../wiki_log-session-entry-consolidation.md) (append-only scoping plus session consolidation). Each preamble edit drifts every existing wiki's `log.md` boilerplate once, so landing the three together spends that drift a single time; word this task's `Scope:` group against whichever preamble text is current when it builds.

## Approach

1. **State the scope rule in the canonical preamble.** Extend the blockquote in `template_log.md` with a `Scope:` group beside the existing `Entries:` and `Body:` groups: an entry names files under the wiki and what changed on each; a change elsewhere in the repository that holds the wiki belongs to that change's own commit message; knowledge worth keeping goes onto the wiki page that owns it, after which the entry names that page instead of restating it. Name the failure the rule prevents in one clause, since an agent applies a rule it understands the purpose of more reliably than a bare prohibition: an entry that reads as a commit message with a wiki bullet attached, or that parks findings no page carries. Keep the group generic — the wiki's own tree is the only thing the template can name portably, so state the boundary as inside-the-wiki versus outside rather than by listing directory names any one repository happens to have.

2. **Mirror it in the schema template.** The log convention bullet in [references/template_schema.md](../../plugins/knowledge_management/skills/wiki/references/template_schema.md), which currently opens `**Append every operation that creates or updates wiki files to \`log.md\`**`, states the trigger and stops. Rewrite it in place to carry the subject scope too, pointing at the preamble as the point-of-use copy rather than restating the whole rule twice.

3. **Carry the subject scope in the skill's authoring surface.** Rewrite `<appending_to_log>` and the **Log only what changed** pitfall in `skills/wiki/SKILL.md` in place so each carries the subject-scope rule and points at the preamble's `Scope:` group as the point-of-use copy rather than restating the whole rule twice.

4. **Add the check.** For each entry body bullet, take the subject — the text before the bullet's first separator — and emit a finding when that subject is path-shaped and it resolves outside the wiki root. Resolve on this dual-base order: (1) **absolute** — an absolute or `~`-expanded path whose resolved location is outside the wiki root → finding; (2) **wiki `..` escape** — `(wiki / subject).resolve()` lands outside the wiki root → finding; (3) **existing repo-root** — when `_git_repo_root(wiki)` is not `None` and `(repo_root / subject).resolve()` is an existing file outside the wiki root (reuse `_git_repo_root`; follow the repo-root join-if-exists pattern in `check_raw_origin_form`, do not call that check) → finding; (4) otherwise **wiki-relative** — no finding even when the named file is absent. A bare `name.ext` is class (4). Existence on disk discriminates only branch (3), not (4). Treat as separators the first match among `:`, ` — `, ` – `, and ` | `; when none appear, the whole remainder after the list marker is the subject. Example with a separator: `- concepts/foo.md: added section` → subject `concepts/foo.md`. Example with none: `- Lint clean across the vault` → subject is the full remainder. Treat a subject as path-shaped only when the entire subject is one path token — a single relative or absolute path string with no surrounding prose — either containing `/` or a bare filename with a dotted extension. A prose subject that merely embeds path substrings is not path-shaped. Example that is path-shaped: `- plugins/ai_dev/skills/task/SKILL.md: bumped version` → subject `plugins/ai_dev/skills/task/SKILL.md`. Examples that are not: `- Outcome: lint passed with 0 errors` → subject `Outcome`; `- Structure created with SCHEMA.md, index.md, log.md, raw/, entities/, concepts/, comparisons/, queries/, summaries/, procedures/` → subject is the full remainder (scaffold seed shape). The subject position is the whole discriminator and the boundary that keeps the check honest: a non-wiki path cited inside a bullet as the source a claim was drawn from is legitimate provenance and must not fire, while the same path standing as what the bullet is about must. Emit at info under `Issue.category` `log-scope` (distinct from `log`, so `log`'s single-emit / two-field premise stays intact), aggregated into one finding per run that names the count and a few offenders rather than one finding per bullet, so a wiki with historical violations gets a signal instead of a swamped report. Register `log-scope` in `TWO_FIELD_CATEGORIES` beside `log`, for the same reasons: one line-less Issue per path (`log.md`) and a message that embeds a volatile count, so path alone identifies the finding and acceptance never keys on the count substring. Info is the deliberate level. The log is append-only by design and this task ships no clearing move for a historical violation, so a warn would strand the `auto_shaper_wiki` agent on a bar it cannot reach. That is the same reasoning the sibling log checks in [wiki_log-heading-uniqueness-and-repair.md](wiki_log-heading-uniqueness-and-repair.md) and [wiki_log-rotation-and-retrieval.md](../wiki_log-rotation-and-retrieval.md) follow. New entries stay correct because the rule binds the agent's authoring directly per **Report, never silently rewrite.**, which needs no lint severity. Parse fence-safe, consistent with the section readers already in [skills/wiki/scripts/lint.py](../../plugins/knowledge_management/skills/wiki/scripts/lint.py). Document the check in `references/lint_checks.md` (matrix row; info severity bucket; and the two-field acceptance-form row rewritten so membership is `size`, `log`, `stale`, and `log-scope`, superseding the prior trio-only claim) and in the severity-bucket listing in `skills/wiki/SKILL.md`, superseding the over-500-entries-only listing of log info checks.

5. **Report, never silently rewrite.** The log is append-only by design, so the agent in [agents/auto_shaper_wiki.md](../../plugins/knowledge_management/agents/auto_shaper_wiki.md) reports a violating entry and leaves the text alone; trimming historical entries is an editorial decision the owner makes. Where the agent writes a new entry, the rule binds it directly.

6. **Let convergence ride the existing path, additively.** Rewrite `<fix_log_preamble_drift>` in `agents/auto_shaper_wiki.md` so it ensures every canonical preamble unit from `references/template_log.md` above the first `## [` — labeled groups such as `Entries:`, `Body:`, and `Scope:`, and unlabeled lines such as `Chronological record` and `When this file exceeds 500 entries` — by (a) inserting any unit absent from the live preamble and (b) refreshing any drifted unit matched by its label (for labeled groups) or by greppable stem (for unlabeled lines) to the current template text, while leaving wiki-only lines in the preamble region in place. Never wholesale-delete or wholesale-replace the preamble region. Confirm insert and refresh in fixtures rather than assuming them. Co-editors that reword a shared canonical unit propagate through that refresh; compose with [wiki_sanctioned-template-deviations.md](../wiki_sanctioned-template-deviations.md) without absorbing its classify-versus-restore mechanism for owner extensions, and without absorbing an interim carve that would grant composed durability before that sibling ships. Independence is the content rule and either-order shipping with that sibling; composed durability — owner-line preservation through a full clean audit after leftover `boilerplate` warn clearance — lands only with that sibling. The Layer 2 scenario for the additive-owner fixture grades only the `log.md` postconditions — canonical `Scope:` present and the owner line byte-identical, with a leftover `boilerplate` warn about that extension allowed — and does not grade `<lint_clean>`; clearing that warn stays with that sibling. Leave `check_verbatim_boilerplate`, `<linter_is_truth_for_structure>`, and the declaration path to that sibling.

**Out of scope:** rewriting historical entries in any existing wiki, which stays with the owner per **Report, never silently rewrite.** Widening the shipped SEV_INFO acceptance store from [wiki_lint-accepted-info-suppression.md](wiki_lint-accepted-info-suppression.md) to warn findings. Building the declaration and promotion mechanism, and rewriting `check_verbatim_boilerplate` / `<linter_is_truth_for_structure>` for classify-versus-restore, which stay with [wiki_sanctioned-template-deviations.md](../wiki_sanctioned-template-deviations.md).

## Acceptance

- `template_log.md`'s preamble carries the `Scope:` group described in **State the scope rule in the canonical preamble.**, including the named failure mode, and a freshly scaffolded wiki carries it verbatim.
- The `template_schema.md` log convention bullet states subject scope alongside the trigger and points at the preamble; the prior trigger-only wording is superseded rather than left beside the new text.
- `<appending_to_log>` and the **Log only what changed** pitfall in `skills/wiki/SKILL.md` each state subject scope and point at the preamble `Scope:` group; the prior trigger-and-body-only wording in those passages is superseded rather than left beside the new text.
- Fixture entries whose bullet subjects are paths outside the wiki draw the info finding; the fixtures together exercise each of the four separators named in **Add the check.** (`:`, ` — `, ` – `, ` | `) and include absolute, `~`-expanded, and relative-with-`/` path-token subjects that resolve outside the wiki per that step (an existing file under the repo root outside the wiki (repo-root branch of **Add the check.**), and `..` escape). Bare-`name.ext` is not an outside-wiki fixture subject (it joins under the wiki per **Add the check.**).
- A Layer 1 fixture with an aggregated `log-scope` info finding accepted via the two-field form (`Accepted finding: log-scope — <wiki-root-relative log path>`) suppresses that finding after the volatile count substring in `Issue.message` changes, proving `log-scope` membership in `TWO_FIELD_CATEGORIES` and the two-field match predicate for this emit shape.
- A fixture entry whose bullet subject is a wiki file and which cites a path outside the wiki mid-bullet as the source of the claim draws no finding, proving the subject-position boundary in **Add the check.**
- A fixture log with violations in several entries draws one aggregated finding naming the count, not one finding per bullet.
- A fixture whose only violating text sits inside a fenced block draws no finding.
- A fixture entry with a non-path subject, such as a lint outcome line, draws no finding.
- A fixture entry whose bullet subject is prose that embeds path substrings in the scaffold seed shape (names such as `SCHEMA.md`, `index.md`, `log.md`, `raw/`, and sibling directory tokens inside one prose remainder) draws no finding, proving the whole-subject path-token rule in **Add the check.**
- A fixture entry whose bullet subject is a path-shaped token under the wiki root that names a file absent from disk draws no finding, proving the path-boundary (not missing-file) reading of resolve-under-wiki-root in **Add the check.**
- `references/lint_checks.md` and the severity-bucket listing in `skills/wiki/SKILL.md` name the new subject-scope log check under category `log-scope` beside the existing log-over-500 info check; the prior over-500-only listing of log info checks is superseded. The same `lint_checks.md` two-field acceptance-form row lists `log-scope` beside `size`, `log`, and `stale`; the prior trio-only membership claim is superseded.
- An `auto_shaper_wiki` run over a fixture log containing a violating historical entry leaves that entry's text byte-identical and names it in the report.
- An `auto_shaper_wiki` run over a fixture wiki whose preamble predates the rule and declares no deviation for that slot ends with the canonical `Scope:` group present in the wiki's `log.md`.
- An `auto_shaper_wiki` run over a fixture wiki whose preamble both lacks the canonical `Scope:` group and carries an owner-added line in that region ends with the `Scope:` group present at template text and the owner's line preserved byte-identical, proving `<fix_log_preamble_drift>` ensures missing labeled units without restoring the region wholesale per **Let convergence ride the existing path, additively.** That scenario grades only those `log.md` postconditions; a leftover `boilerplate` warn about the owner extension does not fail the item, and the run is not required to satisfy `<lint_clean>`. The prior insert-missing-only framing of that fix move is superseded.
- An `auto_shaper_wiki` run over a fixture wiki whose preamble is missing one unlabeled canonical unit (for example the chronological-record opener or the rotation rule) and declares no deviation for that slot ends with that unit present at template text, proving unlabeled-unit insert under **Let convergence ride the existing path, additively.**
- An `auto_shaper_wiki` run over a fixture wiki whose preamble carries a drifted labeled canonical unit (label present, body not byte-identical to the current template — e.g. an older co-editor reword of `Entries:` or `Body:`) together with an owner-added wiki-only line in that region ends with the labeled unit refreshed to current template text and the owner's line preserved byte-identical, proving refresh-by-label without wholesale region restore per **Let convergence ride the existing path, additively.** That scenario grades only those `log.md` postconditions and does not require `<lint_clean>`.
- An `auto_shaper_wiki` run over a fixture wiki whose preamble carries a drifted unlabeled canonical unit (stem present, body not byte-identical to the current template — e.g. a reword of `Chronological record` or `When this file exceeds 500 entries`) together with an owner-added wiki-only line in that region ends with that unit refreshed to current template text and the owner's line preserved byte-identical, proving refresh-by-stem without wholesale region restore per **Let convergence ride the existing path, additively.** That scenario grades only those `log.md` postconditions and does not require `<lint_clean>`.
- Layer 1 scenarios under default `tests/wiki/run_all.sh` exercise every lint-fixture scenario named above and pass with them harness-wired. Layer 2 scenarios under `tests/wiki/run_all.sh --layer2` exercise every `auto_shaper_wiki` scenario named above and pass with them harness-wired.
