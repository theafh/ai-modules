# Stop the boilerplate check from overruling the preserve-extensions rule

## Goal

The skill stops giving two opposite instructions about the same hunk. The agent already classifies content a wiki has and the canonical template lacks as a customization to preserve when it extends the canon without contradicting it; the locked-slot boilerplate check overrules that verdict by naming restoration of the canonical text as the remedy, and the check currently wins. After this task the check uses the structural insert-only classification Approach freezes (pure additions agree with the agent's preserve path; any delete or replace still warns), so an owner's addition inside a template-locked region of their own `SCHEMA.md` or `log.md` is reported as an extension rather than as something to restore away, a region that deletes or rewrites canonical text still warns, and a wiki that means to contradict canon can declare that and have the declaration honoured. Reverting a declared divergence goes out of bounds for the agent, and a divergence the agent judges good in general is reported as a candidate for the shipped template rather than deleted in the one wiki that has it.

The outcome the owner sees: a rule they anchored in their wiki is still there after an audit, and an audit that removed one is no longer reported as a clean run.

This task owns the **mechanism** — how any local divergence from a template is treated, whatever it says. What a log entry should contain by default is a content question owned by [wiki_log-scope-wiki-changes-only.md](wiki_log-scope-wiki-changes-only.md), and the two are independently shippable in either order.

## Context

Two shipped mechanics currently leave an owner's refinement of a locked region with no path but removal.

The linter locks two regions byte-for-byte against the shipped templates. `check_verbatim_boilerplate` in [skills/wiki/scripts/lint.py](../plugins/knowledge_management/skills/wiki/scripts/lint.py) walks the `VERBATIM_SLOTS` tuple, extracts each slot's region from the wiki and from its template, and on any difference emits a `boilerplate` warn whose message ends `restore the region verbatim or update the template if the change is intentional`. Those are the only two remedies the message offers, and neither preserves a per-wiki refinement: the first deletes it, and the second is unavailable to a wiki owner editing their own wiki, since the template ships from this repo and editing it does not reach a wiki that already exists.

The skill already carries the right rule, in the wrong place to win. `<hunk_classification>` in [agents/auto_shaper_wiki.md](../plugins/knowledge_management/agents/auto_shaper_wiki.md) rules that content the wiki has and the canonical lacks is a customization to preserve as-is when it extends the canon without contradicting it, and surfaces it for the user only when it contradicts canonical semantics. An owner's added paragraph inside a locked region is an extension by that test, so the classifier's verdict is preserve. The `boilerplate` finding overrides that verdict, because `<linter_is_truth_for_structure>` makes structural lint output authoritative and the finding's own message names restoring the canonical text as a remedy. Two mechanisms in one skill therefore give opposite instructions on the same hunk, and the one that wins is the one that destroys the owner's work. Note also that `<configurable_zones>` grants `template_log.md` a zone for entries and their bodies while deliberately running the diff on the preamble alone, so the preamble is the single region with no configurable zone and no classifier protection that survives contact with the check.

The agent then acts on that signal. `<scaffold_drift>` in [agents/auto_shaper_wiki.md](../plugins/knowledge_management/agents/auto_shaper_wiki.md) drives comparison from a line-level diff against each canonical template, and `<linter_is_truth_for_structure>` makes the linter's structural output authoritative. Nothing in either instruction distinguishes an owner's deliberate addition inside a locked region from accumulated drift, so the remediation available is to restore the canonical text. Two further agent sites still demand restore-to-canonical on those same slots even when the check later classifies an addition as an extension: `<lint_already_covers_prelude>` treats any prelude/preamble mismatch as already named for remediate because the boilerplate check enforces verbatim equality, and `<fix_log_preamble_drift>` instructs restoring the canonical preamble lines while leaving only entries below untouched.

Observed end to end once, in a wiki managed by this skill, and the diagnosis below is a reading of the two instruction blocks named above rather than a ruling by the skill's author: the owner added a paragraph to the `log.md` preamble scoping log entries to changes of the wiki itself, and anchored the same rule in that wiki's `SCHEMA.md` and in the repository's agent instruction files. The next audit read the preamble difference as scaffold drift and deleted the paragraph. The owner caught it mid-run and ordered it restored. Left alone, the audit would have reported a clean run while having removed the rule it was asked to maintain, which is the failure mode this task closes: a silent revert reads afterwards as compliance.

Three sibling tasks bound this one; two remain live and [wiki_lint-accepted-info-suppression.md](archive/wiki_lint-accepted-info-suppression.md) is already implemented, so compose with the live siblings and reuse that sibling's shipped surfaces rather than overwrite:

- [wiki_log-scope-wiki-changes-only.md](wiki_log-scope-wiki-changes-only.md) promotes the rule from the motivating incident into canon, because scoping a log entry to wiki changes turned out to be a general failure mode rather than one wiki's preference — the same drift was corrected by hand in two wikis. That settles what this incident is evidence for: the mechanism gap, not a permanently local refinement. Keep the incident as the evidence and do not present that rule as this mechanism's standing example, since the wiki carrying it as a declaration retires the declaration once canon carries the rule.
- [wiki_lint-accepted-info-suppression.md](archive/wiki_lint-accepted-info-suppression.md) has already landed the per-finding acceptance store as labeled `Accepted finding:` bullets in the SCHEMA `## Lint` section, parsed fence-safe like the existing `Page-check exclusions:` bullet, plus the runner surfaces `Issue.render_acknowledged`, `partition_accepted`, and the report's `ACKNOWLEDGED` section. Matching stays `SEV_INFO` only; a matching acceptance never suppresses a non-info finding. A `boilerplate` finding is a warn, so that mechanism cannot carry this case, and this task does not widen it to warns. What this task reuses is that shipped storage decision, parser, and acknowledged channel: another labeled bullet in the same section, registered in the agent's `<configurable_zones>` entry for `template_schema.md` beside the bullets that sibling and [wiki_page-type-growth-and-anatomy.md](wiki_page-type-growth-and-anatomy.md) register there. Add the `Declared boilerplate:` bullet beside the already-present sibling bullets rather than replacing them.
- [wiki_schema-template-generalization.md](archive/wiki_schema-template-generalization.md) rewrites the same slot set from the other side. Its defect numbered for the attribution paragraph proposes dropping the `SCHEMA.md prelude` lock as compelled rather than offered, while keeping the `log.md preamble` lock because that region is load-bearing format documentation. This task agrees with that split and depends on nothing in it: the lock stays, and the declaration is what makes a locked slot survivable. If that task lands first and one slot is gone, this task's mechanism applies to whichever slots `VERBATIM_SLOTS` still holds, which is why the work below reads the tuple rather than naming a fixed pair.

## Approach

1. **Make the check classify instead of demanding verbatim restoration.** Rewrite `check_verbatim_boilerplate` so a mismatch is classified before any restore message is emitted. Compare the extracted wiki region to the extracted canonical region with a line-level sequence alignment (`difflib.SequenceMatcher` opcode walk over lines; opcodes limited to equal / insert / delete / replace). **Insert-only** — every canonical line survives in order and the only non-equal opcodes are inserts — is an **extension**: report it on a dedicated **acknowledged** report channel that is outside the three live severity totals (`blocking` / `warn` / `info`), never as a live `warn` or live `info` Issue; reuse the acknowledged-section shape [wiki_lint-accepted-info-suppression.md](archive/wiki_lint-accepted-info-suppression.md) already landed via `Issue.render_acknowledged`, `partition_accepted`, and the report's `ACKNOWLEDGED` section, naming the slot and that content was added, and emit no `boilerplate` warn and no restore-verbatim instruction. `check_verbatim_boilerplate` returns `(live_issues, acknowledged_items)`; `main` extends the shared issues list with `live_issues` only; after `partition_accepted`, append those boilerplate `acknowledged_items` onto the acknowledged list before `render_report`. Insert-only extensions and matching declarations never appear as live `warn` or live `info` Issues and never invent a fourth severity. Compose `Issue.render_acknowledged` so the acknowledged line marker is parameterized — `(accepted)` for Accepted-finding suppressions, `(extension)` for insert-only locked-slot extensions, `(declared)` for matching `Declared boilerplate:` honours — and widen the `ACKNOWLEDGED` section header beyond accepted-only wording so it covers those three sources without implying every acknowledged line was an `Accepted finding:` bullet. **Any delete or replace** of canonical content keeps today's warn, with both remedies named as today. The check does not judge semantic contradiction; that path is the declaration in step 2 plus the agent's existing surface-for-user posture. This is the cheap half and needs no new wiki syntax, which is why it leads.

2. **Declare a deliberate contradiction, for the case classification cannot settle.** Add one labeled bullet per declared slot to the SCHEMA `## Lint` section. Freeze the grammar as `- Declared boilerplate: <slot.label> — <reason>`, where `<slot.label>` is the exact `VerbatimSlot.label` string from `VERBATIM_SLOTS` and `<reason>` is a short free-text explanation. Parse with the same fence-safe `## Lint` scan as `Page-check exclusions:` / `Accepted finding:`: read only outside fences; match the label case-insensitively; left-anchor on ` — ` so the machine key is the slot-label field and the reason is the remainder (reason is not matched). A live bullet suppresses the `boilerplate` warn only when its slot-label field equals that slot's `label` exactly. A live `Declared boilerplate:` bullet whose slot-label field matches no `VerbatimSlot.label` in `VERBATIM_SLOTS` suppresses nothing and emits one live `SEV_INFO` Issue with category `boilerplate`, path `SCHEMA.md`, naming the unmatched label; it is not placed on the acknowledged channel. Document the bullet in [references/template_schema.md](../plugins/knowledge_management/skills/wiki/references/template_schema.md) `## Lint` as a fenced example mirroring the exclusions bullet, and compose with the two sibling tasks at that section per `## Context`.

3. **Honour the declaration in the runner.** In `check_verbatim_boilerplate`, a slot with a matching `Declared boilerplate:` bullet emits no `boilerplate` warn and no Issue in any of the three live severity buckets. Report it on the same non-counted acknowledged list and `render_report` path step 1 wires — again without `Accepted finding:` matching and without emitting into any live severity bucket — naming the slot and the declared reason, so the divergence stays visible without an undo instruction and without inflating blocking/warn/info totals or the live `total:` summary. An undeclared *remove-or-rewrite* divergence is unchanged: same warn, same message, both remedies still named. An undeclared *extension* follows step 1, not this warn path.

4. **Put reverting a locked-slot refinement the check has already cleared out of bounds for the agent.** Rewrite the agent sites that still enforce restore-to-canonical so they follow the check's classification:

- `<lint_already_covers_prelude>` — supersede the verbatim-equality / "any mismatch is already named for remediate" passage so an acknowledged locked-slot extension (no declaration) is not a restore target; a still-live restore-instructing `boilerplate` warn remains the structural signal for remove-or-rewrite drift in those slots.
- `<fix_log_preamble_drift>` — compose with [wiki_log-scope-wiki-changes-only.md](wiki_log-scope-wiki-changes-only.md) **Let convergence ride the existing path, additively.**: ensure every canonical preamble unit by inserting any unit absent and refreshing any drifted unit matched by label or canonical identity, while leaving wiki-only lines in the preamble region in place and never wholesale-deleting or wholesale-replacing the region. A still-live restore-instructing `boilerplate` warn for the log preamble remains the structural signal for remove-or-rewrite drift; an acknowledged extension and any declared-slot region stay untouched.
- `<scaffold_drift>` / hunk-classification and `<linter_is_truth_for_structure>` — keep the stronger declared-slot rule: a hunk inside a declared slot is wiki-owned and no repair touches it, with the reason in one clause (reverting an owner's declared refinement destroys a recorded decision while the audit reports success). Separately, an undeclared locked-slot extension the check reports as acknowledged is preserved the same way `<hunk_classification>` already preserves wiki-has/canonical-lacks extensions — no restore move fires on it.

1. **Report a divergence worth promoting.** Where the agent judges a declared deviation to be a general improvement rather than a local one, its final report names it as a candidate for the shipped template. That is a report line, not an edit: the agent does not modify the templates in this repo from inside a managed wiki. This closes the other half of the gap, since a refinement that only ever lives in one wiki's declaration is invisible to every other wiki generated from the same template.

2. **Teach the workflow once.** Point [skills/wiki/SKILL.md](../plugins/knowledge_management/skills/wiki/SKILL.md) and [references/lint_checks.md](../plugins/knowledge_management/skills/wiki/references/lint_checks.md) at both locked-slot routes: classify-as-extension when an undeclared region only adds to the canonical text, and the SCHEMA `## Lint` declaration when the wiki means to contradict canon. Document each route's boundary against the info-level acceptance store and the directory-level walk exclusion so the three mechanisms do not read as alternatives for one another.

**Out of scope:** widening the acceptance store to warn-level findings generally, which stays with [wiki_lint-accepted-info-suppression.md](archive/wiki_lint-accepted-info-suppression.md) and its `SEV_INFO` boundary. Deciding which slots stay locked, which stays with [wiki_schema-template-generalization.md](archive/wiki_schema-template-generalization.md). Propagating a landed template change into wikis that already exist, which rides the scaffold restore path that [wiki_log-scope-wiki-changes-only.md](wiki_log-scope-wiki-changes-only.md) exercises and confirms; here the declaration is only what keeps a refinement alive in the wiki that has it while it is still local.

## Acceptance

- A fixture wiki whose locked-slot region adds a paragraph to the canonical text under the insert-only sequence-diff rule in **Make the check classify instead of demanding verbatim restoration.**, with no declaration present and with no `Accepted finding:` bullet, draws no restore-verbatim warn, contributes nothing to the live blocking/warn/info totals, and is listed on the acknowledged channel with the `(extension)` line marker naming the addition; the same run's `ACKNOWLEDGED` section header covers the three acknowledgement sources (accepted-finding suppressions, locked-slot extensions, declared boilerplate) and no longer reads as accepted-bullets-only, proving that step.
- A fixture wiki whose locked-slot region deletes or rewrites canonical text (any delete/replace opcode under that same rule) still draws the warn with both remedies named.
- A Layer 2 (or `tests/wiki/run_all.sh --layer2`) `auto_shaper_wiki` scenario over the extension fixture ends with the added paragraph byte-identical, and the run's report does not claim a scaffold repair it did not make.
- A fixture wiki whose locked-slot region is a delete-or-replace divergence under **Make the check classify instead of demanding verbatim restoration.**, with a matching live `- Declared boilerplate: <slot.label> — <reason>` bullet in its SCHEMA `## Lint` section per **Declare a deliberate contradiction, for the case classification cannot settle.** and with no `Accepted finding:` bullet, draws no `boilerplate` warn, contributes nothing to the live blocking/warn/info totals, and is listed on the acknowledged channel with the `(declared)` line marker and its declared reason.
- The same delete-or-replace fixture without the `Declared boilerplate:` bullet still draws the `boilerplate` warn, and the message still names both the restore-verbatim and update-the-template remedies.
- A `Declared boilerplate:` bullet that sits only inside a fenced example does not suppress the warn on that same delete-or-replace fixture, proving the fence-safe parse.
- A `Declared boilerplate:` bullet naming a slot label absent from `VERBATIM_SLOTS` suppresses nothing, and the run emits one live info-level `boilerplate` finding on `SCHEMA.md` naming that unmatched label (not on the acknowledged channel), rather than failing silently.
- A `Declared boilerplate:` declaration for one slot leaves a genuine divergence in a second locked slot reported normally.
- `template_schema.md` `## Lint` documents the `Declared boilerplate:` bullet as a fenced example beside the `Page-check exclusions:` bullet, and any already-landed bullets from the two sibling tasks named in `## Context` remain present after this task's rewrite of that section.
- The agent's `<configurable_zones>` entry for `template_schema.md` names the `Declared boilerplate:` bullet alongside the sibling tasks' bullets, so a scaffold diff reads all of them as wiki-owned rather than as drift.
- After this task's rewrites, `<lint_already_covers_prelude>` no longer treats an acknowledged locked-slot extension as already named for remediate; `<fix_log_preamble_drift>` carries the composed additive ensure/refresh form in **Put reverting a locked-slot refinement the check has already cleared out of bounds for the agent.** and leaves acknowledged extensions and declared-slot regions untouched; each site's prior verbatim-equality / wholesale-restore-preamble passage is superseded.
- `<scaffold_drift>` / hunk-classification and `<linter_is_truth_for_structure>` state that a hunk inside a declared slot is wiki-owned and that no repair reverts it, each with the reason attached — the stronger declared-slot no-touch rule, distinct from the undeclared-extension preserve path above.
- The agent's reporting instruction requires naming a declared deviation the agent judges generally applicable as a template candidate, and requires leaving this repo's templates unedited from inside a managed wiki.
- `lint_checks.md` documents classify-as-extension for an undeclared locked-slot addition, the declaration route for intentional contradiction, and each route's boundary against the info-level acceptance store and the `Page-check exclusions:` walk exclusion, with no overlap in what each one suppresses.
- `SKILL.md` points at both routes: classify-as-extension with no declaration required, and the SCHEMA `## Lint` declaration for an intentional contradiction.
- A Layer 2 (or `tests/wiki/run_all.sh --layer2`) scenario over a fixture carrying a declared deviation finishes with the deviation's text byte-identical to what it was before the run.
- Layer 1 fixtures under `tests/wiki/layer1/` cover the classify-as-extension, delete-or-rewrite, declaration-present, declaration-absent, fence-safe, unmatched-slot, and second-slot cases above, and default `tests/wiki/run_all.sh` (Layer 1 only) passes with them harness-wired.
- The Layer 2 scenarios that prove the two `auto_shaper_wiki` preservation claims above are harness-wired and pass under `tests/wiki/run_all.sh --layer2` (or an equivalent explicit Layer 2 invocation).
