# Stop the boilerplate check from overruling the preserve-extensions rule

## Goal

The skill stops giving two opposite instructions about the same hunk. The agent already classifies content a wiki has and the canonical template lacks as a customization to preserve when it extends the canon without contradicting it; the locked-slot boilerplate check overrules that verdict by naming restoration of the canonical text as the remedy, and the check currently wins. After this task the check classifies the same way the agent does, so an owner's addition inside a template-locked region of their own `SCHEMA.md` or `log.md` is reported as an extension rather than as something to restore away, a region that deletes or rewrites canonical text still warns, and a wiki that means to contradict canon can declare that and have the declaration honoured. Reverting a declared divergence goes out of bounds for the agent, and a divergence the agent judges good in general is reported as a candidate for the shipped template rather than deleted in the one wiki that has it.

The outcome the owner sees: a rule they anchored in their wiki is still there after an audit, and an audit that removed one is no longer reported as a clean run.

This task owns the **mechanism** — how any local divergence from a template is treated, whatever it says. What a log entry should contain by default is a content question owned by [wiki_log-scope-wiki-changes-only.md](wiki_log-scope-wiki-changes-only.md), and the two are independently shippable in either order.

## Context

Two shipped mechanics currently leave an owner's refinement of a locked region with no path but removal.

The linter locks two regions byte-for-byte against the shipped templates. `check_verbatim_boilerplate` in [skills/wiki/scripts/lint.py](../plugins/knowledge_management/skills/wiki/scripts/lint.py) walks the `VERBATIM_SLOTS` tuple, extracts each slot's region from the wiki and from its template, and on any difference emits a `boilerplate` warn whose message ends `restore the region verbatim or update the template if the change is intentional`. Those are the only two remedies the message offers, and neither preserves a per-wiki refinement: the first deletes it, and the second is unavailable to a wiki owner editing their own wiki, since the template ships from this repo and editing it does not reach a wiki that already exists.

The skill already carries the right rule, in the wrong place to win. `<hunk_classification>` in [agents/auto_shaper_wiki.md](../plugins/knowledge_management/agents/auto_shaper_wiki.md) rules that content the wiki has and the canonical lacks is a customization to preserve as-is when it extends the canon without contradicting it, and surfaces it for the user only when it contradicts canonical semantics. An owner's added paragraph inside a locked region is an extension by that test, so the classifier's verdict is preserve. The `boilerplate` finding overrides that verdict, because `<linter_is_truth_for_structure>` makes structural lint output authoritative and the finding's own message names restoring the canonical text as a remedy. Two mechanisms in one skill therefore give opposite instructions on the same hunk, and the one that wins is the one that destroys the owner's work. Note also that `<configurable_zones>` grants `template_log.md` a zone for entries and their bodies while deliberately running the diff on the preamble alone, so the preamble is the single region with no configurable zone and no classifier protection that survives contact with the check.

The agent then acts on that signal. `<scaffold_drift>` in [agents/auto_shaper_wiki.md](../plugins/knowledge_management/agents/auto_shaper_wiki.md) drives comparison from a line-level diff against each canonical template, and `<linter_is_truth_for_structure>` makes the linter's structural output authoritative. Nothing in either instruction distinguishes an owner's deliberate addition inside a locked region from accumulated drift, so the remediation available is to restore the canonical text.

Observed end to end once, in a wiki managed by this skill, and the diagnosis below is a reading of the two instruction blocks named above rather than a ruling by the skill's author: the owner added a paragraph to the `log.md` preamble scoping log entries to changes of the wiki itself, and anchored the same rule in that wiki's `SCHEMA.md` and in the repository's agent instruction files. The next audit read the preamble difference as scaffold drift and deleted the paragraph. The owner caught it mid-run and ordered it restored. Left alone, the audit would have reported a clean run while having removed the rule it was asked to maintain, which is the failure mode this task closes: a silent revert reads afterwards as compliance.

Three sibling tasks bound this one, all live, so compose rather than overwrite:

- [wiki_log-scope-wiki-changes-only.md](wiki_log-scope-wiki-changes-only.md) promotes the rule from the motivating incident into canon, because scoping a log entry to wiki changes turned out to be a general failure mode rather than one wiki's preference — the same drift was corrected by hand in two wikis. That settles what this incident is evidence for: the mechanism gap, not a permanently local refinement. Keep the incident as the evidence and do not present that rule as this mechanism's standing example, since the wiki carrying it as a declaration retires the declaration once canon carries the rule.
- [wiki_lint-accepted-info-suppression.md](wiki_lint-accepted-info-suppression.md) builds the per-finding acceptance store as labeled bullets in the SCHEMA `## Lint` section, parsed fence-safe like the existing `Page-check exclusions:` bullet, and it scopes matching to `SEV_INFO` only, stating that a matching acceptance never suppresses a non-info finding. A `boilerplate` finding is a warn, so that mechanism cannot carry this case, and this task does not widen it to warns. What this task reuses is its storage decision and its parser: another labeled bullet in the same section, registered in the agent's `<configurable_zones>` entry for `template_schema.md` beside the bullets that task and [wiki_page-type-growth-and-anatomy.md](wiki_page-type-growth-and-anatomy.md) register there. Whichever lands later adds its bullet beside the others rather than replacing them.
- [wiki_schema-template-generalization.md](wiki_schema-template-generalization.md) rewrites the same slot set from the other side. Its defect numbered for the attribution paragraph proposes dropping the `SCHEMA.md prelude` lock as compelled rather than offered, while keeping the `log.md preamble` lock because that region is load-bearing format documentation. This task agrees with that split and depends on nothing in it: the lock stays, and the declaration is what makes a locked slot survivable. If that task lands first and one slot is gone, this task's mechanism applies to whichever slots `VERBATIM_SLOTS` still holds, which is why the work below reads the tuple rather than naming a fixed pair.

## Approach

1. **Make the check classify instead of demanding verbatim restoration.** Bring `check_verbatim_boilerplate` into line with `<hunk_classification>`: a locked-slot region that adds to the canonical text without contradicting it is an extension, reported as acknowledged context naming the addition, and never as an instruction to restore. A region that removes or rewrites canonical content still warns, with both remedies named as today. This is the cheap half and it needs no new syntax in any wiki, which is why it leads: the classifier's own test already draws the line this check is missing.

2. **Declare a deliberate contradiction, for the case classification cannot settle.** Add one labeled bullet per deviated slot to the SCHEMA `## Lint` section, carrying the slot's label as `VERBATIM_SLOTS` spells it plus a short reason, and parse it with the same fence-safe reader that handles `Page-check exclusions:` so a documented example inside a fence is not a live setting. The reason field is not machine-read; it exists so the next reader learns why the divergence stands without opening this repo. Document the bullet in [references/template_schema.md](../plugins/knowledge_management/skills/wiki/references/template_schema.md) `## Lint` as a fenced example mirroring the exclusions bullet, and compose with the two sibling tasks at that section per `## Context`.

3. **Honour the declaration in the runner.** In `check_verbatim_boilerplate`, a slot with a matching declaration emits no `boilerplate` warn. Report it instead as acknowledged context naming the slot and the declared reason, so the divergence stays visible without carrying an instruction to undo it, and keep it out of the live warn count. An undeclared divergence is unchanged: same warn, same message, both remedies still named.

4. **Put reverting a declared deviation out of bounds for the agent.** Rewrite `<scaffold_drift>` and its hunk-classification guidance so a hunk inside a declared slot classifies as wiki-owned content and no repair touches it, and state the reason in one clause: reverting an owner's declared refinement destroys a decision the wiki has already recorded, and the audit that does it reports success. Add the same rule to `<linter_is_truth_for_structure>`, which today makes structural lint output authoritative with no exception for a region the wiki has claimed.

5. **Report a divergence worth promoting.** Where the agent judges a declared deviation to be a general improvement rather than a local one, its final report names it as a candidate for the shipped template. That is a report line, not an edit: the agent does not modify the templates in this repo from inside a managed wiki. This closes the other half of the gap, since a refinement that only ever lives in one wiki's declaration is invisible to every other wiki generated from the same template.

6. **Teach the workflow once.** Point [skills/wiki/SKILL.md](../plugins/knowledge_management/skills/wiki/SKILL.md) and [references/lint_checks.md](../plugins/knowledge_management/skills/wiki/references/lint_checks.md) at the declaration as the route for an intentional divergence in a locked slot, and document its boundary against the info-level acceptance store and the directory-level walk exclusion so the three mechanisms do not read as alternatives for one another.

**Open decision:** where the contradiction gets fixed. **Option A, the check classifies** — steps 1 and 3 as written. The wrong remedy disappears at its source, the behaviour is deterministic, and every consumer of the linter inherits it; the cost is changed lint output for every wiki. **Option B, the agent gains an exception** — `<linter_is_truth_for_structure>` learns that a locked-slot extension is the classifier's call. Smaller, touches no shipped script, but the check keeps printing an instruction that is wrong for that case, so the next consumer of that output repeats the mistake. Default without further input: option A, because the misleading instruction originates in the check and an advisory exception elsewhere does not stop it being followed. Acceptance below is written against that default; option B keeps the same fixtures and moves the assertions from the check's output to the agent's behaviour.

**Out of scope:** widening the acceptance store to warn-level findings generally, which stays with [wiki_lint-accepted-info-suppression.md](wiki_lint-accepted-info-suppression.md) and its `SEV_INFO` boundary. Deciding which slots stay locked, which stays with [wiki_schema-template-generalization.md](wiki_schema-template-generalization.md). Propagating a landed template change into wikis that already exist, which rides the scaffold restore path that [wiki_log-scope-wiki-changes-only.md](wiki_log-scope-wiki-changes-only.md) exercises and confirms; here the declaration is only what keeps a refinement alive in the wiki that has it while it is still local.

## Acceptance

- A fixture wiki whose locked-slot region adds a paragraph to the canonical text, with no declaration present, draws no restore-verbatim warn and is reported as an acknowledged extension, proving **Make the check classify instead of demanding verbatim restoration.**
- A fixture wiki whose locked-slot region deletes or rewrites canonical text still draws the warn with both remedies named.
- An `auto_shaper_wiki` run over the extension fixture ends with the added paragraph byte-identical, and the run's report does not claim a scaffold repair it did not make.
- A fixture wiki whose locked-slot region differs from its template, with a matching declaration bullet in its SCHEMA `## Lint` section, draws no `boilerplate` warn and contributes nothing to the live warn count; the run reports the slot as acknowledged with its declared reason.
- The same fixture without the declaration bullet still draws the `boilerplate` warn, and the message still names both the restore-verbatim and update-the-template remedies.
- A declaration bullet that sits only inside a fenced example does not suppress the warn, proving the fence-safe parse.
- A declaration bullet naming a slot label absent from `VERBATIM_SLOTS` suppresses nothing, and the run surfaces the unmatched declaration rather than failing silently.
- A declaration for one slot leaves a genuine divergence in a second locked slot reported normally.
- `template_schema.md` `## Lint` documents the declaration bullet as a fenced example beside the `Page-check exclusions:` bullet, and any already-landed bullets from the two sibling tasks named in `## Context` remain present after this task's rewrite of that section.
- The agent's `<configurable_zones>` entry for `template_schema.md` names the declaration bullet alongside the sibling tasks' bullets, so a scaffold diff reads all of them as wiki-owned rather than as drift.
- `<scaffold_drift>` and `<linter_is_truth_for_structure>` state that a hunk inside a declared slot is wiki-owned and that no repair reverts it, each with the reason attached.
- The agent's reporting instruction requires naming a declared deviation the agent judges generally applicable as a template candidate, and requires leaving this repo's templates unedited from inside a managed wiki.
- `lint_checks.md` documents the declaration and its boundaries against the info-level acceptance store and the `Page-check exclusions:` walk exclusion, with no overlap in what each one suppresses.
- An end-to-end run of the wiki regression harness over a fixture carrying a declared deviation finishes with the deviation's text byte-identical to what it was before the run.
- `tests/wiki/run_all.sh` exercises every fixture scenario named above and passes with them harness-wired.
