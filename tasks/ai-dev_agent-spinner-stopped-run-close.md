# Let a stopped agent_spinner run close cleanly

## Goal

`close --stopped` ends a stopped run. It settles every row still in `pending`, `dispatched`, or `unknown` to a terminal outcome with a recorded reason and exits 0 when no other close condition remains, while a `violation` row or any other open condition still refuses and keeps the run open. Today `TERMINAL` excludes those three states, and `cmd_close` calls `close_open_items` unconditionally, so a run that follows the skill's own stop path stays open forever.

## Context

- The defect lives in `plugins/ai_dev/skills/agent_spinner/scripts/run_ledger.py`: `TERMINAL` lists only `accepted`, `inability`, `failed`, `unreturned`, and `dropped`; `close_open_items` rejects every row outside that set; and `cmd_close` runs it whether or not `--stopped` is set, returning 3.
- The archived [terminal-states task](archive/ai-dev_agent-spinner-ledger-terminal-states.md) fixed the stop report's headings and added `dispose --rows`, but it did not relax the close condition. The skill still documents `stop` then `close --stopped` as the way to end a stopped run, so the code contradicts the documented path.
- The observed effect: runs in four repositories stayed open after a stop; one session deleted the run directory rather than fake a clean close, and another reported success while its run still showed `state: open`.
- The settlement must not turn unverified work into accepted work: an `unreturned` or `dropped` row is a recorded non-result, not a pass.

## Approach

1. In `cmd_close`, when `--stopped` is set, settle and persist before any other close step, in this order. Settle every non-terminal row by state: `pending` becomes `dropped`, `dispatched` becomes `unreturned`, `unknown` becomes `unreturned`, and `violation` stays `violation` and is still refused. Append one `stopped` record per settled row; each record carries `type` (`stopped`), `label`, `from` (the original state), `reason`, `path`, which holds the row's target path and the empty string when the row names no path, `outcome`, which holds the settled terminal state, one of the two terminal outcomes `dropped` and `unreturned`, and `dropped_check`, which holds the label of every existing `check:<slug>` row for that path as a list (the rows `diff --add-checks` writes, `check:` plus the slugified path), empty when the path has none, where a row record fills `label`, `from`, `reason`, and `outcome`, and `reason` takes one of two values, `in-flight at stop` for a `dispatched` or `unknown` row and `never dispatched` for a `pending` row. Refresh the landed change list by recording only the row-attributed landed writes, plus every angle-bracket metadata entry the diff emits, including the aggregate residue entry: run the diff to observe the tree, then write into `run.json`'s `changes` list only each landed path a row recorded, carrying its attribution and merging that change's existing `checks` from the prior list by path so the record preserves them and creates no new pending row. A landed path no row recorded, such as an untracked stray, stays out of the `changes` list so condition 5 still refuses it. For every row-attributed landed path with no accepted check, gate, or taken-on-word disposition, append a `stopped` record naming the path and its `dropped_check`. The settlement's path scope covers only a row-attributed landed write, a path a row recorded, so a landed path no row recorded keeps refusing under condition 5. Record the settlement once: the first `--stopped` call runs the diff refresh and sets a run-level `stopped_settled` flag before evaluating conditions, and a run carrying that flag reuses its recorded changes and appends no second `diff` or `stopped` record. The flag trades a fresh change list for idempotency: a path that changes after the first settlement keeps its recorded entry and diff snapshot, so a later `--stopped` call reports the first settlement's tree state for that path rather than re-reading the file. Let `change_covered` accept that record as the path's disposition and `stray_entries` treat the path as known. Then rewrite `report.md`'s tally: replace every `TALLY-BEGIN`…`TALLY-END` region with the settled `tally_block` (the single region in a normal report, and every region when a report carries more than one), insert that block when `report.md` is present but carries no tally region, and create `report.md` carrying that block when it is missing. Then print the settled tally and the five row lists. Source the row lists from the settled state: the `unknown` and `not dispatched` lists print each row's `from` value from its `stopped` record, and the `violation` list prints the live row's `violation` state, because a violation row is never settled and has no `stopped` record. Condition 7 then compares the settled tally against a `report.md` that already carries it, and condition 1 sees only the settled rows and the violation rows.
2. The exit contract, stated once here: `close --stopped` exits 0 when settlement leaves only terminal rows and every remaining close condition holds, and exits 3 when a violation row or any other close condition remains. A refused `close --stopped` keeps the settlement it made, with the rows left terminal, their `stopped` records written, and the tally region rewritten.
3. Relax condition 1 only, and rewrite condition 1 in the `### close` entry of `references/run-protocol.md` to carry the `--stopped` exception. Every other close condition still refuses, so a run stopped with an unanswered gate or fork still refuses with its `condition 6` line, which the existing `ledger_run.sh` scenario already pins. Leave `accepted`, `failed`, and `inability` rows untouched.
4. Make the settlement idempotent: a second `close --stopped` on a closed run reaches the same exit contract, prints the same tally block, appends no record, and leaves each settled row carrying exactly one `stopped` record.
5. Rewrite in place the passages that state the close outcome: the `### close` entry in `references/run-protocol.md`, its `close --stopped` sentence, and the `<run_state>` passage in `SKILL.md`, so each states the settlement, the two terminal outcomes, the `violation` exception, and that `close --stopped` now writes `report.md` before printing the settled tally; and rewrite the `<coverage_tradeoff>` passage in `SKILL.md`, whose sentence reads ``a row left unrun is dropped by a named narrowing through `dispose`, with its reason``, so it names both drop paths, `dispose --rows` for a deliberate narrowing and `close --stopped` for a stopped run's `pending` rows, each with its recorded reason; and in `references/report-shapes.md` the `## Stop report` passage whose line reads `non-terminal it prints them and refuses, exiting non-zero` and the stop-report example whose opening line reads `Stopped after 2 of 4 writers,`, so both state the settlement and the exit 0 it now allows instead of the refusal the section still records for pending rows. In the same edit, update the `tests/agent_spinner/script_tests/run.sh` fixture that pins the stop-report example's opening sentence: in `stop_template_first_sentence_facts`'s negative control, update the `old` and `new` strings together, so `old` carries the rewritten example's opening sentence verbatim (currently ``2 returned, and `close --stopped` exited 3``) and `new` carries that same text with the exit clause split into a second sentence (currently ``2 returned. `close --stopped` exited 3``), keeping the control mutating the shipped text instead of raising `stop template sentence not found`.
6. Extend `tests/agent_spinner/script_tests/ledger_run.sh` with scenarios covering the settled rows (a dispatched row, a pending row, an `unknown` row, and a violation row), a stopped run that landed a change, a stopped run holding an `accepted` check on that landed path, a stopped run whose `report.md` is present with no tally region, and a stopped run with no `report.md`. Register each new `scenario_*` function by name in `run_all_scenarios`, which calls every scenario explicitly and discovers none, passing it its own scratch subdirectory under `$root`.

**Out of scope:** changing what `dispose --rows` does; that verb already records an explicit drop and stays the path for a deliberate narrowing.

## Acceptance

- The new `ledger_run.sh` scenario stages a run holding a dispatched row, a pending row, and an `unknown` row and no violation row. `close --stopped` exits 0, the dispatched and `unknown` rows end `unreturned`, the pending row ends `dropped`, and each settled row carries one `stopped` record with its original state in `from`, its `reason` (`in-flight at stop` or `never dispatched`), and its `outcome`.
- A second staged run in the same scenario holds a violation row: `close --stopped` exits 3, names condition 1 for that row, and leaves the run open. The refused call keeps the settlement it made: every other non-terminal row in that run ends terminal with its `stopped` record, the violation row keeps state `violation` with no `stopped` record, and `report.md` carries exactly one tally region equal to the settled tally block the refused call printed.
- The scenario asserts that the printed `unknown` and `not dispatched` lists show each settled row's pre-settlement state from its `stopped` record's `from`, and that the printed `violation` list shows the live violation row's `violation` state.
- The scenario stages `report.md` with a tally region carrying a sentinel line; after `close --stopped`, `grep -c '^TALLY-BEGIN$' .agent_spinner/report.md` is 1, the sentinel pre-settlement block text is absent, and the single region equals the tally block the command printed.
- A third staged run has no `report.md`: `close --stopped` exits 0 and creates `report.md` carrying exactly one tally region equal to the settled tally block the command printed.
- A fourth staged run lands a file change that a row records before the stop and already holds a `check:<slug>` row for that path: `close --stopped` exits 0, the path appears in the modified list, a `stopped` record names the path, its `dropped_check` is a non-empty list holding that `check:<slug>` row's label, and the close reports no condition 3 or condition 5 entry for it, because the settlement covers this row-attributed write.
- `bash tests/agent_spinner/script_tests/ledger_run.sh` still reports `condition 6 refuses an unanswered surfaced fork with exit 3` and `close --stopped still refuses the unanswered surfaced fork and lists it`, proving `--stopped` relaxed condition 1 alone.
- On the first staged run from Acceptance item 1, a second `close --stopped` exits 0, prints the same tally block, and leaves the settlement's records unchanged: each settled row carries exactly one `stopped` record, and `ledger.jsonl`'s line count after the second call equals its line count after the first, proving the settlement is idempotent rather than only its tally.
- `rg -n "close --stopped" plugins/ai_dev/skills/agent_spinner/` finds text that names the settlement and the violation exception, no passage still promises a clean close without them, and no passage still states that `close --stopped` refuses while rows are `pending`, `dispatched`, or `unknown`. Read the three sites that grep cannot see directly. In `references/run-protocol.md`, the condition-1 line in the `### close` entry names the `--stopped` exception, and the old unqualified line is absent: `rg -nF "A row is not terminal." references/run-protocol.md` returns nothing. In `references/report-shapes.md`, the `## Stop report` prose states the settlement and the exit 0 it now allows, and the old refusal clause is absent: `rg -nF "non-terminal it prints them and refuses, exiting non-zero" references/report-shapes.md` returns nothing. In `SKILL.md`, the `<coverage_tradeoff>` passage names both drop paths on one line, and the old single-path clause is absent: `awk '/^<coverage_tradeoff>$/{f=1;next} /^<\/coverage_tradeoff>$/{f=0} f' plugins/ai_dev/skills/agent_spinner/SKILL.md | rg "close --stopped" | grep -qF "dispose --rows"` succeeds, and ``rg -nF 'narrowing through `dispose`, with its reason' plugins/ai_dev/skills/agent_spinner/SKILL.md`` returns nothing.
- `bash tests/agent_spinner/script_tests/ledger_run.sh` passes, including every pre-existing scenario, among them `scenario_stopped_row_lists`, which keeps passing unchanged.
- `bash tests/agent_spinner/script_tests/run.sh` passes, including every pre-existing check, and the `stop_template_first_sentence_facts` negative control still mutates the rewritten example's opening sentence instead of raising `stop template sentence not found`.
- `scenario_close_conditions` extends its `close --stopped lists modified paths with exit 3` case beyond the `modified:` grep and the exit code: it asserts that `stray.txt` is absent from `run.json`'s `changes` list and that the close output carries a `condition 5` line naming `stray.txt`, so the untracked stray still refuses under condition 5 because the settlement covers only row-attributed landed writes.

- A staged run lands a file change that a row records and holds an `accepted` check row on that path: `close --stopped` exits 0, appends no `stopped` record for the path, leaves the accepted row's state unchanged, preserves the change's recorded `checks` through the refresh with no new pending row, and reports no condition 3 entry.
- A staged run holds `accepted`, `failed`, and `inability` rows: `close --stopped` exits 0 and leaves each of those rows' state and records unchanged, adding no `stopped` record for any of them.
