# Mechanize the log-preamble merge with a bundled convergent, never-corrupt script

## Goal

The wiki skill ships a bundled script that reconciles a wiki's `log.md` preamble against the canonical template, and the `auto_shaper_wiki` move `<fix_log_preamble_drift>` runs that script instead of hand-editing the region. The script is better than the hand edit on every input it accepts, not only on the one the hand edit loses. It converges each canonical unit to current template text, it preserves an owner-added line by construction, and it never leaves two copies of one canonical rule behind. Classification runs off declared unit identities rather than a judgement re-made per run, so the outcome does not vary between runs.

The net effect, stated against the real distribution of how a preamble drifts: the common cases converge correctly with owner lines intact, and the single input the script declines is a genuinely ambiguous one that the hand edit only ever guessed at. On that input the script refuses loudly and writes nothing, rather than corrupting the file. So the change removes the measured owner-line deletion without introducing a quieter failure to replace it: the failure it cannot auto-resolve is rare, is undecidable in principle from the file alone, and surfaces as a visible finding rather than as silent damage.

This task re-homes the one open acceptance residue of [wiki_log-scope-wiki-changes-only.md](archive/wiki_log-scope-wiki-changes-only.md): the owner-line preservation that task demands from the hand-edited move holds only stochastically, and further instruction wording measurably does not change that. The preamble behaviours move from sampled Layer 2 agent runs into deterministic Layer 1 unit tests, and Layer 2 keeps one job for this move, confirming the agent routes remediation through the script.

## Context

`<fix_log_preamble_drift>` in [auto_shaper_wiki.md](../plugins/knowledge_management/agents/auto_shaper_wiki.md) prescribes the merge as a hand edit today: insert an absent canonical unit, refresh a drifted unit by its label or its greppable stem, and leave every wiki-only line alone. The agent re-derives the unit matching from prose on every run. Measured on 2026-08-22 across repeated Layer 2 preamble scenario runs (recorded under `tests/wiki/layer2/workspace/run-20260822-*`), roughly one pass in ten wholesale-restores the region and deletes the owner's line. Three contradiction removals in the same agent file, shipped since, left the aggregate pass rate unchanged at 92% before and 90% after. Every failing pass reasons the same way: the preamble should equal the template, so it rewrites the whole region. The gap is not wording. Deletion is available to a judgement call, and the judgement is sampled.

A naive script closes that hole and opens another, and this task exists to close both. Match each live line to a canonical unit by exact label or stem, refresh on a hit, treat a miss as an owner line: that rule loses nothing, but it manufactures a different defect. When a canonical unit has drifted past its own anchor — its label or stem reworded, not just its body — the live line matches nothing, so the script preserves it as an owner line and also inserts a fresh canonical copy at the same position. The preamble then states one canonical rule twice, once current and once stale. That is an intra-file contradiction, the defect class the project treats as first-class precisely because it reads as fine on the page and needs measurement to catch. A `boilerplate` warn is raised either way, so the stale copy is indistinguishable from a legitimate owner extension. Trading a visible deletion for a laundered contradiction is not an improvement, so the design below removes the guesswork that produces it rather than detecting the wreck afterward.

The move that makes the script better as a whole is to give each canonical unit a declared identity the script owns, so classification stops being inference. Read against how a preamble actually drifts, the cases separate cleanly:

- **Template body reworded here, anchor kept.** This is the bulk of real drift: a wording change shipped in this repo leaves every downstream wiki one version behind. The live line still carries the canonical anchor, so it matches and refreshes to current text. Owner lines are untouched. The hand edit does this too, but also risks the deletion.
- **Owner added a line, canonical units intact.** The measured failure case. Every canonical unit matches and refreshes; the added line matches nothing and is preserved. No deletion, no duplicate.
- **Canonical anchor reworded here.** A rename shipped from this repo would leave every downstream wiki's prior anchor unmatched at once. The script's declared identity carries prior anchors as aliases, so the old form still matches and refreshes. The rename ships with its alias in the same change, or our own template-parse validation fails before it ever reaches a wiki.
- **Owner locally reworded a canonical rule's anchor.** Rare, and genuinely undecidable from the file alone: the script cannot tell a heavily-reworded canonical unit from a new owner line that happens to resemble one. Here, and only here, the near-duplicate guard refuses: it declines to insert-and-preserve, writes nothing, and names the unit for a human. The hand edit's behaviour on this same input is to guess, which is where the deletions and duplications both came from, so a loud refusal dominates it.

Across that distribution the script converges correctly and preserves owner content on every common case, and the one case it cannot settle it surfaces instead of damaging. The principled way to auto-resolve even the last case is a stored-base three-way merge — record the template version a wiki last synced to, then merge the repo's change and the owner's change against that base — which removes the inference entirely. That needs a per-wiki base marker that legacy wikis do not carry, so it is named as the forward path rather than built here; the declared-identity design is what makes the residual rare enough that its absence is acceptable.

Derive the unit set from the template at implementation time rather than from a list frozen here, because sibling tasks edit the template. The preamble region is the H1 prelude of [template_log.md](../plugins/knowledge_management/skills/wiki/references/template_log.md), the same region the linter's `extract_h1_prelude` in [lint.py](../plugins/knowledge_management/skills/wiki/scripts/lint.py) extracts. Its units are the labeled `> Label:` blockquote groups, each absorbing its soft-wrapped continuation lines, plus the unlabeled blockquote units. As of this writing that yields the labeled groups `Format:`, `Actions:`, `Entries:`, `Repair:`, `Scope:`, and `Body:`, plus two unlabeled units, the `Chronological record` opener and the `When this file exceeds 500 entries` rotation rule; treat that enumeration as an illustration, not the contract.

The script follows the skill's existing bundled-script conventions: it lives in `skills/wiki/scripts/` beside `lint.py`, `init_wiki.sh`, `discover_wiki.sh`, and `compute_sha256.py`, and the agent invokes it through the resolved `$WIKI_SKILL` bundle path exactly like its existing `python3 "$WIKI_SKILL/scripts/lint.py"` calls.

Two sibling tasks bound this one:

- [wiki_log-scope-wiki-changes-only.md](archive/wiki_log-scope-wiki-changes-only.md) shipped the unit-scoped move; its acceptance defines the insert-missing, refresh-by-label, refresh-by-stem, and owner-line-preservation semantics this task mechanizes, and its measured residue is the motivation above.
- [wiki_sanctioned-template-deviations.md](wiki_sanctioned-template-deviations.md) owns the linter side: the `check_verbatim_boilerplate` classification, the acknowledged report channel, and declared contradictions. Once it lands, an insert-only owner extension stops warning at all, which removes most occasions for this merge to run; the script stays the remediation for a preamble whose canonical units actually drifted. The two tasks ship in either order, with two named touch points. Both edit `<fix_log_preamble_drift>`'s closing paragraph about a surviving owner-line `boilerplate` warn. And that sibling's declare-and-honour path gates what any repair may touch: a declared or acknowledged region stays untouched whichever mechanism performs the repair, so once both tasks are in, the agent checks declarations before invoking the script, or the invocation skips declared slots. Whichever task lands second reconciles both points against the text the first left behind.

## Approach

1. **Declare canonical unit identity in the script.** Give the script a single table of the canonical units, each entry carrying a stable id, its current match anchor, and a list of prior anchors (aliases), empty until a rename happens. A labeled unit's anchor is its `> Label:` token; an unlabeled unit's anchor is a committed stem string (`Chronological record`, `When this file exceeds`). This table is the one place identity is decided, so a live line is canonical exactly when it resolves to an entry through the entry's current anchor or one of its aliases, and every other classification rule reads from here rather than re-deciding.

2. **Build `merge_log_preamble.py` and validate its own inputs.** Place it in `plugins/knowledge_management/skills/wiki/scripts/`. It takes the path to a wiki's `log.md` and resolves the template relative to its own directory (`../references/template_log.md`). Import the region extraction from the adjacent `lint.py` (`extract_h1_prelude`) so the script and the linter cannot disagree about what the preamble is. Parse the template region into ordered units, and validate the parse against the identity table before using it: every template unit resolves to exactly one table entry through that entry's current anchor, every table entry's current anchor appears exactly once in the template, and re-serializing the parsed units reproduces the template region byte-identically. On any mismatch exit non-zero and write nothing. This is what makes a template edit here that renames or drops an anchor without updating the table fail in this repo's own tests, before it can reach a wiki.

3. **Classify and merge, with no delete branch.** Parse the live preamble the same way. Classify each live unit by resolving its anchor through the identity table, current anchors first, then aliases. Walk the template's units in table order and, for each: refresh in place when a live unit resolves to it, or insert it at its canonical position when none does. Every live line that resolves to no table entry is an owner line and passes through unchanged at its position. Everything from the first `##` heading onward is copied byte-identical. The program has no operation that removes a line, so owner content survives whatever the classification does.

4. **Guard the one ambiguous case loudly.** Before inserting a canonical unit that no live unit matched, test the unmatched live lines for a high-similarity near-match to that unit's canonical text. On a near-match, do not insert and do not silently keep both: exit non-zero, write nothing, and name the unit as an ambiguous local rewrite needing a human. This guard fires only when a canonical unit is both missing and resembled by an owner line, which is the genuine "did the owner rewrite this rule or add a similar one?" case, so it stays a rare safety net rather than the primary path. Pick the similarity measure and threshold so a clearly distinct owner line does not trip it; record the threshold in the script.

5. **Self-check the result, then write.** After a clean merge, assert every table entry appears exactly once at current template text and every unmatched-live owner line is present unchanged and in order; on any violation exit non-zero and write nothing. A run over an already-converged file makes no change and exits 0. A non-zero exit always names the offending unit.

6. **Route the fix move through the script.** Supersede the hand-edit recipe inside `<fix_log_preamble_drift>` in place, so the move runs the script via `$WIKI_SKILL`, keeps its confirm-by-re-reading step, and on a non-zero exit surfaces the script's message as a finding for the user rather than falling back to hand-editing the units. Restate the never-delete and no-duplicate rules as properties the script guarantees rather than instructions the agent must obey, and keep the move's insert, refresh, and preserve vocabulary so `<lint_already_covers_prelude>`'s pointer at this move stays true. Keep the closing surviving-warn paragraph as the sibling-owned wording described in Context.

7. **Prove the behaviours in Layer 1.** Add fixture-based unit tests under `tests/wiki/layer1`, wired into the default `tests/wiki/run_all.sh` run, one per distribution case and per guard: insert a missing labeled unit; refresh a drifted labeled unit; refresh a drifted unlabeled unit; refresh a unit whose live anchor is a prior alias, proving the rename path converges without leaving a duplicate; owner-line preservation asserted as an invariant across every fixture; the ambiguous near-match case failing loud with nothing written; a duplicated canonical unit and a table-rejecting template both failing loud; idempotence; and entries below the preamble left byte-identical.

8. **Shrink Layer 2 to routing.** Extend the recorded grading of the Layer 2 scenarios that exercise `<fix_log_preamble_drift>` so each pass records the remediation mechanism observed, script or hand edit, then run the measurement in Acceptance.

**Out of scope:** The linter's classification of preamble mismatches, the `boilerplate` warn message, and the acknowledged or declared channels, owned by [wiki_sanctioned-template-deviations.md](wiki_sanctioned-template-deviations.md). The stored-base three-way merge that would auto-resolve the ambiguous local-rewrite case, which needs a per-wiki base marker this task does not add and is named here as the forward path. Relabeling the template's unlabeled units to make every unit label-matched, which changes the rendered preamble and is not needed once identity is declared. A lint auto-fix mode that runs this merge from inside `lint.py`, since remediation stays an agent move the linter only reports on. Any delete or reconcile branch for owner lines, since removing the delete operation is the property this task ships.

## Acceptance

- Running `merge_log_preamble.py` on a fixture `log.md` whose preamble lacks one canonical labeled group inserts that group byte-identical from the template at its canonical position, with every other line unchanged.
- Running it on a fixture whose preamble carries a drifted labeled unit rewrites that unit to current template text in place; running it on a fixture whose preamble carries a drifted unlabeled unit does the same through that unit's declared stem.
- Running it on a fixture whose preamble carries a canonical unit under a prior alias (the anchor renamed in the template, the alias recorded in the identity table) refreshes that one unit to current template text and leaves exactly one copy of it, proving the rename path converges without inserting a stale duplicate.
- Across every fixture in the new test set, every input preamble line that resolves to no table entry appears in the output byte-identical, and everything from the first `##` heading onward is byte-identical, proving owner-line preservation as an invariant rather than a sampled behaviour.
- On a fixture whose preamble is missing a canonical unit and carries an owner line that is a high-similarity near-match to that unit, the script exits non-zero, writes nothing, and names the unit as an ambiguous local rewrite; on a fixture whose owner line is clearly distinct from every missing unit, the same run inserts the unit and preserves the owner line without tripping the guard.
- On a fixture whose live preamble carries a duplicated canonical unit, and on a template region the parse validation rejects, the script exits non-zero, writes nothing, and names the offending unit.
- Running the script twice in a row on the same file leaves the second run reporting no change with exit 0.
- The hand-edit recipe inside `<fix_log_preamble_drift>` is superseded in place: the move invokes the script through `$WIKI_SKILL`, directs a non-zero exit to be surfaced as a finding, states the never-delete and no-duplicate properties as guarantees of the script, and no passage still instructs editing individual units by hand; the closing surviving-warn paragraph remains.
- The default `tests/wiki/run_all.sh` Layer 1 run passes with the new script tests included.
- Measured, with a fail branch: re-run the Layer 2 scenarios that exercise `<fix_log_preamble_drift>` (per their scenario definitions under `tests/wiki/layer2`) at 4 passes each, matching the strongest 2026-08-22 baseline run, and record the benchmark with each pass's remediation mechanism. The recorded benchmark is the deliverable. The hypothesis: every pass routes remediation through the script and ends with the owner's line byte-identical and no duplicated canonical unit. On a failing pass, classify it: a script defect is a gap in this task and blocks completion; a bypass where the agent hand-edited despite the routed move is recorded with that pass's reasoning in the run record and surfaced to the user for disposition rather than silently accepted.
