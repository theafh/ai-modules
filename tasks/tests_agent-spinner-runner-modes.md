# Runner modes for the agent_spinner evals, the same on Claude and Cursor: a resumed second turn, an inline skill body, staged agents, CLI-withheld shell and writes with declared-absence spawn, a tool-call record, and the parity rule

## Goal

`tests/agent_spinner/evals/run.py` is the vendor-aware runner for agent_spinner's behavioural evals. It runs each eval as one turn of a vendor CLI in print mode, the CLI's non-interactive `-p` mode, on Claude or on Cursor. The evals that coming agent_spinner tasks add need three modes the runner lacks. After this task it offers all three, on both vendors it drives:

- An eval can send a second turn that resumes the first turn's session through the vendor CLI's own resume path, with a fixture step between the turns.
- An eval can hand the worker the skill body inline, the way a host's manual attachment does, in place of a path to read.
- An eval can stage named agent definitions, a plugin role or a fixture's mock agent, where the worker's host discovers them.

Today the runner also withholds tools unevenly. On Claude it passes `--disallowedTools`, which removes the tool. On Cursor it only appends a note to the prompt, and the tool stays callable. After this task every eval runs and grades the same way on Claude and Cursor, so the suite proves agent_spinner on Cursor as fully as on Claude Code. Shell and write are withheld by cli-flag on Claude and cli-config on Cursor; spawn by declared-absence on both. The withheld-tool rule under Approach holds that table once. The runner records which mechanism applied.

Each runner mode proves itself with a smoke eval that passes on the default vendor, Cursor, and the plumbing test proves each mode's Claude command with a stub worker. A smoke eval is a small eval that tests the runner itself rather than agent_spinner. A smoke eval whose verdict turns on a tool call grades that call from a vendor-neutral record of each vendor's stream, the tool-call record. TESTING.md states the parity rule every harness follows, and the operator guides, `tests/CLAUDE.md` and `tests/AGENTS.md`, cite it. The parity rule says an eval runs and grades the same way on Claude and Cursor, and a harness is vendor-specific only when it tests a vendor-specific feature, which it names. It sits beside TESTING.md's default-vendor rule: evals run without `--vendor` on Cursor, an eval that needs a Claude-specific feature runs with `--vendor claude`, and any other Claude run waits for the operator's request.

## Approach

### Harness keys

Each eval opts into a mode through its `harness` block, and an absent key leaves that mode off.

| Key | Value | Effect |
| --- | --- | --- |
| `inline_body` | `true` | The first turn carries the deployed skill body inline, in place of the path-read steps. |
| `second_turn` | `{"prompt": "...", "between": "fixtures/<id>/between_turns.sh"}` | After the first turn the runner runs the optional `between` script, a path relative to the evals directory, then sends `prompt` as a second turn through the resume path. |
| `agents` | repository-relative paths | Each file is staged as a discoverable agent definition before the first turn. A fixture's mock agent lives under `fixtures/<id>/agents/`. |
| `disallowed_tools` | tool classes: `spawn`, `shell`, `write` | Each class is withheld under the withheld-tool rule. |
| `needs_real_absence` | `true` | The eval's expected behaviour rests on a withheld tool being truly absent, and the runner reports a run where that absence is only declared. |
| `tool_record` | `true` | Every turn streams its events, and the runner writes the tool calls they show to `tool_calls.jsonl` beside `response.txt`. |

### Withheld-tool rule

This rule governs the worker's tools in every eval whose `disallowed_tools` names a class, on both vendors alike. A class is a group of tools that the runner withholds together. `tests/lib/vendor.py` holds the rule's table, one row per class:

| Class | Claude tool names | Cursor stream kind | Claude route | Cursor route | `withheld_by` |
| --- | --- | --- | --- | --- | --- |
| `spawn` | `Agent`, `Task`, `Workflow` | `taskToolCall` | the declared-absence note | the declared-absence note | `declared-absence` on both |
| `shell` | `Bash` | `shellToolCall` | `--disallowedTools Bash` | the deny entry `Shell(*)` | `cli-flag` on Claude, `cli-config` on Cursor |
| `write` | `Edit`, `Write`, `NotebookEdit` | `editToolCall` | `--disallowedTools Edit,Write,NotebookEdit` | the deny entry `Write(**)` | `cli-flag` on Claude, `cli-config` on Cursor |

The `withheld_by` value names the mechanism: `cli-flag` for a command-line flag, `cli-config` for the CLI's project config file, and `declared-absence` for the prompt note.

- **CLI withholding.** Every Claude turn passes the `--disallowedTools` names of each withheld `shell` or `write` class. On Cursor, the runner writes each such class's deny entry into the eval's own `proj/.cursor/cli.json`, as `{"permissions": {"allow": [], "deny": [...]}}`. `run_one` launches the worker with both its working directory and `--workspace` at `proj/`. `seal` makes `proj/` a git repository, so the CLI's project-level lookup finds the file. Every turn keeps the runner's `--force` and `--sandbox disabled` flags. Both routes held inside spawned helpers, so a helper carries no withheld class back into the run.
- **Declared absence.** No Cursor deny entry withholds the spawn tool, so the `spawn` class is a declared absence on both vendors alike. Every eval that withholds it carries one note in its prompt, kept as a constant beside `WORKER_PROMPT`. The eval passes no flag or deny entry for the class, so it runs identically on both vendors.
- **No read-only session mode.** The runner withholds by class and runs no vendor session mode in its place. Neither vendor's plan or ask mode keeps the run read-only here, as the Context bullet **Withholding, observed in a probe run on 2026-10-04** records.
- **Staged roles.** The table governs the worker's own tools. A role that an eval stages lacks its classes through its own lever instead, which `stage_agents` renders per vendor: Claude's `tools:` allowlist or Cursor's `readonly: true`, both of which held in print mode. `stage_agents` keeps the body unchanged. The body's prompt-level prohibition then reaches the role in the same words on both vendors. harness_portability's rule beginning "Enforce a read-only agent role with each harness's own native lever" pairs that prohibition with every lever.
- **Values.** Rewrite every `disallowed_tools` value in `evals.json` from its Claude tool name to its class, so `Task` becomes `spawn`. A value outside the class set stops the run before staging, with a message naming the eval.
- **Grading.** `grade.sh` and every verdict take no vendor input, so grading stays identical on both vendors. The one exception is an eval whose signal row, its row in the `## Signal per eval` table, names a vendor-specific feature. That eval's `grade.sh` case reads the vendor from the `EVAL_VENDOR` variable the runner exports to it, the way task_create's runner exports `RESPONSE_FILE`. `withheld_by` is recorded and printed, never graded. The progress and verdict lines name each withheld class with its `withheld_by` value. For an eval marked `needs_real_absence` with a `declared-absence` class, the verdict line adds that the absence rests on the prompt declaration. That line reads the same on both vendors, and the run summary lists those evals together.

### Vendor layer: `tests/lib/vendor.py`

- **Sessions.** Have `build_print_cmd` support an optional session id and a resume turn beside its existing `output_format` keyword, which already passes `--output-format stream-json` on both vendors and adds `--verbose` on Claude. Leave the exact keyword signature open so long as those capabilities hold and every current caller still builds the same command when they are unused.
  - A Claude first turn passes `--session-id <id>` with a fresh UUID the runner chose, and each later turn passes `--resume <id>`.
  - A Cursor first turn passes no session flag, and each later turn passes `--resume <id>` with the `session_id` the first turn's stream carried.
  - Each turn repeats the vendor's permission, workspace, model, and extra arguments, since every turn is its own CLI call.
- **Agent staging.** Extend `vendor.stage_agents(workdir, vendor, agent_files)`, which today copies each file verbatim into `<workdir>/.claude/agents/` or `<workdir>/.cursor/agents/`, so it renders each file's frontmatter by the `rewrite_agent_frontmatter` rule for that vendor, with the body unchanged. Port that rule into Python beside the other vendor helpers (same keep-unprefixed / strip-own-prefix / drop-other-prefix semantics as `deployment/deployment.sh`), rather than shelling out. `stage_skill_tree` already routes its `agent_files` argument through `stage_agents`, so the module keeps one staging rule. `stage_agents` serves fixture agents; a plugin role that `discover_artifacts` names joins the pass's micro-deployment instead, whose deploy-script run renders it. No runner passes `agent_files` today, so only its unit test sees the change.
- **Withholding.** Add the table the withheld-tool rule describes. Add a helper that returns, for a vendor and a list of classes, the extra CLI arguments, the deny entries to stage, the classes to declare, and the `withheld_by` record. Add a helper that writes deny entries into a workdir's `.cursor/cli.json`.
- **Stream parser.** Extend `parse_stream_json` in `tests/lib/micro_deploy.py`, which today turns one turn's `stream-json` output into its final message, its `session_id`, and per-call records that `paths_from_tools` reads, so its records become the vendor-neutral records below, and keep `paths_from_tools` and the read-provenance check working on them. It reads the shapes in the Context bullet **Streams and resume, observed in the same probe run**.
  - Each tool call yields one record. The record holds the call's class from the table, or `other`, and the tool name as the stream records it: Claude's `name`, or Cursor's tool-kind key such as `createGoalToolCall`. It also holds the helper name or path the call names, its input and result text, and whether it failed.
  - A Claude call pairs a `tool_use` block with the `tool_result` block whose `tool_use_id` matches its `id`. It fails when `is_error` is true, and it carries the `parent_tool_use_id` that marks a helper's call.
  - A Cursor call is its `completed` record. The single tool-kind key gives the class, `args` the input, and `result` the outcome. The call fails when that `result` holds anything but `success`.
  - A spawn record names the helper from Claude's `subagent_type` input or Cursor's `subagentType` value. The final message is the closing `result` record's `result` field on both vendors.
  - Claude's `init` record yields one more record, naming the classes on its tool list. A Cursor stream yields none, since its `init` lists no tools.
- **Helper calls.** A Claude parent's stream carries its helpers' tool calls, while a Cursor parent's stream carries only each helper's final text. An eval that needs a helper's own calls therefore asserts filesystem facts or reads the helper's own transcript.
- **Unit tests.** `tests/lib/test_vendor.py` gains the first-turn and resumed-turn command for each vendor. It gains a staging case whose file carries one unprefixed key plus `CLAUDE_`, `CURSOR_`, and `CODEX_` keys, and the withholding cases Acceptance names. `tests/lib/test_micro_deploy.py` gains the parser cases.

### Runner: `tests/agent_spinner/evals/run.py`

- **Inline body.** Read the deployed `SKILL.md` the pass's path map names, drop its YAML frontmatter, and open the first turn with an attachment block. The block holds, in order, a note, a line naming the deployed file's absolute path, and the body. The note is kept as a constant beside `WORKER_PROMPT`. It says the user attached the file below and other files need reading only if the task needs them. The harness steps follow, without the two steps that say to read the skill file and its `references/`. What remains is the governing-skill line when `extra_reads` names one, the state-path step, and the request. The governing-skill line names a skill that governs the request, and the state-path step says where to keep the run's state.
- **Second turn.** Choose the Claude session id before the first turn. Run the first turn, then run the `between` script with `sandbox_target` then `sandbox_proj` as its arguments, in that order. Then send the second prompt verbatim through the resume path. Every turn runs through `micro_deploy.run_worker`, which requests `stream-json` on both vendors. The runner thus reads Cursor's session id from the first turn's stream, and takes each turn's final message from its stream. Both turns run from the sandbox, each under the eval's timeout. Write the first turn's final message to `response_turn1.txt` and the last turn's to `response.txt`, which `grade.sh` keeps reading. The eval completes only when every turn completes, and a failed first turn sends no second. Both turns run inside the pass's one micro-deployment, so the Claude session the first turn stores under the scratch `CLAUDE_CONFIG_DIR` is still there for the resume, the scratch home goes away only after the last turn, and `artefacts_read_from_micro_deployment` covers both turns' reads.
- **Tool record.** For an eval with `tool_record`, the runner keeps each turn's records from its `stream-json` output. The runner writes each turn's final message wherever it wrote that turn's text output. It writes every turn's records, tagged by turn, to `tool_calls.jsonl` beside `response.txt`. `grade.sh` reads that file and never a stream, so grading stays vendor-free.
- **Resume pre-flight.** Before the first two-turn eval of a run, prove the vendor's resume path once, from a scratch directory under the run directory. Shape the check like `micro_deploy.preflight_auth`, the existing live call that confirms the worker can sign in, and run both of its turns inside one micro-deployment environment, so the resume is proven where the evals run. The first turn hands the worker a random token, and the resumed turn asks for it back. The pre-flight passes when the second reply carries the token. It guards each run against a resume path that stops working. When it fails, every two-turn eval of the run fails with a message naming the failed pre-flight and the vendor, and the other evals run as usual.
- **Staged files.** After `stage.sh` returns, add each listed plugin role to the pass's micro-deploy declaration, and once the micro-deployment returns, stage each listed fixture agent into `proj/` through `stage_agents`. On Cursor, also stage the deny entries the withheld-tool rule calls for. Then re-run `seal` from `fixtures/_common.sh` on the sandbox, so the staged files, and any file the micro-deployment wrote into `proj/` such as a Cursor role under `proj/.cursor/agents/`, are committed and recorded in both inventories. A run that edits, adds, or removes a staged file then fails `tree_unchanged`, and the sandbox repository starts with a clean status. The declaration already feeds `source_roots_for`; add each fixture agent's parent directory to it too, so an edit to a staged agent moves the cache key as an `extra_reads` edit does.
- **Withheld tools.** `run_one` holds a branch that turns `disallowed_tools` into `--disallowedTools` on Claude and an appended "Environment note" on Cursor. Replace that branch with the withheld-tool rule. Keep `prompt_before_flags=bool(extra_args)` when `extra_args` carries Claude's `--disallowedTools` list.
- **Cache key.** The verdict cache replays a recorded verdict instead of re-running an eval whose cache key is unchanged. Work out the withholding before the cache lookup, and fold its result into the key. Append each withheld class with its mechanism and its flag or deny entry to the prompt value `run_one` passes to `content_key`. A `smoke_*` eval's key also folds in the worker CLI's version, read once per run from `<bin> --version`, so a new build re-runs every smoke eval. On a cache hit, add `withheld_by` to the replayed `timing.json`. The CACHED line then carries the withheld classes and the declared-absence note a fresh verdict line would. A cached eval marked `needs_real_absence` with a `declared-absence` class joins the run summary's list.
- **Records.** `timing.json` keeps `worker_rc` and `claude_rc` for the last turn that ran. It adds each turn's exit status and duration, the modes the eval used, the staged agent names, and `withheld_by`.
- **Docstring.** Rewrite the module docstring's paragraphs on the no-delegation fixture and on Cursor's missing flag into one account of withheld tools under the withheld-tool rule, and describe the three modes.

### Smoke evals

Each runner mode proves itself with a smoke eval that passes once on each vendor, and the tool record proves itself through the smoke evals that set it. Add each one to `evals.json` with a fixture under `fixtures/<id>/` and a `grade.sh` case. The case asserts a file in `proj/`, plus the tool record where the eval sets `tool_record`:

- `smoke_inline_body` runs in inline-body mode. It asks the worker to write into `smoke.txt` the first non-blank line of the attached text as it received it. The attached body starts after the frontmatter, while the staged file it names starts with `---`. A run that read the file in place of the attachment therefore writes a different line. `grade.sh` derives the expected line at grade time, from the skill's `SKILL.md` with its frontmatter removed.
- `smoke_second_turn` hands the worker a token in its first prompt, and its `between` script writes a second token into `proj/`. The second prompt asks for both tokens in `smoke.txt`. `grade.sh` asserts both tokens and both response files.
- `smoke_staged_agent` sets `tool_record` and stages a mock agent from `fixtures/smoke_staged_agent/agents/` whose body replies with a fixed token. The request asks the worker to spawn that agent by name once and write its reply into `smoke.txt`.
