# Two-pass remediation: route displaced semantics before normalising structure

## Goal

When the `auto_shaper_wiki` agent normalises a structural element (heading vocabulary, page anatomy, frontmatter field, label) and the existing content carries semantics that don't fit the target structure, the agent must route the displaced semantics to their proper channel **before** applying the structural fix. Calling this "two-pass remediation" makes it citable in the audit report. The audit report must surface both halves of the fix, not silently swallow the routing step.

## Context

This is one of a family of **generalisable refinements** to the wiki skills + `auto_shaper_wiki` agent. The trigger was a concrete friction point surfaced while auditing a real wiki, but the rule is stated globally so it applies to every user of the wiki skills, not just the originating case.

During that audit the agent normalised eight labels from "What the session showed" to "What the canon says" (a vocabulary fix), and then **jammed the displaced session date into the heading** as a parenthetical qualifier — producing the same overcompressed labels documented in [wiki_metadata-in-headings.md](../wiki_metadata-in-headings.md).

The correct path: route the date+session metadata to an agent-writable channel (**first**) — `sources:` pointing at an existing `raw/` sidecar when one already exists, otherwise frontmatter, `## Derived from`, an inline link, or `log.md` — then normalise the label with no leftover semantic baggage. When displaced meaning needs a new `raw/` sidecar, surface that need for `wiki_import` rather than creating `raw/` content during the audit.

The agent already practises the pattern inside single-purpose fix moves — `<fix_external_source_pointer>` migrates an external pointer to `## Derived from` and surfaces "external attribution migrated" in the per-file change report — so this task names the general rule those moves instantiate and applies it to every normalisation.

**Where the rule sits relative to the shipped remediation contract.** The agent now carries one governing remediation rule in `<remediation_contract>`: apply every fix that is safe and deterministic, surface only genuine judgment calls, where safe and deterministic means the fix "loses no meaning, invents no value, and resolves no genuine ambiguity". Two-pass remediation refines that contract rather than competing with it, and it closes a gap the contract leaves open: jamming a displaced date into a heading loses no meaning by the contract's own test — the date is still on the page — so the contract permits the fix while the reader is left with a broken structural element. Two-pass supplies the missing clause, that a fix having to relocate meaning routes it to its channel first and changes the structure second. State the rule as a refinement of the contract and cite the contract from it, per the repo convention of pairing an enforcement rule with the canonical statement it refines.

Skipping the routing step also produces:

- **Overcompressed labels** — vocabulary terms forced to carry extra semantics they were never meant to (the "What the canon says (2026-01-15 ...)" case above).
- **Headings with parenthetical attribution** — the structural element broken to hold metadata.
- **Frontmatter fields with embedded prose** — e.g., `scope: project xyz (Q3 only)`.
- **Section titles with embedded scope or mandate-level tags** — another shape of the same failure when scope/mandate metadata gets jammed into a title rather than routed to frontmatter.

It cites this task's named "two-pass remediation" rule and owns the heading/SCHEMA Layer-2 fixtures (Approach **Harness placement**, scenarios **AS-6** / **AS-7**); this task authors the named rule and proves it on a frontmatter surface it alone owns. ## Approach

1. **`plugins/knowledge_management/agents/auto_shaper_wiki.md` `<remediate>` section** — add an explicit three-step rule named "two-pass remediation", opening with one line that cites `<remediation_contract>` as the governing statement it refines and names the gap it closes (relocating meaning passes the contract's loses-no-meaning test, so the contract alone permits the broken structure — see Context). The three steps:
   1. **Identify displaced semantics.** Before changing the structure, name what semantic content the existing structure carries that won't fit the target. Examples: date/source in a heading, qualifier in a frontmatter key, scope tag in a section title, mandate level in a page name.
   2. **Route displaced semantics first.** Move the content to its proper structured channel the agent may write — frontmatter, `sources:` to an existing `raw/` sidecar, an inline link, `## Derived from`, `log.md` — before applying the structural fix. When the proper channel is a new `raw/` sidecar, surface the need for `wiki_import` and leave `raw/` content untouched (`<raw_directory_read_only>`, `<fix_external_source_pointer>`).
   3. **Then normalise.** Apply the structural fix with no leftover semantic baggage.
2. **Same file, `<report_changes>`, `<remediate_output>`, and `<verify_output>`** — rewrite those three surfaces so that when the agent performs a normalisation, both the live remediation summary (`<remediate_output>`) and the final per-file change report (`<report_changes>` / `<verify_output>`) name both halves: the structural fix *and* any displaced-semantics routing it performed. Example phrasing: "label normalised + date/source routed to `sources:`". A normalisation with displaced semantics that were not routed must surface in those reports rather than being silently completed.
3. Reference the new rule by name ("two-pass remediation") from every `<fix_*>` move under `<fix_moves>` that rewrites structural labels, headings, anatomy, or frontmatter shape — including at least `<fix_type_anatomy_mismatch>`, `<fix_section_order_or_gaps>`, `<fix_frontmatter_missing_or_malformed>`, and `<fix_undeclared_custom_field>`. Rewrite `<fix_undeclared_custom_field>` in place so it keeps the undeclared-key branch (remove the field, or add a `SCHEMA.md` `## Frontmatter` declaration before keeping it) and adds an invalid-declared-value branch: when the field is already declared and the value sits outside the declared set because it embeds a displaceable qualifier, apply "two-pass remediation" — route the qualifier to an agent-writable channel first, then set the field to the matching clean declared enum member (field remains; that case does not use remove-or-declare).
4. **Harness placement** — stage one Layer-2 `wiki_fix` / `auto_shaper_wiki` behavioural fixture as scenario **AS-12** (confirm **AS-12** is still free against every `AS-*` id reserved by a live task under `tasks/`, including those reserved in [wiki_metadata-in-headings.md](../wiki_metadata-in-headings.md) and [wiki_log-heading-uniqueness-and-repair.md](../wiki_log-heading-uniqueness-and-repair.md)): register it in `tests/wiki/layer2/evals.json` and add a matching `stage_AS-12` block in `tests/wiki/layer2/setup_scenarios.sh` following the existing AS-* pattern (`skill_name: wiki_fix`, out-of-band grading, top-level `passes` denominator from that `evals.json`). The fixture page carries `scope: alpha (Q3 only)`. The sandbox `SCHEMA.md` `## Frontmatter` yaml block declares `scope: alpha | beta` and a second field `window: Q3 | full` so normalisation targets declared enums rather than `<fix_undeclared_custom_field>` remove-or-declare handling. After remediation `scope` is the clean declared value `alpha` and the displaced qualifier is routed to frontmatter `window: Q3` (not `sources:` / `raw/`, and not `## Derived from` — Q3 is scope metadata, not a source or external lineage) before the normalisation, with both halves named in the report surfaces Approach **Same file, `<report_changes>`, `<remediate_output>`, and `<verify_output>`** names. Grade AS-12 against the expanded `<fix_undeclared_custom_field>` invalid-declared-value branch (not remove-or-declare). AS-12 declares Layer-2 observables on the final graded surface, following the AS-5 `extra_report_fields` / `final_line` pattern in `tests/wiki/layer2/evals.json`: `extra_report_fields` `per_file_both_halves: <verbatim final per-file change-report line(s) for the fixture page that name both the structural normalisation and the displaced-semantics routing>` and `remediate_both_halves: <paste or one-line summary of the live`<remediate_output>`both-halves naming for that file>`; `extra_report_field_doc` states that `remediate_both_halves` is filled from the live remediation summaries because mid-work `<remediate_output>` is not a filesystem surface, and that `per_file_both_halves` pastes the final per-file report the agent emits under `<report_changes>` / `<verify_output>`; assertions grade those fields with `report_field_matches` (needles/regex that require both the structural half and the routing half). Grade AS-12 out-of-band over that top-level `passes` denominator; all-passes-clean is the deliverable. When a run misses the bar, record the measured rate and diverging assertions and hand disposition to the user rather than re-running for a better draw.

**Out of scope:** heading/SCHEMA vocabulary Layer-2 fixtures (AS-6 / AS-7) and the heading-label remediation story (non-vocabulary labels, SCHEMA vocabulary match, attribution routing), owned by [wiki_metadata-in-headings.md](../wiki_metadata-in-headings.md).
