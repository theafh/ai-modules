# Route serial implement/audit delegation to agent_spinner

## Goal

A prompt that asks for a serial two-agent loop — implement, then have a second agent audit, repeat until the task is stamped audited — loads `agent_spinner`. A prompt that names a task file and also asks for helper agents stays with `agent_spinner`, because the ask requests delegation, and it is not routed away to `task_*` before the skill is considered. The description and `<selector>` carry a phrase for the serial loop, not only for fan-out, lenses, judges, and verifiers.

## Context

- The skill's `description:` enumerates fan-out over files, parallel helpers, lens panels, judge panels, verifier passes, and cross-checks. It has no phrase for the serial implement/audit loop, even though its own selector table names "Implement one task, a tracked item with its own acceptance list, spanning many files" and the `multi-file-task.md` recipe. `python3 plugins/ai_dev/skills/skill_doctor/scripts/discovery_safety.py plugins/ai_dev/skills/agent_spinner/SKILL.md` reports the description at 974 characters against the 1,000-character listing-risk threshold (`LISTING_BUDGET_RISK_CHARS = 8000 // 8`), so 26 characters of headroom remain. The edit cuts the 42-character span `Every guarantee holds at the inline floor.` in place, whose doctrine stays in `<role>` and `<degradation>`, to fund the new clause instead of appending past the threshold. The clause introduces the words `serial`, `implement`, `audit`, and `loop`, which `tests/agent_spinner/trigger_overlap.py`'s `VOCAB` does not carry today, so step 9 extends it and disposes every set the wider vocabulary then names.
- The serial-loop ask has no recipe and no selector row. The recipe files `references/recipes/*.md` cover fidelity review, artifact repair, check-only audit, prose sweep, multi-file task, option panel, research synthesis, and disputed claim; `serial-loop.md` does not exist.
- `<selector>` says an ask that combines rows "takes no recipe", so the serial-loop row this task adds contradicts that sentence as it stands. The row is a dedicated procedure for a combining ask, so step 3 rewrites that sentence in place to permit a dedicated row and to state that the serial-loop row's recipe is authoritative, rather than leaving the row and the sentence in conflict.
- `<invocation_boundary>` routes "a request naming the task backlog or the wiki without naming this skill" to that family. `task_implement` and `task_audit` own no agent loop, so a prompt whose first token is a `tasks/….md` path reads as a backlog request and the delegation discipline falls through the gap. Its second paragraph already says the family's writer stays the only writer, which the first paragraph's routing sentence does not reconcile with a task-path ask that also wants helpers.
- Observed: eleven sessions carrying the verbatim ask "implement and audit run in sub-agents until one audit stamps the task as audited" never loaded the skill; several loaded `git_auto_review` later, for the review phase only. Separately, 13 of 16 sessions using an identical pasted multi-agent sweep prompt bypassed the skill, because the prompt itself supplied the discipline.
- `python3 tests/agent_spinner/trigger_overlap.py` currently prints `task 1`, naming the `task` set's query "is this task actually done? verify it against the code". The RUNBOOK's older "no set qualified" sentence is stale against that result. With `VOCAB` carrying the four words step 9 adds, the script names every set whose queries carry one of them, and `task` is the closest competition because its queries use `implement`, `audit`, and `loop` in task territory; step 9 records a disposition for every set the re-run names.
- The [trigger-drift task](archive/ai-dev_agent-spinner-trigger-drift.md) measured two specific Cursor queries and closed with no description edit, because the confirming runs passed. This task owns the serial-loop phrase and the routing boundary, and the description edit and its budget headroom are its alone.
