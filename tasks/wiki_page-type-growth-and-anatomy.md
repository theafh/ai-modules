# Declare page-type growth patterns; clarify custom-type anatomy for session-derived sources

## Goal

Two adjacent failures around page-type contracts get fixed together:

1. **Lint reads a growth pattern before emitting size findings.** Every page type resolves to a growth pattern (`fixed | backlog (self-trimming) | monotonic-append | unbounded-synthesis`), and the 200-line size finding defers for growing types until a higher threshold, where it recommends splitting or graduating entries instead of sanctioning a healthy backlog or synthesis page. The prose canon moves with the check: the split-threshold statements in the wiki skill, the schema template, and the agent's objectives state the same per-pattern thresholds, so the linter and the authoring guidance stop disagreeing about when a page is oversized.
2. **Custom page-type anatomies cover session-derived sources explicitly.** A wiki that declares a custom type states in that type's SCHEMA section which label its entries use for session-derived sources, removing the ambiguity that drives parenthetical heading annotation and silent redefinition of terms like "canon".

## Context

This is one of a family of **generalisable refinements** to the wiki skills + `auto_shaper_wiki` agent. The trigger was a concrete friction point surfaced while auditing a real wiki, but the rule is stated globally so it applies to every user of the wiki skills, not just the originating case. During that audit the auto-shaper either parenthetically annotated a paragraph heading or silently broadened the definition of "canon" in a page-summary paragraph. Both are remediation smells driven by an ambiguous custom page-type contract. Separately, lint size findings landed in the page body as sanction prose even though that page type's growth past 200 lines is its expected behaviour.

Three facts about the shipped plugin shape the design:

- The canonical page-type enum in the SCHEMA template is `entity | concept | comparison | query | summary | procedure`. The originating wiki's `todo` is a **custom** type, honoured because `lint.py` parses each wiki's `type:` enum from its own SCHEMA frontmatter block (the `TYPE_ENUM_RE` read), and `log.md` / `index.md` are special files outside the page walk that the size check never visits. Growth therefore lands as canonical defaults in the linter plus a per-wiki declaration for custom types.
- SCHEMA.md already has a machine-read config channel: the `## Lint` section, which `lint.py` parses fence-safe through `iter_lint_section_lines` for the `Page-check exclusions:` bullet (`LINT_EXCLUDE_RE`), the `Accepted finding:` bullet (`LINT_ACCEPT_RE`), and the `Declared boilerplate:` bullet (`load_declared_boilerplate`). The growth declaration follows that established pattern rather than inventing a second parse convention.
- `lint_checks.md` already describes a growth-pattern declaration as a page-type-level suppression scope in its "Three suppression scopes sit side by side" paragraph, but `check_page_size` implements no growth logic and `template_schema.md` carries no declaration bullet. This task makes the shipped reference and the code agree, and keeps that reference paragraph as the statement of the scope.

Files involved:

- [template_schema.md](../plugins/knowledge_management/skills/wiki/references/template_schema.md): the `## Lint` section, the custom-declaration guidance, and the `**Split a page** when it exceeds ~200 lines` threshold bullet.
- [lint.py](../plugins/knowledge_management/skills/wiki/scripts/lint.py): `check_page_size` and the `## Lint` section parse.
- [lint_checks.md](../plugins/knowledge_management/skills/wiki/references/lint_checks.md): document the growth-aware size behaviour.
- [skills/wiki/SKILL.md](../plugins/knowledge_management/skills/wiki/SKILL.md): the `<write_or_update_pages>` "**Split** a page that exceeds ~200 lines" bullet and the `<pages_stay_scannable>` pitfall.
- [auto_shaper_wiki.md](../plugins/knowledge_management/agents/auto_shaper_wiki.md): the `<topic_separation>` objective, the `<anatomy_compliance>` and `<section_order_or_gaps>` objectives (custom-type anatomy routing), plus a verify-only pass over the line containing "note the rationale on the page's body or" (locate by phrase).

Related tasks:

- [wiki_metadata-in-headings.md](wiki_metadata-in-headings.md): the parenthetical-attribution failure this task partly causes by leaving the anatomy ambiguous.
- [wiki_lint-accepted-info-suppression.md](archive/wiki_lint-accepted-info-suppression.md) owns the instance-level accept mechanism and has shipped (`status: finished`, `implemented-by: Andreas Hoffmann`); the decided boundary stands: a declared growth pattern defers size findings type-wide, while the accept mechanism covers an individual reviewed finding. The shipped `<topic_separation>` statement already carries the `- Accepted finding: …` route in `auto_shaper_wiki.md`, so this task composes its per-pattern thresholds with that route in the one existing statement, and registers its growth bullet in the same `<configurable_zones>` entry beside the landed `Accepted finding` bullet.

## Approach

1. **Canonical defaults in `lint.py`.** Map the built-in types: `entity`, `concept`, `procedure` → `fixed`; `summary`, `query`, `comparison` → `unbounded-synthesis`. `comparison` joins the growing set because `lint.py` already treats it as a synthesis type (`SYNTHESIS_TYPES = frozenset({"summary", "query", "comparison"})`) and `lint_checks.md` exempts it from the long-lead meta-prose heuristic on that same basis: mapping it to `fixed` would give one type two contradictory contracts and reinstate on comparison pages the exact 200-line sanction Goal 1 exists to remove. Resolve the two synthesis defaults from `SYNTHESIS_TYPES` so the growth set and the meta-prose set cannot drift apart. Defaults live in the linter so existing wikis get them with no migration.
2. **Custom-type declaration in the SCHEMA `## Lint` section.** One labeled bullet, for example `- Growth patterns: todo=backlog`, parsed with the same fence-safe scan as `Page-check exclusions:` and additive over the defaults. Document the bullet in the template's `## Lint` section (as documentation inside a fenced example, mirroring the exclusions bullet) and in `lint_checks.md`. Register it in the agent's `<configurable_zones>` entry for `template_schema.md`, which today names the `Page-check exclusions`, `Accepted finding`, and `Declared boilerplate` bullets as wiki-owned inside `## Lint`: without that entry a declared growth pattern survives on nothing but `<hunk_classification>`'s generic extends-the-canon fallback, and an audit reading it as scaffold drift would remove the declaration that keeps the wiki's size findings correct.
3. **Growth-aware `check_page_size`.** Resolve each page's effective pattern (declaration first, then canonical default, then `fixed` for an undeclared custom type): `fixed` keeps today's over-200 info finding; `backlog`, `monotonic-append`, and `unbounded-synthesis` defer to 500 lines, past which the finding recommends split-or-graduate-entries rather than a body sanction.
4. **Growth-aware prose canon.** Move the split-threshold statements outside the linter together with the check so prose and check tell one story: rewrite the `<write_or_update_pages>` split bullet and the `<pages_stay_scannable>` pitfall in `SKILL.md`, the `**Split a page**` threshold bullet in `template_schema.md`, the `<topic_separation>` objective in `auto_shaper_wiki.md`, and the "Three suppression scopes sit side by side" paragraph in `lint_checks.md` to state the threshold per growth pattern: `fixed` types split past ~200 lines; growing types defer to step 3's higher threshold, where the action is split or graduate entries. That `lint_checks.md` paragraph currently calls a growth declaration a **page-type** suppression that defers size findings "for every page of that type", which step 3 makes untrue: rewrite it to state the threshold deferral, so a page past the higher threshold still draws a size finding recommending split or graduate entries and the paragraph describes the check the linter actually runs. Also rewrite in place the two `lint_checks.md` passages that state one 200-line trigger for every page: the `| size | pages over 200 lines |` row in the check matrix and the "oversized pages (>200 lines)" phrase in the **info** severity bullet. Each becomes the per-pattern statement — the `fixed` trigger at ~200 lines and the growing-type deferral threshold — so no 200-line-for-all-pages wording survives beside the rewritten row and phrase. Rewrite the `<topic_separation>` objective in place as one composed statement: replace its current unqualified 200-line half with those per-pattern thresholds and keep its shipped `- Accepted finding: …` bullet route in `$WIKI/SCHEMA.md`'s `## Lint` section, so the existing sentence carries both halves and the acceptance route survives the rewrite. Carry the new sanction vocabulary into the detector that guards page bodies, because the two move together: add `500-line` and `split or graduate` to `META_PROSE_PHRASES` in `lint.py`, and add the same two phrases to the phrase enumeration in the `meta-prose` matrix row of `lint_checks.md`, so a page body carrying the deferral wording draws an info `meta-prose` finding and the reference names the exact list the code matches.
5. **Custom-type anatomy rule in `template_schema.md`.** Add a new `## Custom Types` section to `template_schema.md`, placed after `## Procedure Pages` and before `## Update Policy` (the template has no existing custom-declaration guidance to sit beside; `**Custom domain-specific fields.**` under `## Frontmatter` covers frontmatter only). It states: a wiki that declares a type beyond the six canonical ones in its `## Frontmatter` `type:` enum adds a `## <Type> Pages` section to its `SCHEMA.md` defining that type's section anatomy, and that anatomy names the label its entries use for session-derived sources. The per-type anatomy lives in `SCHEMA.md` because the detection path and the remediation path must read it from the same place: `fix_canonical_page_type_missing` already sends per-type page-anatomy guidance there, while `auto_shaper_wiki.md` routes anatomy to the canonical `wiki/SKILL.md` "Page anatomy" table alone. Rewrite its three anatomy objectives in place as part of this step — `<anatomy_compliance>`, `<section_order_or_gaps>`, and `<fix_section_order_or_gaps>` — so each resolves a custom type's anatomy from that type's `## <Type> Pages` section in `$WIKI/SCHEMA.md`, falling back to the canonical table for the six built-in types. As shipped all three name that canonical-only table, so a custom-type page is either skipped by the audit or has every heading set flagged as a mismatch, and a page the audit does flag is reordered by `<fix_section_order_or_gaps>` to a canonical type's section list — destroying the custom anatomy this step exists to preserve. The session-derived-source label rule ships with no audit consumer until `<anatomy_compliance>` and `<section_order_or_gaps>` are rewritten. The rule sentence carries the anchor phrase `label its entries use for session-derived sources`, which the Acceptance item greps in the shipped template. The originating wiki's `todo` anatomy, a "What the canon says" paragraph reading awkwardly for entries sourced from recorded sessions, is the motivating illustration.
6. **`auto_shaper_wiki.md` body-routing wording.** Verify the "note the rationale on the page's body or" wording is gone: [wiki_meta-prose-in-page-bodies.md](archive/wiki_meta-prose-in-page-bodies.md) shipped that removal (sanction rationale routes to `SCHEMA.md` or `log.md`, never the page body), so this step is verify-only and changes nothing.

7. **Deterministic proof surface in `tests/wiki/layer1/run.sh`.** Stage Fixtures A–F and the shipped-template check as one `scenario` each in `tests/wiki/layer1/run.sh`, under the next free `l<n>` ids at implementation time, using the shipped `stage_fresh_wiki`, `run_lint`, `assert_lint_finding`, `assert_finding_for_file`, `assert_no_finding_for_file`, `assert_no_lint_category`, and `grow_page_past_soft_cap` helpers. Each scenario writes the fixture wiki's SCHEMA (type enum plus the `## Lint` growth bullet where the fixture declares one), writes the page, grows it to the fixture's line count with `grow_page_past_soft_cap`, runs `run_lint`, and asserts the `size` and `meta-prose` categories for that page's path. `write_typed_page` maps only the six canonical types, so a `todo` page is written directly into its declared type folder. The scenarios run under `tests/wiki/run_all.sh`.

## Acceptance

- **Fixture A:** a wiki whose SCHEMA declares `todo` in its frontmatter type enum and `todo=backlog` on the `## Lint` growth bullet; a 250-line todo page → `run_lint` reports no `size` finding for that page (`assert_no_finding_for_file`) and no `meta-prose` finding for it (`assert_no_lint_category`), and the same page with one `META_PROSE_PHRASES` sentence appended → `assert_finding_for_file` sees an `info` `meta-prose` finding, so the clean page's absence is a live check rather than a vacuous pass. Proved by the layer-1 `todo`-declared, 250-line scenario named in Approach step 7.
- **Fixture B:** same wiki, 700-line todo page → `assert_finding_for_file` finds one `info size` finding scoped to that page, the finding's message names split or graduate entries (asserted by grepping that finding line for `split or graduate`), and `assert_no_lint_category` finds no `meta-prose`. Proved by the layer-1 `todo`-declared, 700-line scenario named in Approach step 7.
- **Fixture C:** a 250-line `summary` page in a wiki with no growth bullet → `assert_no_lint_category` finds no `size` finding (canonical default covers built-in types). Proved by the layer-1 `summary` scenario named in Approach step 7, staged with `write_typed_page`.
- **Fixture D:** the fixture SCHEMA's custom-type section names its session-derived-source label; a todo entry sourced from a recorded session uses that label verbatim with no parenthetical attribution, and attribution lives in frontmatter `sources:` pointing at `raw/meetings/<slug>.md`. Mechanically proved by the layer-1 custom-type scenario named in Approach step 7: `grep -F` finds the label on the fixture `SCHEMA.md`, and a page of that type carrying `sources:` at `raw/meetings/<slug>.md` raises no `broken-source` finding (`assert_no_lint_category … broken-source`).
- **Fixture E:** a wiki whose SCHEMA declares `todo` in its frontmatter type enum but carries no growth bullet; a 250-line todo page → one `size` finding at `info` severity, because an undeclared custom type resolves to `fixed` per Approach 3. Proven as a scenario in `tests/wiki/layer1/run.sh` alongside Fixtures A–D: `grow_page_past_soft_cap "$wiki/todos/<slug>.md" 250`, then `run_lint "$wiki"` and `assert_lint_finding "<label>" "$out" info "size"`.
- **Fixture F:** a 250-line `comparison` page in a wiki with no growth bullet → no size finding, proving `comparison` resolves to `unbounded-synthesis` rather than `fixed`; staged in `tests/wiki/layer1/run.sh` with `run_lint` plus `assert_no_lint_category`.
- **Shipped template rule:** a `tests/wiki/layer1/run.sh` scenario greps the shipped `template_schema.md` (`$WIKI_SKILL/references/template_schema.md`) for the anchor phrase `label its entries use for session-derived sources`, proving the custom-type anatomy rule ships in the template rather than only in a fixture SCHEMA.
- **Custom-type anatomy has an audit consumer:** a `tests/wiki/layer1/run.sh` scenario greps the shipped `auto_shaper_wiki.md` (`$WIKI_SKILL/../../agents/auto_shaper_wiki.md`, resolved the same way the shipped-template scenario resolves its path) and asserts, with `grep -F`, that `<anatomy_compliance>`, `<section_order_or_gaps>`, and `<fix_section_order_or_gaps>` each carry the verbatim anchor `## <Type> Pages` section of `$WIKI/SCHEMA.md`, proving the audit's detection and its remediation both read custom-type anatomy rather than only the canonical `wiki/SKILL.md` "Page anatomy" table.
- The split threshold reads growth-aware at every prose site: the `SKILL.md` split bullet and `<pages_stay_scannable>` pitfall, the `template_schema.md` split bullet, the agent's `<topic_separation>` objective, and the `lint_checks.md` `size` matrix row and info-severity "oversized pages" phrase each state the per-pattern thresholds (fixed at ~200 lines; growing types at the deferral threshold) rather than one unqualified 200-line rule, and neither `lint_checks.md` passage still carries its prior 200-line-for-all-pages wording; the rewritten `<topic_separation>` objective states those thresholds and keeps its shipped `- Accepted finding: …` route inside the same statement, proven by reading `auto_shaper_wiki.md`'s `<topic_separation>` block for both the per-pattern threshold wording and the `- Accepted finding:` route.
- **New-vocabulary meta-prose scenario:** a scenario in `tests/wiki/layer1/run.sh` stages a concept page whose body, below its lead paragraph, carries both `This page is past the 500-line deferral.` and `Past the higher threshold the action is split or graduate entries.`, then asserts each added phrase is caught on its own — `assert_live_message "500-line phrase caught" "$out" "concepts/widget.md" "500-line"` and `assert_live_message "split or graduate phrase caught" "$out" "concepts/widget.md" "split or graduate"` — so registering only one of the two phrases in `META_PROSE_PHRASES` fails the scenario on the other; then stages the same page with both sentences removed and asserts no `meta-prose` finding for that page (`assert_no_finding_for_file "clean page carries no meta-prose" "$out" meta-prose "concepts/widget.md"`), so each new phrase is proven caught rather than passed vacuously.
- `template_schema.md` and `lint_checks.md` document the growth bullet, the canonical defaults, and the deferral thresholds. The `lint_checks.md` "Three suppression scopes sit side by side" paragraph states the threshold deferral — a growing type's size findings defer to the higher threshold, and a page past it still draws a size finding recommending split or graduate entries — matching the check and the SCHEMA bullet, so the reference states a mechanism the linter actually honours. The `lint_checks.md` `meta-prose` matrix row carries the two new sanction phrases beside the existing ones, so the row's phrase enumeration matches `META_PROSE_PHRASES`; proved by grepping that row's `meta-prose` line for `500-line` and `split or graduate`.
- The agent's `<configurable_zones>` entry for `template_schema.md` names the growth bullet alongside the `Page-check exclusions`, `Accepted finding`, and `Declared boilerplate` bullets, so a scaffold diff reads a declared growth pattern as wiki-owned content instead of drift.
- **The wiki harness passes on its deterministic layer-1 default.** `tests/wiki/run_all.sh` exits 0, running the new growth-pattern lint scenarios with the rest of layer 1; layer 2 stays an optional operator measurement pass outside this contract.
