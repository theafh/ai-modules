# Route agent_spinner checking passes through the read-only checker role

## Goal

A checking pass spawns `auto_checker_spinner` by default when the probe finds it, so the host-enforced read-only lever applies. The run records which route each spawned check used on its roster row — an inline pass records no route, because `spawn_route` is written only by `dispatch` and by probe rows — and a check that ran through a generic spawn, such as the host's generic helper, is a visible narrowing rather than an invisible one.

## Context

- `agent_spinner`'s `<degradation>` already directs a run to spawn through `auto_checker_spinner` when the probe finds it, because a registered role can carry a host-enforced read-only lever that a generic spawn lacks. The Checking pass template in `references/role-prompts.md` states neither the route nor the lever, so a generic checker's read-only status rests only on the brief's prose prohibition.
- `auto_checker_spinner` is defined in `plugins/ai_dev/agents/auto_checker_spinner.md` with `readonly: true` and a `Read, Grep, Glob` tool list. The host's generic helper — `generalPurpose` on Cursor, `general-purpose` on Claude — carries no such lever.
- `dispatch` already records `spawn_route` on the roster row (`run_ledger.py` writes `--route`, defaulting to `generic`), and `dispose --narrowing` already writes a `narrowing` record. `close` prints the tally block but no narrowing line, so a generic route is recorded without being named out loud; `references/report-shapes.md`'s "Coverage narrowing:" paragraph is the prose rendering that a printed line would back.
- `references/checks.md` defines a narrowing as "any reduction in what the run checks", which on its own leaves a route weakening outside the checked set: running a found role generically reduces the host-enforced lever, not the checked set. The same section gains a one-clause cross-reference that counts a route weakening as a narrowing of the host-enforced lever, and Step 1's sentence rests on that clause.
- Test surfaces: `tests/agent_spinner/evals/` (`evals.json`, `grade.sh`, `fixtures/<id>/setup.sh`, `README.md`), `tests/agent_spinner/script_tests/run.sh` (static pins), `tests/agent_spinner/script_tests/ledger_run.sh` (ledger scenarios), and `tests/agent_spinner/script_tests/grade_cases.sh` (committed grader pass/fail cases).

## Approach

1. Keep `<degradation>`'s existing default — spawn through `auto_checker_spinner` when the probe finds it — and append this passage to item 2 of the block, after `... with the lever and depth recorded as the probe found them.`, in place, as the shipped text, verbatim:

   > A generic spawn is a narrowing, recorded with the route and the reason the run did not use a role. Name the reason as one of: the probe found no role, the user chose the generic route, the host refused the registered role at spawn, or the role failed and the single re-invocation ran generically. Record it through `dispose --narrowing`, whose text carries the route and the reason.

   Edit sites, each written in place. `plugins/ai_dev/skills/agent_spinner/SKILL.md`'s `<degradation>` block gains the passage above. `references/checks.md`'s narrowing definition gains one sentence immediately after "A narrowing is any reduction in what the run checks, and the report names every narrowing.": "Running a found role generically is a narrowing of the host-enforced lever." `references/run-protocol.md`'s `dispose` `--narrowing TEXT` bullet gains the clause "`--narrowing` alone records a narrowing whose `--drops` list is empty", because `--drops` is optional and `dispose` appends the narrowing record with an empty `drops` list (`run_ledger.py`: `drops = []`, then `led.append({"type": "narrowing", "text": args.narrowing, "drops": drops})`), so a route weakening with no dropped row needs no label list and no migration.

   Task rationale, not shipped text: one scope covers every generic spawn, so the rule fires both where the probe found no role and where it found one the run did not use, and the Goal's checking case is the instance this task proves — a generic writer spawn is covered by the same sentence through the same mechanism, `dispose --narrowing` carrying the route and the reason, so it needs no separate Acceptance item. The four grounds are the admissible reasons a run may name, and `dispose --narrowing` is the recording verb because `close` prints that record once step 3 lands. The inline-floor path stays unchanged; an inline pass records no `spawn_route`, because the field is written only by `dispatch` and by probe rows. The existing `degradation_states_tier_only` pin keeps the block naming the tier and free of the words `answer`, `dispatched`, and `exited`; the passage above carries none of them.

2. Rewrite the Checking pass template in `references/role-prompts.md` in place so its access block adds the sentence "Name the route this pass runs on — `auto_checker_spinner` where the probe found it, or generic — and the read-only lever the probe recorded for that route.", keyed to this table:

   | Route | `spawn_route` | Lever the brief states |
   | --- | --- | --- |
   | Registered role, probe found it | `auto_checker_spinner` | `read_only` as the probe recorded it for the role, plus the role's own `readonly: true` and `Read, Grep, Glob` tool list |
   | Generic, probe found no role | `generic` (the host's generic helper included) | `read_only` as the probe recorded it, `assumed absent` where no lever was established; the brief's prohibition is the only guard |
   | Generic over a role the probe found | `generic` | `read_only` as the probe recorded it, `assumed absent` where no lever was established, with the reason from step 1 in the `narrowing` record's text, not in a roster column |

   Preserve the static constraints the reference tree already enforces: each template's first line opens with an action verb, and no template claims precedence over the surrounding conversation. The Checking pass template's existing pinned default-contract sentence — "Where it names none, hold one line per claim the artifact makes, in artifact order" — stays as it is.

3. Print the narrowing from the ledger: `cmd_close` in `scripts/run_ledger.py` prints one `narrowing: <text>` line per `narrowing` record, which `dispose --narrowing` already writes. `references/report-shapes.md`'s closing report example gains a `narrowing: <text>` line matching that output, and its "Coverage narrowing:" paragraph stays the prose rendering that line backs. `spawn_route` already defaults to `generic` for rows that predate the field; that default stays current behaviour, so no migration is needed. Extend `tests/agent_spinner/script_tests/ledger_run.sh` with a scenario that records a narrowing through `dispose --narrowing` and asserts `close` prints its text.

4. Extend the existing `checker_spawned_without_role` eval in place with the narrowing assertion rather than adding a parallel eval, and extend `checker_spawned_through_role` in place with the write attempt. The generic scenario has no host lever to refuse a write, so it proves the byte-identical tree and the recorded narrowing. The role scenario replaces its `Change no file` line with an instruction that the checker attempts to write its own verdict to the write target `.agent_spinner/checker-write.txt` before it returns its verdict, and that the orchestrator writes no corpus file; a landed write fails the eval. The instruction names no last act, because `cmd_brief` appends the fixed line `Return channel: write returns/<label>.md as your last act.` to every brief (`run_ledger.py`: `closing.append("Return channel: write returns/%s.md as your last act." % args.label)`) and `<helper_failure>` fixes a read-only checker's final message as its return block and END line; the write attempt is the one act the brief asks for before that return, and the attempt probes the host lever the shipped `<checking>` read-only contract refuses. Prove the attempt was made and refused on the surfaces that observe it: the checker brief at `.agent_spinner/briefs/<label>.txt` carries the write instruction naming that target, the through-role prompt carries no `Change no file`, `.agent_spinner/checker-write.txt` is absent (`file_absent`), and `settings.md` stays byte-identical under `tree_unchanged`; optionally, the checker's return names the refusal and the report relays it. Do not claim the refusal through `class_withheld_or_failed write` over `tool_calls.jsonl`: that file is built from `worker.stream_tools` only, while a Cursor helper's calls land in `tools` alone, so the assertion cannot observe a Cursor helper's write. Add a third eval, `checker_generic_over_found_role`, whose fixture is staged from `checker_spawned_through_role`'s fixture so the probe finds `auto_checker_spinner`, whose prompt asks for the host's generic helper (`generalPurpose` on Cursor, `general-purpose` on Claude): it asserts `spawn_route: generic` on the checker row and a `narrowing` record whose text names the generic route and the canonical reason `the user chose the generic route`. The new eval entry copies `checker_spawned_through_role`'s `harness.agents` entry, `plugins/ai_dev/agents/auto_checker_spinner.md`, and its `timeout: 2400`; that `evals.json` field is the edit site that makes the probe find the role, because the fixture stages only the page. Edit sites: `tests/agent_spinner/evals/evals.json` (the two prompts and their expectations, plus the new entry with its copied `harness.agents` and `timeout`), `tests/agent_spinner/evals/fixtures/<id>/setup.sh` (the staged `settings.md` page and `baseline/settings.md`, plus the new `checker_generic_over_found_role` fixture), `tests/agent_spinner/evals/grade.sh` (the brief and prompt assertions beside `file_absent` for the write target), `tests/agent_spinner/script_tests/grade_cases.sh` (give its `checker_spawned_without_role` case a `ledger.jsonl` carrying the narrowing record, add a case where that record is missing so the grader fails, and add a case where the checker brief omits the write instruction so the new brief check fails), and `tests/agent_spinner/evals/README.md` (a "Prompts kept request-only" entry for the new eval's generic-helper prompt and a signal-table row for the eval).

5. Add a static check to `tests/agent_spinner/script_tests/run.sh` that the Checking pass template names `auto_checker_spinner` and the read-only lever, plus the discriminating control the script already uses: a scratch copy with the new sentence removed must fail the check.

The generic route over a role the probe found is advisory: the run records the route and the reason through `dispose --narrowing`, prints the narrowing from `close`, and continues without holding the dispatch. `<coverage_tradeoff>` already treats a named narrowing as the run's proceed-with-a-record mechanism, and `<degradation>` says "otherwise spawn generically" for a host-refused or failed role, so the repository settles the route as recorded rather than gated.

**Out of scope:** changing the `auto_checker_spinner` agent definition itself; its `readonly: true` and `Read, Grep, Glob` tool list are already the correct lever.

## Acceptance

- The default role route is the shipped `<degradation>` prose, not the eval: `rg -n "A generic spawn is a narrowing" plugins/ai_dev/skills/agent_spinner/SKILL.md` finds the new sentence, and the same block still directs the role spawn when the probe finds it. `checker_spawned_through_role` directs the role in its own prompt, so it proves a user-directed route rather than the probe-driven default; it asserts `spawn_route: auto_checker_spinner` on the checker row. `checker_spawned_without_role` asserts the generic checker row's `spawn_route` and a `narrowing` record whose text names the generic route; `script_tests/grade_cases.sh` carries a `ledger.jsonl` with that record for the case and a negative case that fails when the record is absent.
- `checker_generic_over_found_role` passes: its probe finds `auto_checker_spinner` through the entry's copied `harness.agents` (`plugins/ai_dev/agents/auto_checker_spinner.md`), the user asks for the host's generic helper, the checker row records `spawn_route: generic`, and the ledger holds a `narrowing` record whose text names the generic route and the canonical reason `the user chose the generic route`.
- `run_ledger.py`'s `cmd_close` prints one `narrowing: <text>` line per narrowing record: the new `ledger_run.sh` scenario records a narrowing through `dispose --narrowing` and `close` prints its text. The scenario was verified once at implementation time against the pre-change `cmd_close`, which printed no such line; the durable control is the scenario itself.
- On the role route, the checker is told to write and cannot: the `checker_spawned_through_role` checker brief at `.agent_spinner/briefs/<label>.txt` carries the write instruction naming `.agent_spinner/checker-write.txt`, and the same brief keeps `cmd_brief`'s fixed `Return channel: write returns/<label>.md as your last act.` line, with the write instruction carrying no `last act` wording — `grade.sh` asserts each checker brief carries `Return channel: write returns/` and that no line pairs `checker-write.txt` with `last act`, the through-role prompt carries no `Change no file`, and the attempt is refused on the surfaces that observe it — `.agent_spinner/checker-write.txt` is absent (`file_absent`) and `settings.md` stays byte-identical under `tree_unchanged`; `script_tests/grade_cases.sh` proves the brief check fails when the instruction is removed. Where the probe records the lever as `assumed absent` (the generic route), no host refusal exists: the run records the narrowing and the sandbox tree stays byte-identical instead.
- `rg -n "Name the route this pass runs on" plugins/ai_dev/skills/agent_spinner/references/role-prompts.md` finds the route-and-lever sentence in the Checking pass template, and the static check reads the template with wraps collapsed so the full sentence matches across its wrap.
- The four admissible grounds and the recording verb ship in the `<degradation>` block rather than in task prose: `rg -n "the probe found no role|the user chose the generic route|the host refused the registered role at spawn|the role failed and the single re-invocation ran generically" plugins/ai_dev/skills/agent_spinner/SKILL.md` finds all four grounds inside that block, and ``rg -n 'Record it through `dispose --narrowing`' plugins/ai_dev/skills/agent_spinner/SKILL.md`` finds the recording sentence there. `rg -n "alone records a narrowing whose" plugins/ai_dev/skills/agent_spinner/references/run-protocol.md` finds the `--narrowing` clause in the `dispose` bullet.
- `rg -n "Running a found role generically is a narrowing of the host-enforced lever" plugins/ai_dev/skills/agent_spinner/references/checks.md` finds the route-weakening sentence beside the existing "any reduction in what the run checks" definition, so the shipped definition covers the `<degradation>` sentence.
- The Checking pass template carries the per-route table as step 2 writes it: `rg -n "Lever the brief states" plugins/ai_dev/skills/agent_spinner/references/role-prompts.md` finds the header, and `rg -n "Registered role, probe found it|Generic, probe found no role|Generic over a role the probe found" plugins/ai_dev/skills/agent_spinner/references/role-prompts.md` finds all three route rows, read with wraps collapsed.
