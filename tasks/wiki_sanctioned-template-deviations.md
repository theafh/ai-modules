# Align locked-slot boilerplate handling with preserve-extensions so wiki refinements survive audits

## Goal

The skill stops giving two opposite instructions about the same hunk. The agent already classifies content a wiki has and the canonical template lacks as a customization to preserve when it extends the canon without contradicting it; the locked-slot boilerplate check overrules that verdict by naming restoration of the canonical text as the remedy, and the check currently wins. After this task the check uses the structural insert-only classification Approach freezes (pure additions agree with the agent's preserve path; any delete or replace still warns), so an owner's addition inside a template-locked region of their own `log.md` (today's sole `VERBATIM_SLOTS` region) is reported as an extension rather than as something to restore away, a region that deletes or rewrites canonical text still warns, and a wiki that means to contradict canon can declare that and have the declaration honoured. Reverting a declared divergence goes out of bounds for the agent, and a divergence the agent judges good in general is reported as a candidate for the shipped template rather than deleted in the one wiki that has it.

The outcome the owner sees: a rule they anchored in their wiki is still there after an audit, and an audit that removed one is no longer reported as a clean run.

This task owns the **mechanism** — how any local divergence from a template is treated, whatever it says. What a log entry should contain by default is a content question owned by [wiki_log-scope-wiki-changes-only.md](wiki_log-scope-wiki-changes-only.md), and the two are independently shippable in either order.

## Context

Two shipped mechanics currently leave an owner's refinement of a locked region with no path but removal.

The linter locks each region named in `VERBATIM_SLOTS` byte-for-byte against the shipped templates; today that tuple holds one slot — the `log.md` preamble — and `SCHEMA.md` is not a locked slot. `check_verbatim_boilerplate` in [skills/wiki/scripts/lint.py](../plugins/knowledge_management/skills/wiki/scripts/lint.py) walks the `VERBATIM_SLOTS` tuple, extracts each slot's region from the wiki and from its template, and on any difference emits a `boilerplate` warn whose message ends `restore the region verbatim or update the template if the change is intentional`. Those are the only two remedies the message offers, and neither preserves a per-wiki refinement: the first deletes it, and the second is unavailable to a wiki owner editing their own wiki, since the template ships from this repo and editing it does not reach a wiki that already exists.

The skill already carries the right rule, in the wrong place to win. `<hunk_classification>` in [agents/auto_shaper_wiki.md](../plugins/knowledge_management/agents/auto_shaper_wiki.md) rules that content the wiki has and the canonical lacks is a customization to preserve as-is when it extends the canon without contradicting it, and surfaces it for the user only when it contradicts canonical semantics. An owner's added paragraph inside a locked region is an extension by that test, so the classifier's verdict is preserve. The `boilerplate` finding overrides that verdict, because `<linter_is_truth_for_structure>` makes structural lint output authoritative and the finding's own message names restoring the canonical text as a remedy. Two mechanisms in one skill therefore give opposite instructions on the same hunk, and the one that wins is the one that destroys the owner's work. Note also that `<configurable_zones>` grants `template_log.md` a zone for entries and their bodies while deliberately running the diff on the preamble alone, so the preamble is the single region with no configurable zone; what fails on contact with the check is not missing classifier protection — `<hunk_classification>` already preserves wiki-has/canonical-lacks extensions — but the live `boilerplate` warn whose message names restore-verbatim and, under `<linter_is_truth_for_structure>`, overrides that preserve verdict.

The agent then acts on that signal. `<scaffold_drift>` in [agents/auto_shaper_wiki.md](../plugins/knowledge_management/agents/auto_shaper_wiki.md) drives comparison from a line-level diff against each canonical template, and `<linter_is_truth_for_structure>` makes the linter's structural output authoritative. Nothing in either instruction distinguishes an owner's deliberate addition inside a locked region from accumulated drift when a restore-instructing `boilerplate` warn is live, so the remediation available is to restore the canonical text. [wiki_log-scope-wiki-changes-only.md](wiki_log-scope-wiki-changes-only.md) has already landed additive ensure/refresh on `<fix_log_preamble_drift>` (insert absent units, refresh drifted units by label or greppable stem, leave wiki-only lines byte-identical) and `<lint_already_covers_prelude>` already routes remediation through that move rather than wholesale restore — but both sites still treat a surviving owner-line `boilerplate` warn as an expected remaining finding. The remaining work is aligning those sites (and related clean-exit / scaffold rules) with classify-as-extension / acknowledge / declare so an insert-only extension is not a restore target and no longer blocks as a live warn.

Observed end to end once, in a wiki managed by this skill, and the diagnosis below is a reading of the two instruction blocks named above rather than a ruling by the skill's author: the owner added a paragraph to the `log.md` preamble scoping log entries to changes of the wiki itself, and anchored the same rule in that wiki's `SCHEMA.md` and in the repository's agent instruction files. The next audit read the preamble difference as scaffold drift and deleted the paragraph. The owner caught it mid-run and ordered it restored. Left alone, the audit would have reported a clean run while having removed the rule it was asked to maintain, which is the failure mode this task closes: a silent revert reads afterwards as compliance.

Three sibling tasks bound this one; [wiki_log-scope-wiki-changes-only.md](wiki_log-scope-wiki-changes-only.md) remains live (`audited`), and [wiki_lint-accepted-info-suppression.md](archive/wiki_lint-accepted-info-suppression.md) and [wiki_schema-template-generalization.md](archive/wiki_schema-template-generalization.md) are finished archived, so compose with the live sibling and reuse the finished siblings' shipped surfaces rather than overwrite:

- [wiki_log-scope-wiki-changes-only.md](wiki_log-scope-wiki-changes-only.md) promotes the rule from the motivating incident into canon, because scoping a log entry to wiki changes turned out to be a general failure mode rather than one wiki's preference — the same drift was corrected by hand in two wikis. That settles what this incident is evidence for: the mechanism gap, not a permanently local refinement. Keep the incident as the evidence and do not present that rule as this mechanism's standing example, since the wiki carrying it as a declaration retires the declaration once canon carries the rule.
- [wiki_lint-accepted-info-suppression.md](archive/wiki_lint-accepted-info-suppression.md) has already landed the per-finding acceptance store as labeled `Accepted finding:` bullets in the SCHEMA `## Lint` section, parsed fence-safe like the existing `Page-check exclusions:` bullet, plus the runner surfaces `Issue.render_acknowledged`, `partition_accepted`, and the report's `ACKNOWLEDGED` section. Matching stays `SEV_INFO` only; a matching acceptance never suppresses a non-info finding. A `boilerplate` finding is a warn, so that mechanism cannot carry this case, and this task does not widen it to warns. What this task reuses is that shipped storage decision, parser, and acknowledged channel: another labeled bullet in the same section. Today the agent's `<configurable_zones>` entry for `template_schema.md` names the `Page-check exclusions` bullet and every `Accepted finding` bullet in the `## Lint` section as wiki-owned; [wiki_page-type-growth-and-anatomy.md](wiki_page-type-growth-and-anatomy.md) is still open and has not registered its growth bullet there yet. Rewrite that `<configurable_zones>` enumeration in place so `Declared boilerplate:` joins the wiki-owned `## Lint` bullets present when this task ships (today those two), preserving any further sibling bullets that have already landed by then and replacing none of them.
- [wiki_schema-template-generalization.md](archive/wiki_schema-template-generalization.md) already dropped the `SCHEMA.md` prelude lock and kept the `log.md` preamble lock as load-bearing format documentation. This task agrees with that split: the remaining lock stays, and the declaration is what makes a locked slot survivable. The mechanism below applies to whichever slots `VERBATIM_SLOTS` still holds (today that one region), which is why the work reads the tuple rather than naming a fixed pair.

## Approach

1. **Make the check classify instead of demanding verbatim restoration.** Rewrite `check_verbatim_boilerplate` so a mismatch is classified before any restore message is emitted. Compare the extracted wiki region to the extracted canonical region with a line-level sequence alignment (`difflib.SequenceMatcher` opcode walk over lines; opcodes limited to equal / insert / delete / replace). **Insert-only** — every canonical line survives in order and the only non-equal opcodes are inserts — is an **extension**: report it on a dedicated **acknowledged** report channel that is outside the three live severity totals (`blocking` / `warn` / `info`), never as a live `warn` or live `info` Issue; reuse the acknowledged-section shape [wiki_lint-accepted-info-suppression.md](archive/wiki_lint-accepted-info-suppression.md) already landed via `Issue.render_acknowledged`, `partition_accepted`, and the report's `ACKNOWLEDGED` section, naming the slot and that content was added, and emit no `boilerplate` warn and no restore-verbatim instruction. `check_verbatim_boilerplate` returns `(live_issues, acknowledged_items)`; `main` extends the shared issues list with `live_issues` only; after `partition_accepted`, append those boilerplate `acknowledged_items` onto the acknowledged list before `render_report`. Insert-only extensions and matching declarations never appear as live `warn` or live `info` Issues and never invent a fourth severity. Compose `Issue.render_acknowledged` so the acknowledged line marker is parameterized — `(accepted)` for Accepted-finding suppressions, `(extension)` for insert-only locked-slot extensions, `(declared)` for matching `Declared boilerplate:` honours — and widen the `ACKNOWLEDGED` section header beyond accepted-only wording so it covers those three sources without implying every acknowledged line was an `Accepted finding:` bullet. Supersede the module docstring acceptance-only acknowledgment paragraph (beginning `An info finding the wiki owner has reviewed and accepted`) in place so it names all three acknowledged-channel sources this step wires — accepted-finding suppressions, insert-only locked-slot extensions, and matching `Declared boilerplate:` honours — and states that each is reported outside the live blocking/warn/info totals. Supersede in place the remaining `lint.py` commentary that still states verbatim-equality or accepted-only acknowledgment for these slots: the `VERBATIM_SLOTS` section comment (today: `this check enforces verbatim equality`) so it states the classify-as-extension / delete-or-replace-warn contract this step freezes; the `VerbatimSlot` class docstring (today: "required to match its canonical template") so it names a locked region compared under that contract rather than byte-identical match alone; the `extract_h1_prelude` docstring passage that calls the prelude `"must-stay-verbatim"` so it names a locked-slot extract under classify-as-extension; the `check_verbatim_boilerplate` docstring (today: "warn on mismatch") so it names insert-only → acknowledged extension and delete/replace → warn; the `Issue.render_acknowledged` docstring (today: accepted-finding-only) so it covers the parameterized `(accepted)` / `(extension)` / `(declared)` markers; and the `render_report` docstring (today: ``Accepted finding:``-only for `acknowledged`) so it names all three acknowledged-channel sources and the live-count boundary, matching the module-docstring and `ACKNOWLEDGED` header rewrites already named in this step. **Any delete or replace** of canonical content keeps today's warn, with both remedies named as today. The check does not judge semantic contradiction; that path is the declaration in **Declare a deliberate contradiction, for the case classification cannot settle.** plus the agent's existing surface-for-user posture. This is the cheap half and needs no new wiki syntax, which is why it leads.

2. **Declare a deliberate contradiction, for the case classification cannot settle.** Add one labeled bullet per declared slot to the SCHEMA `## Lint` section. Freeze the grammar as `- Declared boilerplate: <slot.label> — <reason>`, where `<slot.label>` is the exact `VerbatimSlot.label` string from `VERBATIM_SLOTS` and `<reason>` is a short free-text explanation. Parse with the same fence-safe `## Lint` scan as `Page-check exclusions:` / `Accepted finding:`: read only outside fences; match the label case-insensitively; left-anchor on ` — ` so the machine key is the slot-label field and the reason is the remainder (reason is not matched). A live bullet suppresses the `boilerplate` warn only when its slot-label field equals that slot's `label` exactly. A live `Declared boilerplate:` bullet whose slot-label field matches no `VerbatimSlot.label` in `VERBATIM_SLOTS` suppresses nothing and emits one live `SEV_INFO` Issue with category `boilerplate`, path `SCHEMA.md`, naming the unmatched label; it is not placed on the acknowledged channel. Prove per-slot isolation with a Layer 1 fixture that temporarily registers a second test-only `VerbatimSlot` for that case and tears it down afterward; do not add a second production entry to `VERBATIM_SLOTS`. Document the bullet in [references/template_schema.md](../plugins/knowledge_management/skills/wiki/references/template_schema.md) `## Lint` as a fenced example mirroring the exclusions bullet, and compose with the two sibling tasks at that section per `## Context`.

3. **Honour the declaration in the runner.** In `check_verbatim_boilerplate`, a slot with a matching `Declared boilerplate:` bullet emits no `boilerplate` warn and no Issue in any of the three live severity buckets. Report it on the same non-counted acknowledged list and `render_report` path **Make the check classify instead of demanding verbatim restoration.** wires — again without `Accepted finding:` matching and without emitting into any live severity bucket — naming the slot and the declared reason, so the divergence stays visible without an undo instruction and without inflating blocking/warn/info totals or the live `total:` summary. An undeclared *remove-or-rewrite* divergence is unchanged: same warn, same message, both remedies still named. An undeclared *extension* follows **Make the check classify instead of demanding verbatim restoration.**, not this warn path.

4. **Put reverting a locked-slot refinement the check has already cleared out of bounds for the agent.** Rewrite the agent sites so they follow the check's classification on top of the additive ensure/refresh path [wiki_log-scope-wiki-changes-only.md](wiki_log-scope-wiki-changes-only.md) already landed:

   - `<lint_already_covers_prelude>` — supersede any reading that a still-live `boilerplate` mismatch on the locked slot is restore-named for remediate when the check has already cleared an insert-only extension onto the acknowledged channel; keep the landed rule that reporting never licenses wholesale restore and that remediating a live restore-instructing warn goes only through `<fix_log_preamble_drift>`; a still-live restore-instructing `boilerplate` warn remains the structural signal for remove-or-rewrite drift in those slots.
   - `<fix_log_preamble_drift>` — keep the landed additive ensure/refresh form from [wiki_log-scope-wiki-changes-only.md](wiki_log-scope-wiki-changes-only.md); extend it so an acknowledged locked-slot extension and any declared-slot region stay untouched the same way wiki-only lines already do, and a still-live restore-instructing `boilerplate` warn for remove-or-rewrite drift remains the structural signal.
   - `<lint_clean>` — supersede the clean-exit exception that treats a surviving `boilerplate` warn on an owner-added preamble line as an allowed remaining finding; after this task, an acknowledged insert-only locked-slot extension satisfies clean exit (no live `boilerplate` warn); a still-live delete/replace `boilerplate` warn continues to block clean exit.
   - `<scaffold_drift>` / hunk-classification and `<linter_is_truth_for_structure>` — keep the stronger declared-slot rule: a hunk inside a declared slot is wiki-owned and no repair touches it, with the reason in one clause (reverting an owner's declared refinement destroys a recorded decision while the audit reports success). Separately, an undeclared locked-slot extension the check reports as acknowledged is preserved the same way `<hunk_classification>` already preserves wiki-has/canonical-lacks extensions — no restore move fires on it. Rewrite `<linter_is_truth_for_structure>` in place so its "when a check is wrong" passage no longer reads as Accepted-finding-only: name the three non-overlapping structural routes — `- Accepted finding: …` for intentional **info-level** findings only; acknowledged locked-slot **insert-only extensions** (no SCHEMA bullet; visible on the acknowledged channel); `- Declared boilerplate: …` for intentional locked-slot **remove-or-rewrite** divergences — and state that each route suppresses or preserves only its own finding class and none substitutes for the others.
   - `<scaffold_alignment>` — supersede the customization enumeration so acknowledged locked-slot insert-only extensions (no SCHEMA bullet; visible on the acknowledged channel) and `- Declared boilerplate:` regions sit beside configured domain, tag taxonomy, declared custom fields, user-added page types, and page-check exclusions as wiki-owned customizations preserved on top of the canonical baseline; supersede any reading that scaffold alignment requires verbatim locked-slot equality.
   - `<scaffold_alignment_is_in_scope>` — supersede the "bring the scaffold forward to match" passage so convergence is additive and does not strip acknowledged locked-slot extensions or declared-slot regions; extend the preservation list with those two locked-slot routes alongside domain, tag taxonomy, declared custom fields, user-added page types, and page-check exclusions.

5. **Report a divergence worth promoting.** Extend `<verify_output>` in [agents/auto_shaper_wiki.md](../plugins/knowledge_management/agents/auto_shaper_wiki.md) so the verify-phase final report names any declared-slot deviation the agent judges generally applicable as a candidate for the shipped template. That is a report line under `<verify_output>`, not an edit: the agent does not modify the templates in this repo from inside a managed wiki. This closes the other half of the gap, since a refinement that only ever lives in one wiki's declaration is invisible to every other wiki generated from the same template.

6. **Teach the workflow once.** Supersede stale always-warn boilerplate prose in [references/lint_checks.md](../plugins/knowledge_management/skills/wiki/references/lint_checks.md): rewrite the `boilerplate` table row so insert-only locked-slot additions are classified as extensions on the acknowledged channel (not a live warn), delete/replace divergences remain warn with both remedies named, and matching `Declared boilerplate:` honours follow **Honour the declaration in the runner.**; update the **warn** severity-bucket bullet so verbatim-boilerplate mismatches are live warn only for delete/replace (not insert-only extensions); supersede `## Iteration loop` so its "If a check is wrong" / `ACKNOWLEDGED` passage names the same three non-overlapping structural routes as the `<inline_iteration_loop>` rewrite in this step (`- Accepted finding: …` for info-level findings only; acknowledged insert-only locked-slot extensions with no SCHEMA bullet; `- Declared boilerplate: …` for intentional locked-slot remove-or-rewrite divergences) instead of reading Accepted-finding-only. In [skills/wiki/SKILL.md](../plugins/knowledge_management/skills/wiki/SKILL.md), supersede `<narrow_inline_checks>` so the warn bucket no longer lists every verbatim-boilerplate mismatch unconditionally — name insert-only extensions as acknowledged-channel and delete/replace as warn — and supersede `<inline_iteration_loop>` so its "check is wrong" / `ACKNOWLEDGED` passage names all three non-overlapping structural routes (`- Accepted finding: …` for info-level findings only; acknowledged insert-only locked-slot extensions with no SCHEMA bullet; `- Declared boilerplate: …` for intentional locked-slot remove-or-rewrite divergences) instead of reading Accepted-finding-only. Document each locked-slot route's boundary against the info-level acceptance store and the `Page-check exclusions:` walk exclusion so the three mechanisms do not read as alternatives for one another.

7. **Refresh interim Layer 2 owner-extension contracts.** Rewrite [tests/wiki/layer2/evals.json](../tests/wiki/layer2/evals.json) scenarios AS-15, AS-17, and AS-18 in place: each description currently treats a leftover live `boilerplate` warn on the owner insert-only preamble line as expected (AS-15 names this task as the deferred owner of that classification). After **Make the check classify instead of demanding verbatim restoration.** ships, that interim contract is false — insert-only owner extensions leave no live `boilerplate` warn. Supersede those description passages so they state that the owner insert-only line is an acknowledged locked-slot extension (no live `boilerplate` warn for that class), while keeping each scenario's additive ensure/refresh `log.md` postconditions and grading boundary unchanged.

**Out of scope:** widening the acceptance store to warn-level findings generally, which stays with [wiki_lint-accepted-info-suppression.md](archive/wiki_lint-accepted-info-suppression.md) and its `SEV_INFO` boundary. Deciding which slots stay locked, which stays with [wiki_schema-template-generalization.md](archive/wiki_schema-template-generalization.md). Propagating a landed template change into wikis that already exist, which rides the scaffold restore path that [wiki_log-scope-wiki-changes-only.md](wiki_log-scope-wiki-changes-only.md) exercises and confirms; here the declaration is only what keeps a refinement alive in the wiki that has it while it is still local.
