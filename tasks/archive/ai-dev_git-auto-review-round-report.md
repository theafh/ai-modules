# Make git_auto_review's report.txt state each round's outcome, what was left unapplied and why, and the final state

## Goal

`git_auto_review`'s terminal `report.txt` answers three questions in plain terms: what each round did, which findings the run left unapplied and why, and what state the working tree is in when the run stops. It carries only the blocks that have content. A finding fixed in an earlier round reads as fixed, and the current "did not fix" umbrella never covers it.

## Context

The confusing output has two sources in the skill's report contract. The `<relay>` paragraph at [the git_auto_review skill](../../../plugins/ai_dev/skills/git_auto_review/SKILL.md) says `report.txt` carries "one line per finding the run did not fix", while `<convergence>`'s reporting sentence in the same file requires every gate-listed finding that does not qualify, a tag-excluded `closed` or `settled by a decision` finding included, to be listed with its lane and no fix. A finding fixed in round 1 and re-tagged `closed` by round 2's delta gate therefore lands under a "did not fix" heading even though the run fixed it. The report has no per-round record to say so.

The same contract prescribes no format. `<output_contract>` says the deliverable is `report.txt` "written to the relay and reprinted to the caller", and the `<report>` step says to reprint it, while `auto_gate_git` returns its gate report as Markdown. The loop's own report inherits Markdown-looking output without a stated choice.

The deterministic harness reads this file: [grade.sh](../../../tests/git_auto_review/evals/grade.sh) resolves `report.txt` and asserts properties on it, and [evals.json](../../../tests/git_auto_review/evals/evals.json) names the report assertions each scenario checks.

## Approach

Rewrite the `<relay>` report contract and the `<convergence>` rendering sentence so `report.txt` carries three blocks in this order, each emitted only when it has content and each introduced by its exact label line:

- `per-round record`: one line per round that reaches its Close step, step 12, an early-close case included, so a round the run stops inside — a helper failure, a second ledger failure, or a second unmapped hunk — gets no line; `ledger` and `delta-audit` name that round's final outcome after any restore-and-retry, and `not-run` where an early close skipped the check. Fields in this order separated by ` | `: `round <n> | review <first|delta> | decision <continue|stop> | qualifying <id[,id]|none> | triage <id=approved|id=not-approved: reason|none> | fixes <id=path[,path]|none> | ledger <pass|fail|not-run> | delta-audit <pass|fail|unmapped|not-run>`. With two approved findings the round-1 line reads `round 1 | review first | decision continue | qualifying 1,2 | triage 1=approved;2=approved | fixes 1=report.py;2=notes.md | ledger pass | delta-audit pass`.
- `not-applied record`: one line for every finding the run left unapplied at the stop, plus one line for each finding an earlier round fixed that the stopping round's gate re-lists as `closed` or `settled by a decision`. Fields in this order separated by ` | `: `<id> | <heading> | <location> | <lane> | <reason class> | earlier-fix <round n|no>`, where the reason class is one of a follow-up task proposal, `lane-excluded`, `tag-excluded (closed)`, `tag-excluded (settled by a decision)`, `triage-not-approved` with the verifier's reason, `charter-set-refused`, `decision-pending` naming the pending decision entry, or `stop-unlanded (<stop condition>)` naming the `stop` field's label from the `final-state block` below for a finding whose approved fix a Restore undid or a stop condition ended the round before it landed. This list is exhaustive over the membership clause.
- `final-state block`: one line, fields in this order separated by ` | `: `stop <condition> | files-changed <path[,path]|none> | pending-decisions <wording|none>`, where `files-changed` names the net working-tree files the run changed at the stop, and `stop` carries the condition's existing label in plain text, never a paraphrase of the Stop rule's prose: `spawn-failure`, `mid-run-death`, `contract-violating`, `declared-inability`, or `helper-script` for a helper failure under `<agent_failure_policy>`; `round cap` for the cap; `a decision is pending`; `no qualifying finding remains`; `the approved set is empty`; `two consecutive rounds whose qualifying findings all sit in code the loop wrote in an earlier round`; `a second Regression ledger failure`; `a second audit-delta unmapped-hunk result`; `a concurrent modification`; and `a CHARTER-before-write refusal`. Name `<agent_failure_policy>`, `<charter_before_write>`, and `<initialise>` as edit sites whose `report.txt` "stop line" passages point at this `stop` field.

State the format explicitly in `<output_contract>`: plain text with one record per line, the ` | ` field separator, the `;` separator between entries within a field, and the `,` separator inside an id or path list, with a literal ` | ` or `;` inside free text escaped as `\|` or `\;`, so the file and its reprint read the same and no Markdown rendering is implied. Omit an empty block rather than printing it with a `None.` placeholder.

Keep the `closed` tag semantics in `auto_gate_git` unchanged; the report layer carries the earlier-fix fact. Update the `<convergence>` sentence that requires listing a non-qualifying finding so it points at the `not-applied record` and names the `earlier-fix` clause for a `closed` or `settled by a decision` re-list instead of folding every such finding into "did not fix".

Extend the existing behavioral evals instead of adding scenarios. `fixes_in_scope_bug` already stages round 1's fix and round 2's delta verdict that re-tags finding 1 `closed` (`tests/git_auto_review/evals/fixtures/fixes_in_scope_bug/gate-r2.txt`), and `stops_on_clean_first_gate` already stages the clean round-1 verdict. Add the report assertions to their existing `grade.sh` arms with the `has_line` helper: the `fixes_in_scope_bug` arm asserts the `per-round record` label line, a `round 1` line carrying `fixes` and `report.py`, a `not-applied record` line carrying `tag-excluded (closed)` and `earlier-fix round 1`, and a `final-state block` line carrying the stop condition and the changed files; the `stops_on_clean_first_gate` arm asserts the `per-round record` and `final-state block` label lines with a `round 1` line, and asserts no `not-applied record` line and no `None.` placeholder. In `routes_decision`'s arm, assert a `not-applied record` line carrying `report.py:3` and `decision-pending`, and replace the arm's whole-text `adjustment` check with a `has_line` assertion that the `final-state block` line carries `pending-decisions` and `adjustment`; in `stops_on_second_ledger_fail`'s arm, assert a `not-applied record` line carrying `alpha.py:2` and `stop-unlanded`, and assert with the `has` helper that the report carries no `per-round record` label line, because the fixture's ledger failure stops the run inside round 1, before that round reaches Close, so the staged `gate-r2.txt` at `beta.py:2` is never consumed; in `restores_stray_fixer_path`'s arm, retag finding 1 in `tests/git_auto_review/evals/fixtures/restores_stray_fixer_path/gate-r2.txt` from `closed` to `settled by a decision` in its prose sentence and its `tag:` line, reword the prose sentence to state the decision that settled it, update the matching comment in that fixture's `setup.sh`, and assert a `not-applied record` line carrying `tag-excluded (settled by a decision)` and `earlier-fix round 1`. Update the rows for those five evals in `tests/git_auto_review/evals/README.md`'s signal table , and in `tests/git_auto_review/RUNBOOK.md`'s `## Session measurement log` update the existing rows for `fixes_in_scope_bug`, `stops_on_clean_first_gate`, and `routes_decision` and add rows for `stops_on_second_ledger_fail` and `restores_stray_fixer_path`, and keep `evals.json`'s scenario set unchanged. These are behavioral evals, so `make test` and `tests/git_auto_review/script_tests/run.sh` do not execute them: pin the new contract strings on the deterministic surface by extending `s4_convergence_labels_single_source` in `tests/git_auto_review/script_tests/run.sh` with `assert_contains` checks for the three block labels, the `earlier-fix` clause, and the `decision-pending` and `stop-unlanded` class tokens, and `s5_carryover_blocks` with the `<output_contract>` plain-text, one-record-per-line sentence, the `;` entry separator, and the `qualifying 1,2`, `triage 1=approved;2=approved`, and `fixes 1=report.py;2=notes.md` fragments.

Follow the standing repo rules' version-bump discipline for the `ai_dev` plugin in the implementing commit.

**Out of scope:** Changing what `git_review` reports or how `auto_gate_git` assigns tags; those contracts stay as written.

## Acceptance

- The `<relay>` paragraph and the `<convergence>` sentence in `plugins/ai_dev/skills/git_auto_review/SKILL.md` define the `per-round record`, `not-applied record`, and `final-state block`, name the `earlier-fix` clause and the `closed` or `settled by a decision` re-list, and state the `decision-pending` and `stop-unlanded` classes; the report contract no longer uses "did not fix" as the umbrella over a `closed` finding. A grep for those exact strings returns them, and the old phrase is absent from the report contract. The `<relay>` `final-state block` sentence carries the plain-text labels `spawn-failure`, `mid-run-death`, `contract-violating`, `declared-inability`, `helper-script`, `round cap`, `a decision is pending`, `no qualifying finding remains`, `the approved set is empty`, `loop wrote`, `ledger`, `unmapped`, `concurrent`, and `CHARTER`, and `<agent_failure_policy>`, `<charter_before_write>`, and `<initialise>` each point their `report.txt` stop-line sentence at the `stop` field; a grep returns each.
- `tests/git_auto_review/evals/evals.json` keeps its scenario set unchanged, and the `fixes_in_scope_bug`, `stops_on_clean_first_gate`, `routes_decision`, `stops_on_second_ledger_fail`, and `restores_stray_fixer_path` arms in `tests/git_auto_review/evals/grade.sh` each carry the new report assertions; each has a matching row in `tests/git_auto_review/evals/README.md`'s signal table and a session-measurement row in `tests/git_auto_review/RUNBOOK.md`; `s4_convergence_labels_single_source` and `s5_carryover_blocks` in `tests/git_auto_review/script_tests/run.sh` carry the new `assert_contains` pins for the three block labels, the `earlier-fix` clause, the `decision-pending` and `stop-unlanded` class tokens, the `<output_contract>` format sentence, the `;` entry separator, and the `qualifying 1,2`, `triage 1=approved;2=approved`, and `fixes 1=report.py;2=notes.md` fragments; and `tests/git_auto_review/script_tests/run.sh` passes.
- The `fixes_in_scope_bug` eval produces a `report.txt` whose round-1 record names the fixed finding and whose not-applied record carries a line for that finding, under `tag-excluded (closed)`, whose earlier-fix clause names round 1 as the round that fixed it.
- The `routes_decision` eval produces a `report.txt` whose `not-applied record` line carries the held finding at `report.py:3` with the class `decision-pending`; the `stops_on_second_ledger_fail` eval produces a `not-applied record` line carrying `alpha.py:2` with the class `stop-unlanded`; and the `restores_stray_fixer_path` eval produces a `not-applied record` line carrying `tag-excluded (settled by a decision)` and `earlier-fix round 1`.
- The `stops_on_second_ledger_fail` eval produces a `report.txt` with no `per-round record` label line, because its round stopped before Close, while that round's outcome still appears in the `final-state block`'s `stop` field and its unapplied finding appears in the `not-applied record`'s `stop-unlanded` class.
- The `routes_decision` eval produces a `report.txt` whose `final-state block` line carries the `pending-decisions` field with the pending per-item adjustment decision's wording.
- The `stops_on_clean_first_gate` eval produces a `report.txt` that carries the round-1 per-round record, omits the not-applied block, and prints no empty `None.` placeholder.
- On `fixes_in_scope_bug`, `report.txt`'s round-1 record line names the round number, the first-review kind, the continue decision, the qualifying finding id, the triage decision, the path or paths the fix wrote, and the ledger and delta-audit results, and a round-2 record line names the delta-review kind and the stop decision.
- On `fixes_in_scope_bug`, `report.txt`'s final-state block names the no-qualifying-finding stop condition and the working-tree files the run changed.
- The skill's `<output_contract>` states that `report.txt` is plain text with one record per line, the ` | ` field separator, the `;` separator between entries within a field, and the `,` separator inside an id or path list, with a literal ` | ` or `;` inside free text escaped.
- `python3 tests/git_auto_review/evals/run.py --force fixes_in_scope_bug stops_on_clean_first_gate routes_decision stops_on_second_ledger_fail restores_stray_fixer_path` passes all five runs, one per eval, on the default Cursor `auto` vendor, where a failed or timed-out run fails the item, and each eval's result and date are recorded in its `tests/git_auto_review/RUNBOOK.md` session-measurement row.
