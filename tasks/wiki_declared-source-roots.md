# Let a wiki declare in-repo source roots for `sources:`

## Goal

A wiki whose primary source is a live document tracked in the same repository can cite that document's files in `sources:` frontmatter, structured and lint-validated, without capturing them into `raw/`. The wiki declares each such root once in `SCHEMA.md`, the linter accepts `sources:` entries that resolve under a declared root and inside the repository, reports each declaration on the acknowledged channel so the divergence stays visible, and the `auto_shaper_wiki` agent honours the declaration instead of migrating those entries to `## Derived from`. A wiki that declares nothing keeps today's `raw/`-only contract unchanged.

## Context

The provenance model gives a page two channels and defines each by the object attributed. `sources:` holds sources the wiki captured under `raw/`, validated path by path; `## Derived from` holds "uncaptured external lineage" that is "**not** itself the subject of classification". Both rules sit under the **Cite each source in the channel its object calls for.** and **Record uncaptured external lineage under `## Derived from`.** lead-ins in [template_schema.md](../plugins/knowledge_management/skills/wiki/references/template_schema.md). A third object fits neither definition: a live in-repo document that *is* the subject of classification, a paper, spec, or codebase the wiki exists to explain, which the wiki deliberately does not snapshot because a `raw/` copy of an actively edited source goes stale on the next edit. Such a wiki wants the validation and structure of `sources:`, and it trades mechanical sha256 drift detection for a procedural coherence rule of its own.

The linter cannot express that trade. `check_source_paths_exist` in [lint.py](../plugins/knowledge_management/skills/wiki/scripts/lint.py) blocks any `sources:` entry that "escapes the wiki's `raw/` tree", and the acceptance store cannot clear it because acceptance reaches info findings only. The bound is stricter than the portability goal it serves. [wiki_lint-local-path-portability.md](archive/wiki_lint-local-path-portability.md) set out to stop machine-local paths from passing as provenance, and for the sibling field it chose the right boundary: a raw-sidecar `source_path:` "may point outside the wiki directory but must stay inside the repository", enforced by `check_source_path_portable` through `_git_repo_root`. For `sources:` it enforced the pre-existing "strict `raw/<kind>/<slug>.md` paths" wording instead, and [wiki_origin-field-contract.md](archive/wiki_origin-field-contract.md) later restated the two bounds side by side without a reason for the narrower one. A repo-relative `../paper/ch03.tex` resolves identically on every clone, so it meets the portability goal the rule exists for.

The agent compounds the gap. Its `<read_schema>` step captures only the type enum, custom fields, tag taxonomy, and domain statement; its `<configurable_zones>` lists no source-root declaration; and `<fix_external_source_pointer>` moves every `sources:` entry resolving outside `raw/` into `## Derived from` so the blocking finding "clears". Run on the wiki described above, an audit silently downgrades structured, validated citations into a prose section that receives no lint validation at all. In the motivating downstream wiki, whose repository is the paper it classifies, the earlier alignment audit left every such citation in place and recorded the migration as "a design decision left to the user", by judgment rather than by any guard.

The declaration mechanism this task adds follows the pattern [wiki_sanctioned-template-deviations.md](wiki_sanctioned-template-deviations.md) freezes for locked slots: one labeled `## Lint` bullet, parsed by the fence-safe `iter_lint_section_lines` scan that `load_excluded_roots` and `LINT_ACCEPT_RE` share, honoured by linter and agent alike, and reported with a `(declared)` marker on the acknowledged channel outside the live totals. That task must ship first. It rewrites `<linter_is_truth_for_structure>`, `<inline_iteration_loop>`, and the `## Iteration loop` passage of [lint_checks.md](../plugins/knowledge_management/skills/wiki/references/lint_checks.md) to name three non-overlapping structural routes, and this task extends that enumeration to a fourth, so it edits those passages after they exist in their new form. Two further live tasks share surfaces. [wiki_provenance-via-raw-and-sources.md](wiki_provenance-via-raw-and-sources.md) owns the capture rule and channel boundary inside the template's Provenance block, which this task widens by one object. [wiki_synthesis-citation-consistency-lint.md](wiki_synthesis-citation-consistency-lint.md) classifies an inline citation as a source by its `raw/` prefix, which this task widens to "under `raw/` or under a declared root".

## Approach

1. **Parse the declaration.** Add `load_declared_source_roots(wiki)` to `lint.py` beside `load_excluded_roots`. It reads `## Lint` through `iter_lint_section_lines`, matches the label `Declared source root:` case-insensitively, and left-anchors on ` — ` (the `ACCEPT_SEP` the acceptance bullets use) so the machine key is a wiki-root-relative path and the remainder is a free-text reason. Grammar, frozen: `- Declared source root: <path> — <reason>`, one bullet per root. A root may name a directory or a single file; a file root admits exactly that file. The reason is required and is never matched.

2. **Honour it in `check_source_paths_exist`.** Rewrite the check so a relative `sources:` entry passes when it resolves under `raw/` or under any declared root, and keeps today's behaviour otherwise: an entry resolving under neither stays the blocking `broken-source` "escapes" finding, and an entry under a declared root that resolves to no file is the blocking "missing on disk" finding, exactly as a `raw/` entry is. Bound the roots the way `check_source_path_portable` bounds `source_path:`. When the wiki is inside a git repo, a declared root that resolves outside `_git_repo_root(wiki)`, or to no file or directory, is itself a blocking `broken-source` finding on `SCHEMA.md`, because it would legitimize non-portable entries. When the wiki is not inside a git repo it is local-only, so any root that resolves is accepted. Report each valid declaration once on the acknowledged channel with the `(declared)` marker, naming the root and its reason, never as a live blocking, warn, or info Issue, through the acknowledged return path the sanctioned-template-deviations task wires. Rewrite the `broken-source` messages so the remedy reads "use a `raw/…` path, or declare an in-repo root in `SCHEMA.md`". The absolute-path safe-fix branch is unchanged. Supersede the function docstring in place so one statement of the widened contract remains.

3. **Keep the downstream consumers coherent.** `check_stale_content` keys on `raw/` ingest dates and skips an entry it has no date for, and `check_quality_signals` counts entries regardless of root; confirm both hold for declared-root entries on the fixtures and adjust only if a fixture shows otherwise. The synthesis-citation task's citation set becomes "resolves under `raw/` or under a declared root" rather than a bare `raw/` prefix test; whichever of the two tasks lands second applies that widening.

4. **Teach the agent.** In [auto_shaper_wiki.md](../plugins/knowledge_management/agents/auto_shaper_wiki.md): `<read_schema>` also captures the declared source roots; `<configurable_zones>` lists the `Declared source root:` bullets beside the exclusions and acceptance bullets as wiki-owned; `<external_source_pointer>` classifies a `sources:` entry resolving under a declared root as a declared primary source, neither broken nor external by design; `<fix_external_source_pointer>` leaves such entries in `sources:` untouched and migrates only entries that resolve under no declared root; `<linter_is_truth_for_structure>`, `<scaffold_alignment>`, and `<scaffold_alignment_is_in_scope>` name the declaration as a fourth non-overlapping structural route and add it to their preservation lists. A declared source root describes one wiki's repository layout, so `<verify_output>` does not report it as a candidate for the shipped template.

5. **Teach the skill and the references.** In [SKILL.md](../plugins/knowledge_management/skills/wiki/SKILL.md), rewrite the **Provenance** bullet and `<inline_iteration_loop>` in place so they name the fourth route and the third object. In `lint_checks.md`, rewrite the `broken-source` row, the **blocking** line of `## Severity buckets`, and `## Iteration loop` in place to the widened contract. In `template_schema.md`, add a fenced `Declared source root:` example in `## Lint` beside the `Page-check exclusions:` example, and rewrite the two Provenance lead-in bullets so the object split reads: a source captured under `raw/`, cited in `sources:`; a live in-repo document that is the subject of classification, cited in `sources:` under a declared root, carrying no sha256 drift detection and relying on a coherence rule the wiki states; uncaptured lineage that is not the subject of classification, recorded in `## Derived from`. Compose the Provenance rewrite with the provenance task named in `## Context`, whichever lands second rewriting over the first.

6. **Prove it.** Layer 1 fixtures in [tests/wiki/layer1/run.sh](../tests/wiki/layer1/run.sh): a wiki inside a scratch git repo with a sibling directory outside the wiki, a declared root naming it, and a page citing a file under it lints with no `broken-source` finding and one `(declared)` acknowledged line; the same page with the bullet removed draws the blocking "escapes" finding unchanged; a declared root resolving outside the scratch repo draws the blocking finding on `SCHEMA.md`; an entry under a declared root naming a missing file draws "missing on disk"; a file root admits only that file. A Layer 2 scenario in [tests/wiki/layer2/evals.json](../tests/wiki/layer2/evals.json): an audit of a wiki with a declared root leaves every declared-root `sources:` entry in frontmatter, creates no `## Derived from` bullet for them, and re-lints clean.

**Out of scope:**

- A new frontmatter field such as `primary_sources:` for the third object; the declared root carries the distinction with no new key.
- Widening the `raw/`-only default for a wiki that declares nothing.
- Migrating any downstream wiki's citations; each wiki declares its own roots.

## Acceptance

- `lint.py` carries `load_declared_source_roots` reading `Declared source root:` bullets from `## Lint` through `iter_lint_section_lines`, and `check_source_paths_exist` accepts a relative `sources:` entry that resolves under `raw/` or under a declared root; the fixture wiki with a declared sibling root lints with zero `broken-source` findings and one `(declared)` acknowledged line naming the root and reason.
- Removing the declaration from that fixture restores the blocking "escapes the wiki's `raw/` tree" finding, and a fixture wiki with no declaration lints exactly as before this task.
- A declared root resolving outside the fixture's git repo, or to nothing, draws a blocking `broken-source` finding on `SCHEMA.md`; an entry under a valid declared root naming a missing file draws the blocking "missing on disk" finding; a file root admits that file and rejects its siblings.
- The `broken-source` message names both remedies, a `raw/…` path or a declared in-repo root, and the `check_source_paths_exist` docstring states the widened contract once with the `raw/`-only wording superseded.
- `<read_schema>`, `<configurable_zones>`, `<external_source_pointer>`, `<fix_external_source_pointer>`, `<linter_is_truth_for_structure>`, `<scaffold_alignment>`, and `<scaffold_alignment_is_in_scope>` in `auto_shaper_wiki.md` each name declared source roots per **Teach the agent.**, and `rg "Declared source root"` over the agent file finds each site.
- The Layer 2 scenario passes: after an audit, every declared-root `sources:` entry remains in frontmatter and no `## Derived from` bullet was created for it.
- The `broken-source` row and **blocking** bucket line in `lint_checks.md`, its `## Iteration loop`, the SKILL.md **Provenance** bullet and `<inline_iteration_loop>`, and the two `template_schema.md` Provenance lead-in bullets each state the widened contract with the prior `raw/`-only passage superseded, and `template_schema.md` `## Lint` carries the fenced `Declared source root:` example beside the exclusions example.
- `tests/wiki/run_all.sh` passes with the new fixtures and scenario.
