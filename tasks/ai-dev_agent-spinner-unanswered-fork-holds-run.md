# Make an unanswered agent_spinner fork hold the run open

## Goal

A decision the run routes to the user stays open until the user answers it. Plain `close` refuses while such a fork or gate is unanswered, and on a host with no later turn the run ends through `stop` and `close --stopped` with its decision packet, the way SKILL.md `<judgement>` already says. The skill names the ledger record for a fork the orchestrator raises itself, such as a widening, an estimate above the stated guideline, or a scope question. Nothing in the run can settle the fork in the user's place: not a completion goal waiting for a clean close, and not the orchestrator answering its own gate.

## Context

All paths are under `plugins/ai_dev/skills/agent_spinner/`.

- **`close` lets a surfaced fork pass.** SKILL.md `<judgement>` says to "keep each open in the ledger until answered" and that "an unanswered gate ends the run with its decision packet: run `stop` so `STOP` is written, then `close --stopped`". But `cmd_close` in `scripts/run_ledger.py` raises condition 6 only for a fork that is "neither surfaced nor decided" and for an unanswered `user_gate`; a fork disposed as `surfaced` passes. `references/run-protocol.md`'s close condition 6 says the same ("A fork is neither surfaced nor decided, or a user gate is unanswered"), and `show --packet` renders a packet only for a surfaced fork. So the documented way to render a packet leads straight to a clean close.
- **No record for a fork the run raises itself.** SKILL.md names `dispose --open-gate` only for disagreeing returns, and `references/recipes/prose-sweep.md` names it only for recording an approval. In the 2026-11-14 evening Claude run, `widening_needs_estimate_and_ask` made the 40 requested edits, raised the widening to the other 60 pages as a surfaced fork, and closed cleanly with no gate and no STOP; earlier Claude and Cursor runs opened a gate before dispatch and stopped with `close --stopped`.
- **A goal and a self-answer settled a gate.** SKILL.md `<run_state>` has the orchestrator arm a host completion goal where the host offers one. In the Cursor run of `unanswered_gate_stops_with_packet`, the worker first stopped correctly with the full packet and `close --stopped` exiting 3, but the goal it had armed waited for `close` to exit 0, which a stopped run never does. The goal kept the turn going, and the worker then answered its own gate, citing "An answer the request states is the user's answer" although the request asked for the decision to come back unanswered, closed with exit 0, and rewrote the report without the packet.

[The report-and-packet task](archive/ai-dev_agent-spinner-report-packet-enforcement.md) makes packets carry anchored passages and edits `scripts/run_ledger.py` and `references/run-protocol.md` too. The terminal-states, brief-contract, and report-and-packet tasks land before this one; this one lands before the stamped-write-routing, coverage-gates, and record-completeness tasks, which edit the same files.

## Approach

1. In `cmd_close`, make condition 6 refuse a fork that carries a `surfaced` disposition and has no answer record — the `any(...)` test `close_open_items` already computes over `dispositions()`, not an all-dispositions test, so a fork disposed `surfaced` and later `applied` still blocks — the same way it refuses an unanswered gate. `close --stopped` does not exempt condition 6: it refuses with exit 3 as well and lists that fork among the stop's open decisions. Keep the own-authority exemption for a fork the run never surfaced: an `own_authority` record clears condition 6 only for a fork that carries no `surfaced` disposition, so `ledger_run.sh`'s existing `c6fork` assertion stays green while a fork the run surfaced cannot be settled in its own place. An answer record is a `gate_answered` record whose `gate_id` names the fork's gate id, or, for a `surfaced` disposition, the `packet` id that disposition carries — the two keys `open_gates()` and `open_packets()` already compare; it is written by the existing `dispose --gate <id> --answered <text>`, so the answer side needs no new verb. Rewrite `references/run-protocol.md`'s condition 6 in place to match. Also rewrite `tests/agent_spinner/script_tests/ledger_run.sh`'s `scenario_objection_close`, which surfaces `produce:a:forks:0` and then asserts plain `close` exits 0 once only the objection is disposed: assert the condition 6 refusal while that fork is unanswered, and reach exit 0 only after the fork is answered and the objection is disposed.
2. In SKILL.md `<judgement>`, state that a fork the orchestrator raises itself (a widening, an estimate above the stated guideline, a scope question) is recorded as a fork and a user gate before any write it would govern, through `dispose --open-fork ID --issue TEXT --question TEXT`, a verb this step adds to `dispose` in `scripts/run_ledger.py`: it writes a `fork` record (`type`, `id`, `issue`, empty `options`, `passages`, and `preferred`) and a `user_gate` under the same `ID` in one call, takes repeatable `--option ID=TEXT` and `--passage TEXT` to fill the packet body, and refuses an `ID` the ledger already holds. The open `user_gate` holds writer dispatch, and the `fork` record is the one `render_packet` looks up by `id` once the run disposes that `ID` `surfaced` with `--packet`. In the same block, use one term for the open decision in the no-later-turn sentence. Rewrite the matching passages in `references/run-protocol.md` (the P1 announcement and gate steps, the P6 checks, and the `### dispose` command reference) and, in every recipe whose `<stop_and_ask>` carries the sentence "An answer the request states is the user's answer" — all eight files under `references/recipes/` (`artifact-repair.md`, `check-only-audit.md`, `disputed-claim.md`, `fidelity-review.md`, `multi-file-task.md`, `option-panel.md`, `prose-sweep.md`, `research-synthesis.md`) — rewrite that sentence in place, and update the `stop_and_ask` entry in `RECIPE_SHARED_LINES` (`tests/agent_spinner/script_tests/run.sh`) to the replacement sentence in the same edit.
3. In SKILL.md `<run_state>` and `references/run-protocol.md` P4, make an armed completion goal's condition one a stopped run can meet, such as `close` or `close --stopped` exiting as the run's end requires, and say that a goal never answers a gate. P4's sentence "arm one goal per run, with the run directory in its objective and `close` exiting 0 as its completion condition" is the second copy of that rule and takes the same condition, rewritten in place. In the same `<run_state>` block, name an open surfaced fork as a third reason the turn continues and a third state it may end in: the continuation sentence adds the unanswered surfaced fork beside the open gate, and the turn-end sentence admits the interim report while a surfaced fork awaits its answer.
4. In SKILL.md `<judgement>`, rewrite the sentence "An answer the request states is the user's answer." in place — it is the licence the incident cites — to state that a request answers a fork only where it decides that fork in so many words, and that a request asking for the decision to come back leaves the fork for the user, so the old sentence stands nowhere in `SKILL.md` afterwards.
