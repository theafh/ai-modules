# Catch stray fixer files in git_auto_review mechanically

## Goal

After a `git_auto_review` run, the working tree holds the change under review, the fixes the run approved, and the run's own ignored `.git_auto_review/` folder. Every other file the fixer creates, including one in a path the repository ignores, is caught: it shows up in the round's delta audit, the loop removes it on restore together with any folder it created, and the run's records name it, while a pre-existing ignored file stays in place. A bundled script, script tests, and a behavioral eval carry that guarantee. The loose reproduction scripts under this repository's `tests/` tree become harness scenarios or are deleted.

## Context

Each round, `auto_fixer_git` writes a reproduction: a small script that fails before its fix and passes after it. The run keeps these scripts directly in its own folder, `.git_auto_review/<run-stem>/` (the skill calls that folder the relay), as `reproduction-r<round>-finding-<id>.<ext>` files beside `gate-r<round>.txt` and `ledger.txt`. That folder carries its own `.gitignore` with the single line `*`, and each new run clears it. The `<relay>` paragraph beginning "`reproduction-r<round>-finding-<id>.<ext>` holds the file reproduction" in `plugins/ai_dev/skills/git_auto_review/SKILL.md` states the rule.

The naming rule covers reproductions. Four parts of the loop decide whether any other fixer file gets caught, and each one is prose or a partial check today:

- **The round diff is orchestrator prose.** The `<relay>` paragraph beginning "`round-r<round>.diff.txt` holds the round's fixer-write diff" asks the orchestrator to diff "the round's pre-fix snapshot against the current working tree" with `diff -U0` and leaves the method to each run. Whether a new untracked file appears in that diff therefore depends on the run, and `auto_verifier_git`'s delta mode marks `unmapped` exactly what appears there.
- **Restore removes files and keeps their folders.** `scripts/run_restore.sh` deletes "the untracked files the fixer added that the copy does not contain" with `rm -f`, so a folder the fixer created stays on disk, empty, after a restore.
- **The unmapped-hunk evals stage a verifier verdict.** `retries_once_on_unmapped_hunk` and `stops_on_second_unmapped_hunk` in `tests/git_auto_review/evals/evals.json` tell the verifier through an environment note to mark one hunk `unmapped`, and their `grade.sh` arms check the delta mapping, the stop line, and `HEAD`. `tests/git_auto_review/evals/grade.sh` already reads one stage-time record (`.index.before`, through `index_unchanged`), which is the shape a stage-time list of untracked files can follow.
- **Loose reproduction scripts sit under `tests/`.** `git ls-files 'tests/*/script_tests/repro*'` lists reproduction scripts that earlier runs left in this repository, and each one runs only when someone calls it by hand.

`task_auto_check`'s `stray_hunk_reverted` eval in `tests/task_auto_check/evals/evals.json` is the in-repo precedent for planting a stray writer edit through an environment note and grading that the loop reverted it.

[The inert-worker grader task](tests_eval-graders-bite-on-inert-worker.md) also edits `tests/git_auto_review/evals/grade.sh` and adds a scenario to `tests/git_auto_review/script_tests/run.sh`. The two tasks add separate arms and scenarios, so whichever lands second adds its own beside the other's.

## Approach

1. **Script the round diff.** Add `scripts/run_round_diff.sh` beside the other bundled scripts. Rewrite each place that states the bundled-script count in place so it names five scripts and lists `run_round_diff.sh` beside the four: the `git_auto_review/` bullet in `tests/README.md`, the `git_auto_review/` row of the **What's here** table in `tests/CLAUDE.md`, the opening sentence and the `script_tests/` row of `tests/git_auto_review/README.md` (where `run_round_diff.sh` gains its own clause for the scripted round diff over the pre-fix state), the sentence naming the deterministic surface in `tests/git_auto_review/evals/README.md`, and the header comment of `tests/git_auto_review/script_tests/run.sh`, whose script list gains a `run_round_diff.sh` line. It takes `--stem`, `--round`, and `--root` like its siblings and uses their exit codes (`0` written, `1` usage error, `2` environment error). It rebuilds the round's pre-fix state from `pre-fix.patch`, `pre-fix.untracked.tar`, and `pre-fix.ignored.manifest`, the NUL-delimited records of ignored file paths, each followed by its content hash, that `run_snapshot.sh` writes for the ignored files outside the run's `.git_auto_review/` folder and outside the harness run-output trees the `**Out of scope:**` block names, the same way the **Stop rule.**'s "Materialize and diff." case rebuilds the baseline. It then compares that state with the working tree over the union of the paths `git status --porcelain -z --untracked-files=all` and `git ls-files --others --ignored --exclude-standard -z` list now and the members of `pre-fix.untracked.tar`, read as NUL-separated records, dropping the run's `.git_auto_review/` folder and the harness run-output trees — the tracked, untracked, and ignored file set the snapshot, the concurrent-modification guard, and Restore read. A path whose content is binary — a NUL byte or bytes that are not valid UTF-8 — carries a path-only hunk in place of the whole-file addition or tracked hunk its path kind gives it: a `diff --git a/<path> b/<path>` header followed by `Binary files /dev/null and b/<path> differ` for a file the fixer added and `Binary files a/<path> and b/<path> differ` for a tracked file it modified, with no file content, so `round-r<round>.diff.txt` stays valid UTF-8 for every path kind and `auto_verifier_git` maps the hunk by path like any other. For a tracked or untracked file the fixer added, the diff carries one whole-file addition, and for one it deleted, one whole-file removal; for an ignored path, the diff reports only a path present now but absent from the manifest, as one whole-file addition (or, for an ignored path whose content is binary — a NUL byte or bytes that are not valid UTF-8 — a path-only hunk instead: a `diff --git a/<path> b/<path>` header followed by `Binary files /dev/null and b/<path> differ`, with no file content, so `round-r<round>.diff.txt` stays valid UTF-8 and `auto_verifier_git` maps the hunk by path like any other), because a pre-existing ignored file's content is not captured and the file stays as the fixer left it. It writes `round-r<round>.diff.txt` into the run's folder as a `diff -U0`, in which a file the fixer added appears as one whole-file addition and a file it deleted as one whole-file removal. Git ignores the run's `.git_auto_review/` folder, so the diff covers the working tree around it. Each round's ledger check adds no bytecode cache to that path set. Edit `scripts/run_ledger.sh` so `main` exports `PYTHONDONTWRITEBYTECODE=1` once, before its `while IFS= read -r line` loop, so every line's `bash -c` inherits it, and record the export in the script's header comment, stating that each ledger command runs with bytecode writing off; a Python reproduction that imports the repository module it exercises then leaves no `__pycache__/<module>.cpython-*.pyc` for the diff to carry.
2. **Point the skill and the delta verifier at the scripted diff.** Rewrite the `<relay>` paragraph beginning "`round-r<round>.diff.txt` holds the round's fixer-write diff" so that paragraph is the one statement of how the file is written, its one instruction for writing it being to run `scripts/run_round_diff.sh`. Add the script to the signal list of `<agent_failure_policy>`'s `helper-script` class beside `scripts/run_snapshot.sh`. In `<audit_delta>`, replace its own write recipe with a pointer to that paragraph, so the block's opening reads: "After every fix round, write `round-r<round>.diff.txt` under `<relay>` as the `<relay>` paragraph on that file states, then invoke `auto_verifier_git` in delta mode." Then rewrite `plugins/ai_dev/agents/auto_verifier_git.md` so a path-only entry — one that names a path with no `@@` range and no changed lines, the form `scripts/run_round_diff.sh` writes for a binary file — maps like any other entry. Its `description:` delta clause, its `<objective>`, its delta `<policy>` rule, and its `<output_contract>` delta shape each speak of an entry as a hunk or a path-only entry; the policy rule maps a path-only entry `reproduction` when its path lies in a reproduction path `ledger.txt` names and `unmapped` when its path belongs to no approved fix and no reproduction; and the output contract gives each path-only entry its own block in file order, with the `hunk:` key carrying the path alone in place of an `@@` range. Keep the block's restore-and-retry as it stands: a stray file now reaches delta mode as its own hunk or path-only entry, the verifier marks that entry `unmapped`, and the existing retry and stop apply.
3. **Snapshot and restore ignored paths, and remove the folders Restore empties.** Extend `scripts/run_snapshot.sh` to write `pre-fix.ignored.manifest`, the same path-plus-hash record set over the ignored files outside the run's `.git_auto_review/` folder and outside the harness run-output trees the `**Out of scope:**` block names, enumerated with `git ls-files --others --ignored --exclude-standard -z`, beside the existing pair, and extend `scripts/run_restore.sh` to delete the ignored files the fixer added that the manifest does not contain, the same way it handles untracked files, leaving every pre-existing ignored file in place. The restore's ignored enumeration drops every record under the run's `.git_auto_review/` folder and under the harness run-output trees, the same exclusion the manifest and the round diff apply, so the relay files — `pre-fix.patch`, `pre-fix.untracked.tar`, `pre-fix.ignored.manifest`, `ledger.txt`, and the gate returns — never count as fixer-added and stay on disk, as `<regression_ledger>`'s "A restore leaves the relay as it is" and `<concurrent_modification_guard>`'s "a restore never deletes a run file" require. After deleting each fixer-added file, it also removes every parent folder the deletion left empty, up to and including the top-level folder under the repository root. Update both scripts' header comments and `--help` text, and update every skill passage that enumerates the per-round files, the path set, and the Restore steps — the `<relay>` file tree, Close case 4, the `<snapshots>` opening sentence and its file list and **Restore.** paragraph, and the `<concurrent_modification_guard>` parenthetical — so each names `pre-fix.ignored.manifest`, the ignored file set, the ignored-file deletion, and the relay folder and harness run-output trees that enumeration leaves alone.
4. **Run every reproduction with bytecode writing off.** Add a `<policy>` rule to `plugins/ai_dev/agents/auto_fixer_git.md` that runs each reproduction it writes or extends with bytecode writing off, by exporting `PYTHONDONTWRITEBYTECODE=1` for that run or invoking the interpreter with `-B`, and states the reason `git_review`'s `<leave_the_tree_alone>` gives for its own reproductions: a run inside the repository leaves compiled bytecode behind, so the run suppresses that byproduct and leaves the path sets the round diff reads as it found them. The rule sits beside the existing rule that writes each reproduction to run from the repository root, so the reproduction still runs there and only its byproducts change.

5. **Plant a stray file in an eval.** Add `restores_stray_fixer_path` to `tests/git_auto_review/evals/evals.json`, with a fixture under `evals/fixtures/` and an arm in `grade.sh`, modelled on `stray_hunk_reverted` and on the pre-seeded shape of `retries_once_on_unmapped_hunk`. Its environment note addresses the run's orchestrator and names it as the planter, because `auto_fixer_git` otherwise writes only the approved path sets and a licence alone cannot make the helper write: under the fixture's licence the orchestrator writes `stray/new/added.txt` holding `stray`, one extra file inside a new folder at the repository root and outside every approved `Fix:` path, and `__pycache__/added.txt` holding `stray`, one extra file inside the fixture's ignored `__pycache__/` folder, and `__pycache__/blob.bin` holding a NUL byte and a byte that is not valid UTF-8, one binary file in that same ignored folder. Those writes land after round 1's `auto_fixer_git` returns its write and before the round diff is written, the window `<relay>` gives the diff, so the concurrent-modification guard's pre-invocation check has already passed and the two paths reach the round diff as fixer writes. The note continues the run after those writes, and the retry writes only the approved fix. `init_repo` in `evals/fixtures/_common.sh` stays untouched because it seeds every fixture; the new fixture's `setup.sh` writes the fixture-local `.gitignore` naming `__pycache__/` and `ignored/`, plants the pre-existing ignored file `ignored/keep.txt` that must survive, and leaves the orchestrator to add `__pycache__/added.txt` as a second ignored file that must be caught. Because the eval runs a restore-and-retry, add its id to `SERIAL_NESTED_LOOP_IDS` in `tests/git_auto_review/evals/run.py` and to the `git_auto_review` serial nested-loop list that `tests/CLAUDE.md` and `tests/AGENTS.md` both carry. Add its row to the **Signal per eval** table in `tests/git_auto_review/evals/README.md`, recording the evidence Acceptance 4 grades.
6. **Grade that the tree is clean after a run.** Have `evals/stage.sh` write the fixture's stage-time path record to `<target>/.paths.before`, beside `.index.before` and in the same shape: the NUL-delimited tracked, untracked, and ignored paths that `git ls-files -z` and the two `git ls-files --others` enumerations (`--exclude-standard -z`, and `--ignored --exclude-standard -z`) list, with the run's `.git_auto_review/` folder dropped. That record is the one statement of the stage-time set; the round diff reads the run's own snapshot files as step 1 states. Add a `grade.sh` helper that passes only when every path those three enumerations list after the run, with the run's `.git_auto_review/` folder dropped, is in that record, is written by the eval's approved fix, or lies under a path the per-pass micro-deployment in `tests/lib/micro_deploy.py` writes into the sandbox project (on Cursor, the `auto_*_git` agent copies under `.cursor/agents/`), because those files land after stage time. Have the runner in `tests/git_auto_review/evals/run.py` set `PYTHONDONTWRITEBYTECODE=1` on `deploy.env` beside the `TMPDIR` assignment `_apply_job_temp` makes, before it calls `micro_deploy.run_worker`, so every `python3` the worker or its spawned fixer runs inside the sandbox — the reproduction that imports `report.py` included — writes no `__pycache__`; the helper then keeps its strict set with no `__pycache__` allowance, and the new fixture's `__pycache__/` folder holds only the planted files, so Restore removes it. Call the helper from every arm that calls `reproductions_in_relay` and from the new arm.
7. **Resolve the loose reproduction scripts.** For each file `git ls-files 'tests/*/script_tests/repro*'` lists, compare what it checks with its harness's `script_tests/run.sh` scenarios and eval grader arms. Turn a script whose check is that harness's only coverage of the behaviour into a scenario in that harness's `script_tests/run.sh`, then delete every listed file, so the command's output is empty. Before deleting anything, run the selector and record its output in `tests/repro_dispositions.md`, one line per path naming the scenario it becomes in that harness's `script_tests/run.sh`, the eval grader arm that covers it, or the existing scenario whose check it duplicates.

**Out of scope:** Restoring the content of a pre-existing ignored file the fixer modifies or deletes, which stays as the fixer left it and is outside the ignored-path additions the round diff reports. A folder that was already completely empty before the round, which git and the snapshot both leave unrecorded, so Restore removes it when the fixer's file was its only content. Fixer writes into the harness's own regenerated run-output trees under `tests/` (`workspace/`, `scratch/`, `.eval_cache/`, `results/`, `.vendor_probe/`, and the staged `tests/wiki/layer2/` sandboxes), which the harness owns and regenerates; the ignored-path manifest, the round diff, Restore, and the concurrent-modification guard all skip them, so the ignored set stays bounded to the files a fixer could actually stray into.
