# Make the vacuous agent_spinner eval checks able to fail

## Goal

Every agent_spinner eval named for a behaviour fails when a run skips or breaks that behaviour. Today several checks in `tests/agent_spinner/evals/grade.sh` pass on an untouched fixture with a one-word response, or on a simulated run that violates the eval's own rule, so the suite can certify a run that did not do the work. Each repaired check lands with a `tests/agent_spinner/script_tests/grade_cases.sh` case that proves its fail branch fails.

## Context

The 2026-11-14 coverage audit staged every fixture through `evals/stage.sh`, graded it with no agent action, and simulated violating runs for some evals; the checks below passed where they should fail.

- **Sweep sampling.** `sweep_sampling_needs_user` and `sweep_rewrite_hunk_blocks_sampling` assert that every changed page holds exactly one check row. `initial_check_rows_for_path` counts rows in any state, and `diff --add-checks` creates them unprompted, so a run that appended a line to every page, ran `diff --add-checks`, closed every check row with `--classify 'sampled out'`, and dispatched no checker scored 4/4 on both. `references/recipes/prose-sweep.md` allows a sampled checker set only on the user's word. Separately, `offers_sampling` searches the whole run text for its choice cue and matched a quoted gate line in a run that said sampling was not used.
- **`changed_false_still_checked`.** Its brief check matches the producer brief the fixture already staged, so a one-sentence run with no ledger action scored 3/3.
- **`blind_pass_by_prompt`.** It greps only `briefs/` for the hypothesis, while `request.txt`, `intent.md`, and `announcement.txt` in the same run directory can quote it. SKILL.md `<containment>` keeps text a blind pass must not see out of the workspace.
- **`judge_flaws_capped`.** The staged judge returns already carry three or fewer flaws, so the cap check passes on a no-op.
- **`inline_floor`.** `ran_a_checking_pass` falls back to matching `check(ing)? pass|refute|re-?check` in the response.
- **`payload_cap`.** "A brief lists the trimmed identifiers" and "a synthesis brief was written" both pass on the fixture's own survey briefs. The fixture also contradicts itself: its briefs check against a `bin/tool.sh` it never stages, its survey returns say `pass` while carrying major and blocker findings, and gamma's quoted line and `# legacy` heading are missing from `docs/gamma.md`.
- **`unreturned_bound`.** Its fixture sets the row's `unreturned` state itself through `ledger_set_state`, so a single sentence passes.
- **Report-opening helpers.** The tier alternative behind "opening sentence carries the verdict and the tier" accepts "fan-out", a shape name, and `DISPATCH_ARITH` accepts "run against".
- **Go-ahead cue.** `ASKS_GO_AHEAD` contains bare `decide` and `confirm`, which match the standard report heading "Decided on a helper's own authority" and the tally line "confirmations 0", so "asks for the decision" passes on any closed report; a Cursor `depth_one_level` run asked nothing and passed it. `judgement_surfaced` uses the same cue.
- **Probe delegation.** `probe_entry_has_capability_value` tests membership in all of a probe entry's values, so "the role probe records delegation as established" passed on a `probe.json` with `delegation_surface: assumed_absent` because its `concurrency` was established.
- **`payload_cap`'s response checks.** `cap|...` matches "capability" and `alpha` matches `docs/alpha.md`. A synthesis brief that relays the returns by path with a read-in-full instruction pastes nothing, so the skill asks for no cap there (`references/run-protocol.md`: "Relay upstream material ... by path with a read-in-full instruction, or paste it below a stated cap"), yet the brief checks demand a truncation notice.

## Approach

1. For both sweep-sampling evals, count a changed page as checked only when it holds exactly one initial check row whose return was accepted (an `accept` record from a validated return) and whose brief file exists, with no `classification` record for that label. For `sweep_sampling_needs_user`, also require that no sampled-out classification exists for any changed page. Update the existing `write_sweep_roster` cases in `tests/agent_spinner/script_tests/grade_cases.sh` so each staged check row gains a brief, a return, and an accept record, and the re-check case keeps expecting a pass. Make the negation rule one both offer helpers share: `offers_sampling` drops each sentence, and `offers_sampling_item` drops each list item, that negates sampling ("not offered", "not used", "sample-dropped") before and independently of its drop/share/choice cue test, so a negated sentence or item — such as "Sampled checker set: not offered. It would drop … cost: saves 3 of 4 checker spawns." — never re-enters the cue set even when it also matches `offer` or `your word`, and `sweep_sampling_needs_user`'s offer check fails on it. Keep the existing choice cues in place, including `not taken`, which the compliant offer item carries. Keep the announcement in scope, since the prompt asks the run to state its choices there; a Cursor `sweep_rewrite_hunk_blocks_sampling` run that wrote "Sampled checker set: not offered" failed "offers no sampled checker set" on those cues.
2. `changed_false_still_checked`: require a ledger `check` record for `docs/alpha.md` and the brief file belonging to that check row (not the producer's staged brief), so a one-sentence run with no ledger action fails.
3. `blind_pass_by_prompt`: keep the directory-wide absence check `no brief carries the hypothesis text` scanning every brief under `.agent_spinner/briefs/` exactly as `grade.sh` writes it today (`! grep -REqi '45 seconds|a lie' "$BRIEFS_DIR"`), so a run that writes "45 seconds" into any brief — `probe:generic.txt` included — fails it; that directory-wide property is what the check's own label, the eval's `expected_output` and expectation, the `evals/README.md` proof-surface row ("briefs + roster input versions + report"), and Acceptance item 2 all name. Add one condition scoped to the blind row's own brief: read that brief's `permits paths:` line and require it to name none of the run inputs that quote the hypothesis (`request.txt`, `intent.md`, `announcement.txt`), and fail the check when the blind row, its brief file, or that `permits paths:` line is missing, so neither the absence test nor the path requirement passes on an absent artifact. Read no `forbids paths:` entry: `grade.sh`'s own `briefs_one_distinct_target` comment states that counting bare mentions in a negative list "would fail exactly the brief that obeys the rule", and a compliant brief names those three inputs there by rule. The run's verbatim inputs stay out of the read set for the same reason — they necessarily carry the request.
4. `judge_flaws_capped`: keep the eval fixture compliant (two judges, three flaws each) and prove the cap's fail branch in a `grade_cases.sh` case that stages a judge return with four flaws and asserts the grader fails "each judge return holds at most three fatal flaws with a span", beside a compliant case that passes. The cap is the judge helper's contract (`references/role-prompts.md`: "Name at most three fatal flaws, each with a span"); the run confirms it and never rewrites the helper's return.
5. `inline_floor`: replace `ran_a_checking_pass`'s phrase fallback with an accepted check row whose return file post-dates the return files of the producers for the same checked path, and add pass/fail cases.
6. `payload_cap`: read all three brief checks — "a synthesis brief was written", "a brief carries the truncation notice", "a brief lists the trimmed identifiers" — from the synthesis row's own brief file, requiring it to exist. Make them branch-aware: the by-path branch passes when the synthesis row's own brief relays all three labels and names each return path with "in full" and pastes no return body, and the paste branch requires a numeric cap, the cut notice, and the trimmed identifiers. Anchor the two response checks (`payload cap|capped at [0-9]+`, `trimmed[^.]{0,60}survey:(alpha|beta|gamma)`) and apply them only on the paste branch. Update the eval's `expected_output`, its expectations, and the `payload_cap` proof-surface row in `tests/agent_spinner/evals/README.md` so they describe the branch that the grader now accepts. Make the fixture coherent: stage a `bin/tool.sh` that takes `--workers` and rejects `--jobs`, add the quoted `--jobs 8` line under a `# legacy` heading in `docs/gamma.md`, and set the survey verdicts to `fail`.
7. `unreturned_bound`: stage the gamma row as `dispatched` with a back-dated start, so the run has to produce the `unreturned` state through `accept --wait` rather than reading a state the fixture set.
8. Anchor the opening-tier alternative to tier vocabulary (`spawned[- ]roles|inline floor|tier`) and drop "run against" from `DISPATCH_ARITH`.
9. Replace the bare `decide` and `confirm` alternatives in `ASKS_GO_AHEAD` with a user-directed decision cue (`your (decision|call)|needs your (decision|call)|decision for you|await(s)? your`), so "Decided on a helper's own authority" and "confirmations 0" no longer match, and re-check `depth_one_level` and `judgement_surfaced` against the captured compliant runs; both must still pass.
10. Make the probe delegation check read the value of the key whose name contains `delegat` (or `spawn`), so a `delegation_surface: assumed_absent` entry with another capability `established` fails, and a compliant run that reports `delegation: established` passes; `probe_brief` fixes no key name, so the check matches the key name rather than one hard-coded spelling.
11. Re-run each touched eval on the default vendor and record the verdicts in `tests/agent_spinner/evals/README.md`. Rewrite the frozen "11 committed report variants … 15 pass/fail checks in all" sentence in `tests/agent_spinner/README.md` as a selector ("every case `grade_cases.sh` runs"), so the count does not go stale.

**Out of scope:** The mirror defect in `visible_role_delegation`, where a capability value test can fail a compliant run, since this task repairs checks that pass when they should fail.

## Acceptance

- `grade_cases.sh` carries, for each check repaired above, a case where a no-op or violating run fails it and a case where a compliant run passes it, and the suite passes. The judge-cap fail branch is one such case: a four-flaw return makes the grader fail.
- The audit's no-op probe, re-run by staging each touched eval and grading it with an empty response and no agent action, fails every repaired check that reads a run-produced artifact (the accepted-row, brief, ledger-record, and report checks). The two absence checks — no brief carries the hypothesis text, no sampled checker set offered — are proven fail-able by a `grade_cases.sh` case that stages the artifact carrying the forbidden text and asserts the check fails; a no-op run is not counted as passing them.
- `grade_cases.sh` carries two `sweep_sampling_needs_user` cases over that eval's own staged fixture: one writes the negated announcement item "Sampled checker set: not offered. It would drop … cost: saves 3 of 4 checker spawns." and asserts "offers the sampled checker set as a narrowing with its drops and its share of the estimate" fails, and one writes the compliant offer item and asserts it passes.
- The staged `payload_cap` tree is coherent and its `evals.json` `expected_output` and expectations describe the branch the grader accepts: `bin/tool.sh` takes `--workers` and rejects `--jobs`, `docs/gamma.md` carries the quoted `--jobs 8` line under a `# legacy` heading, and the survey returns carry `fail` verdicts.
- `tests/agent_spinner/evals/README.md` records the default-vendor verdicts of the touched evals after the change, and `tests/agent_spinner/README.md` states the `grade_cases.sh` coverage by selector rather than the frozen "11 … 15" count. An eval that now fails a compliant run's behaviour is recorded with the check it fails, and the grader fix is revisited before the task closes.
