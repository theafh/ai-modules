# Close the agent_spinner ledger paths that let a run overstate its coverage

## Goal

The run ledger refuses, or records honestly, four situations in which a run today closes cleanly and reports more checking than it did. A check row closed by classification is counted and reported as unchecked unless a named narrowing covers it. The wave cap bounds unchecked writes rather than writers in flight. A count gate needs a counter whose own positive control passed. The probe records the read-only lever as enforced only when the helper actually could not write.

## Context

Every path is in `plugins/ai_dev/skills/agent_spinner/scripts/run_ledger.py`, and `tests/agent_spinner/script_tests/ledger_run.sh` exercises none of the four failure cases. The coverage audit of 2026-11-14 reproduced each one in a scratch repository.

- **`--classify` accepts a rejected return.** In `cmd_accept`, the branch `if errors and args.classify:` marks the row `accepted`, sets its source, and records only a `classification`. `change_covered` then counts that row as the check its path needs, `close` exits 0, and the tally reports it under `accepted`. The recipes prescribe exactly this command to close sampled-out check rows (`references/recipes/prose-sweep.md` and `references/recipes/multi-file-task.md`, the `accept check:<slug> --stdin --classify` line), and with nothing on stdin that command exits 2 ("return for check:... is empty"). SKILL.md `<coverage_tradeoff>` says "Name every narrowing out loud, printed from the ledger", and `references/checks.md` says `close` refuses "while a changed path lacks an accepted check from another row".
- **The wave cap counts writers in flight.** `cmd_dispatch` counts writer rows in state `dispatched` against `wave_size`, while its error says "written rows are unchecked". Three writers can be dispatched, written, and accepted one after another under `--wave 1` with no check row at all. SKILL.md `<phase_plan>` says "Run writes and their checks in waves, so a stop leaves at most one wave unchecked", and `references/run-protocol.md` says to run "pending checks ahead of queued writes".
- **A count gate accepts a blind count.** `cmd_gate`'s `count` branch only checks that some counter is registered. `references/checks.md` says "`count` needs a counter whose positive control passed", and SKILL.md `<checking>` says "a probe fires on a known positive before its empty result counts".
- **The probe trusts a missing marker.** `accept_probe` records `read_only: enforced` whenever `returns/probe:<slug>.start` is absent, but the probe brief rendered by `init --probe` only says "Attempt one write inside the run directory" and never names that file. A helper that writes any other file is recorded as enforced. `references/run-protocol.md` P1 counts the lever as enforced "only when the probe's write attempt inside the run directory left no file". Separately, `checker_spawned_through_role` grades the spawn route from roster rows the orchestrator fills in itself through `dispatch --route`.

The terminal-states, brief-contract, report-and-packet, unanswered-fork, and stamped-write-routing tasks edit the same ledger file and `ledger_run.sh`; land this one after them and before the record-completeness task.

## Approach

1. Count a check row closed by `--classify` as covering its path only when a `narrowing` record's `drops` list carries that row's exact `label`; `dispose --narrowing` splits `--drops` on commas, refuses a `--drops` entry that names no roster row, and stores the resolved labels, so a label that appears only in the narrowing text, or matches only as a substring, covers nothing. Otherwise `close` refuses on the uncovered changed path. Keep classified rows out of the accepted count in both `print_tally` and `tally_block`, and print their count beside it in each, so a row closed only by classification is reported as unchecked rather than checked. Let `accept --classify TEXT` take an empty stdin, because the classification text is the whole record of a sampled-out row, keep both recipe lines as written, and add beside each the `dispose --narrowing … --drops <labels>` call step 5 gives it.
2. Make `cmd_dispatch`'s writer cap count written rows that lack an accepted check from another row, in addition to writers in flight, so a writer waits while the previous wave is unchecked. A writer row with no `--unit-path` carries an empty path that no accepted check can cover, so it counts toward the cap only while it is in flight and stops counting once it is accepted.
3. Record each counter's control verdict where it is registered, and make the `count` gate require one that passed. `init --counter NAME=PATTERN` evaluates the pattern against the same `CONTROL_MARKER` positive `diff --count` uses and stores the counter as its pattern plus that verdict, so a pattern that misses the positive is stored with `control: false` rather than refused. `diff --count` keeps failing closed on a pattern that misses the positive and stores each counter it accepts with `control: true`. The `count` branch then passes only when at least one registered counter carries `control: true`, and when counters are registered but none passed it appends a `gate_result` with `ok: false` and exits non-zero, keeping `die` for the no-counter-at-all case.
4. Make the probe brief name the exact marker file it must try to write. Take each probe row's baseline list of the files under the run directory once, in `init_probe`, after its loop has rendered every route's brief and `write_rows` has written `roster.tsv`, and store it on that row; no later refresh is needed, because the ignore rule below selects by path rather than listing one run's writes, so a probe accepted after `init` opens the run is compared against a baseline that predates every write the run makes. Have `accept_probe` list the files again before it writes `probe.json` and ignore every path the run writes for itself: everything under `briefs/`, `attempts/`, and `history/`; the run-open directories `init` creates (`access/`, `kinds/`, `items/`, `baseline/`, `snapshots/`, `diffs/`, `gates/`, `outbound/`, `controls/`, `scratch/`); the run-directory files `run.json`, `ledger.jsonl`, `request.txt`, `intent.md`, `preamble.md`, `facts.tsv`, `exclusions.tsv`, `probe.json`, `roster.tsv`, `report.md`, `STOP`, `.gitignore`, and `.lock`; and, under `returns/`, every `returns/<label>.md` and every `returns/<label>.start` whose `<label>` is a roster row, whatever that row's kind, except the current row's own `returns/probe:<slug>.start`, which stays visible — so every row's return, every other helper's marker, and the run's own writes never count as this helper's work, while a `returns/` path no roster row names stays this helper's write. Record `enforced` only when the marker is absent and no path outside that ignore rule was added since the baseline; the marker `returns/probe:<slug>.start` is not one of those ledger paths, so the ledger never writes it and its appearance is the helper's. Add `tool_record: true` to `checker_spawned_through_role` in `tests/agent_spinner/evals/evals.json`, and grade that a spawn call naming the checker role appears in the recorded tool calls.
5. Rewrite in place the `references/run-protocol.md` and `references/checks.md` passages that describe these verbs, and the sampled-out passages in `references/recipes/prose-sweep.md` (its `<ledger_steps>` line and its `<width>` sampled-set line) and `references/recipes/multi-file-task.md` (its `<width>` sampled-set line), so each states what the ledger now enforces. Each recipe keeps its `accept check:<slug> --stdin --classify 'sampled out; per-file gates cover it'` line and gains beside it one `dispose --narrowing 'sampled out; per-file gates cover it' --drops check:<slug>,…` call per run naming every sampled-out `check:<slug>` label, so the prose says the classification text closes the row while the `--drops` list is what makes each sampled-out path count as covered, and that `close` refuses a sampled-out path the list omits. `--drops` records coverage only and changes no row's state.

## Acceptance

- `ledger_run.sh` scenario: a hollow checker return accepted with `--classify` and no narrowing leaves `close` refusing on its path; the same row named in a narrowing's `drops` list lets `close` pass; a narrowing whose text names the row while its `drops` list omits it leaves `close` refusing; a `--drops` entry naming no roster row is refused; and with one accepted check row beside one classified row the tally prints `accepted=1` in `print_tally`'s line and `accepted 1` in the `report.md` tally block, each beside a classified count of 1.
- `ledger_run.sh` scenario: the recipes' sampled-out command, run with nothing on stdin, exits 0 and records the classification.
- `ledger_run.sh` scenario, extending `scenario_dispatch`: under `--wave 1`, after one writer is accepted on a changed path with no accepted check from another row, the next writer dispatch is refused; once a check row on that path is accepted, that same writer dispatch succeeds.
- `ledger_run.sh` scenario: under `--wave 1`, a writer dispatched with no `--unit-path` that is then accepted does not block the next writer's dispatch.
- `ledger_run.sh` scenario: `init --counter zero='^0$'` stores a counter whose control misses the known positive, and a `count` gate run with it on a script that prints `0` appends a `gate_result` with `ok: false` and exits non-zero.
- `ledger_run.sh` scenario: `diff --count --counter good=CONTROL_MARKER` stores that counter with `control: true`, and a `count` gate over a script that prints `CONTROL_MARKER` records `ok: true` and exits 0.
- `ledger_run.sh` scenario: a probe helper that writes a file other than the marker is recorded as not enforced.
- `ledger_run.sh` scenario: the probe brief `init --probe` renders for a route names `returns/probe:<slug>.start` as the file the helper must try to write.
- `ledger_run.sh` scenario, extending `scenario_probe`'s existing clean case: a probe whose return is the only file it leaves is recorded `"read_only": "enforced"`; with two probe rows whose helpers leave only their returns, the second row accepted after the first is also recorded `"read_only": "enforced"`; with two probe rows whose first helper leaves its own `returns/probe:<slug>.start` marker, the row accepted after it is recorded `"read_only": "enforced"`; a probe row accepted after `init` has opened the run is recorded `"read_only": "enforced"` even though a check row's accepted `returns/<label>.md`, a writer helper's `returns/<label>.start`, a `STOP` written by `stop`, and a `report.md` written for the run all landed in the run directory after `init_probe`; and a probe helper that leaves a `returns/` file whose label the roster carries no row for is recorded `"read_only": "not-enforced"`.
- `checker_spawned_through_role` carries `tool_record: true` and a grader check on the recorded spawn call, with a `grade_cases.sh` case where a run that types the route without spawning fails.
- `references/run-protocol.md` and `references/checks.md` state the classification rule: `! rg -n 'accept a free-text return with a classification' plugins/ai_dev/skills/agent_spinner/references/run-protocol.md` finds nothing, and `rg -n 'classif' plugins/ai_dev/skills/agent_spinner/references/checks.md` finds the close sentence naming a classified row.
- `references/recipes/prose-sweep.md` and `references/recipes/multi-file-task.md` state the narrowing a sampled-out row needs: `! rg -n 'stands as a recorded narrowing' plugins/ai_dev/skills/agent_spinner/references/recipes/prose-sweep.md` finds nothing, `! rg -n 'stays a recorded narrowing' plugins/ai_dev/skills/agent_spinner/references/recipes/multi-file-task.md` finds nothing, and `rg -n 'dispose --narrowing' plugins/ai_dev/skills/agent_spinner/references/recipes/prose-sweep.md plugins/ai_dev/skills/agent_spinner/references/recipes/multi-file-task.md` finds the call in each.
- `references/run-protocol.md`'s `--wave N` entry states what the cap counts: `! rg -n 'the wave size, default 2' plugins/ai_dev/skills/agent_spinner/references/run-protocol.md` finds nothing, and `rg -n 'unchecked writes' plugins/ai_dev/skills/agent_spinner/references/run-protocol.md` finds the entry stating the cap bounds unchecked writes.
- `references/run-protocol.md`'s counter entries state the control rule: `! rg -n 'a counter whose positive control must match' plugins/ai_dev/skills/agent_spinner/references/run-protocol.md` finds nothing, and `rg -n 'control: false' plugins/ai_dev/skills/agent_spinner/references/run-protocol.md` finds the entry stating a counter stored with a failed control.
- `references/run-protocol.md` P1's read-only passage names the marker and the stray-file condition: `! rg -n 'write attempt inside the run directory left' plugins/ai_dev/skills/agent_spinner/references/run-protocol.md` finds nothing, and `rg -n 'returns/probe:<slug>\.start' plugins/ai_dev/skills/agent_spinner/references/run-protocol.md` finds the marker the helper must try to write.
