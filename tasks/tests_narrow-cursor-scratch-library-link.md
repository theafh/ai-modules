# Narrow the Cursor scratch home's Library link to Library/Keychains, with the cursor wiki passage rewrite and its keychain-login evidence note

## Goal

Every Cursor eval worker that `tests/lib/micro_deploy.py` prepares gets a scratch home whose `Library` is a real directory holding only the `Keychains` symlink to the real `~/Library/Keychains` on the primary path, plus the fail branch's added sub-path link when `## Acceptance` 5(c) requires one. The Cursor login keeps working, and nothing else of the real `~/Library` is reachable from the scratch home. Worker file searches over the scratch home then stop walking into other apps' private data (`Library/Containers`, `Library/Group Containers`), which ends the macOS "would like to access data from other apps" dialogs those searches trigger, under whichever app launched the eval.

## Context

- **Current mechanism.** `_link_library` in `tests/lib/micro_deploy.py` symlinks the scratch home's `Library` to the whole real `~/Library`, and `micro_deploy()` calls it for the Cursor vendor so the worker can reuse the stored login. The mechanism shipped with [the micro-deploy task](archive/tests_micro-deployed-eval-workers.md), whose verified finding was that an empty scratch `HOME` leaves the Cursor CLI logged out while a linked `Library` restores the login.
- **Why the whole link causes harm.** A worker that globs its own home (observed: a Glob rooted at the scratch home while resolving the `auto_drift_task` helper-agent name the harness declares, in the `mechanical_lint_ready` and `mechanical_lint_markdown` scenarios of `tests/task_auto_check/evals/run.py`) follows the link into the real `Library`. The Cursor CLI's bundled `rg` then touches every app container, and macOS raises one privacy check per container and process, attributed to the app at the top of the process chain. The link also exposes the user's Cursor app state (`Library/Application Support/Cursor/User/globalStorage/state.vscdb`, workspace storage) to workers, which weakens the isolation the micro-deploy exists for.
- **What the login actually needs (verified 2026-10-26).** The Cursor CLI stores its credentials in the macOS login keychain (account `cursor-user`, services such as `cursor-access-token`) and reads them through `/usr/bin/security`. With `HOME` set to an empty directory, `security find-generic-password -a cursor-user -s cursor-access-token` exits 44 and `agent status` reports "Not logged in". With `HOME` set to a directory whose `Library/Keychains` links to the real one, both succeed (`agent status` reports logged in).
- **Other Library reads in the CLI.** The CLI also looks for `Library/Application Support/Cursor/AgentStores`, falling back to a temporary store when it is absent, and for IDE workspace storage under `Library/Application Support/Cursor/User`, which is optional state. Neither is needed for login, per the CLI bundle's code; the live preflight in Acceptance confirms the fallback works.
- **Cleanup paths that name the link.** `MicroDeployHandle.close` and the `except BaseException:` block in `micro_deploy()` (commented "the scratch home (with its Library link) must not outlive it") remove the `Library` link before deleting the scratch tree, and `_preflight_auth`'s Cursor remedy text says the scratch home "borrows the Cursor login through its `Library` link".
- **Tests that pin the old shape.** `tests/lib/test_micro_deploy.py` asserts the whole-`Library` symlink in the checks labelled "cursor Library linked when present", "Library linked before close", and "Library unlinked before the scratch tree is removed".
- **Wiki record.** `wiki/entities/cursor.md` states that "A scratch `HOME` authenticated once its `Library` linked back to the real one", citing the 2026-10-08 micro-home probe note. Wiki edits run through the `wiki` skill per the repo's standing instructions.

## Approach

1. Rewrite `_link_library` into a keychain-only link: create `scratch_home/Library` as a real directory on every pass, then symlink `scratch_home/Library/Keychains` to the real `~/Library/Keychains` when that real directory exists, so only the symlink is skipped and the absent case leaves `Library` present and empty (the same "when present" behaviour the current function has). The fail branch of `## Acceptance` 5(c) creates its added link directly under `Library` as a single top-level entry (`scratch_home/Library/<name>`), so `Library`'s entries stay a flat set of links on both paths and the enumeration in `## Acceptance` 1(a) compares link against link. `_link_keychains` reads the real home through one module-level seam in `tests/lib/micro_deploy.py`, `_real_home()`, which returns `pathlib.Path.home()` and which the staged absent-`Keychains` check points at a temporary directory. Rename the function to `_link_keychains`, and update its call site in `micro_deploy()`.
2. Rewrite both cleanup passages (`MicroDeployHandle.close` and the `except BaseException:` block) to unlink `scratch_home/Library/Keychains` first and then remove the scratch tree. Each unlink runs only when that path is a symlink — the same "when present" guard the helper keeps — so the absent case, where the helper created no link, lets `shutil.rmtree(scratch_home)` run instead of raising `FileNotFoundError` that would leak the scratch tree in `close()` and replace the original exception in the `except BaseException:` block, and each unlink keeps `close()`'s existing `except OSError: pass` tolerance, so a denied or raced unlink stays as silent as it does today. With `Library` now always a real directory, leave it to `shutil.rmtree(scratch_home)` and remove `close()`'s directory-shaped `Library` branches — the `library.is_symlink() or library.exists()` probe and its `IsADirectoryError` → `shutil.rmtree(library, ...)` catch, which only existed for a symlinked `Library`. Rewrite the block's comment to read `the scratch home (with its Keychains link) must not outlive it`.
3. Rewrite the Cursor remedy string in `_preflight_auth` so it says the scratch home borrows the login through its `Library/Keychains` link; keep the `agent login` and `CURSOR_API_KEY` guidance.
4. Rewrite the four `Library` checks in `tests/lib/test_micro_deploy.py` to the new shape, naming the three replacement labels `Keychains linked when present`, `Keychains linked before close`, and `Keychains unlinked before the scratch tree is removed`: `Library` is a real directory whose entries are exactly the links the helper created — `Keychains` alone on the primary path, and `Keychains` plus the fail branch's added sub-path once `## Acceptance` 5(c) adds one — and `Keychains` is a symlink resolving to the real `~/Library/Keychains`, the `Keychains` link is gone before the scratch tree is removed, and the real `~/Library/Keychains` is still a directory after `close()`. The fourth check is the existing `real Library untouched by close` check: re-point it to assert the real `~/Library/Keychains` is still a directory after `close()`, and give it the same real-`Keychains` presence guard the section's other present-branch assertions use. Introduce `REAL_KEYCHAINS = REAL_HOME / "Library" / "Keychains"` once at module level beside the existing `REAL_HOME`, and have every real-`Keychains` assertion in the file test `REAL_KEYCHAINS.exists()`. Extend `test_auth_preflight_failure_surfaces_cli_message` to cover the `except BaseException:` path: with `shutil.rmtree` wrapped the way `test_library_unlinked_before_removal` wraps it, it records whether `scratch_home/Library/Keychains` is still a symlink when the scratch home's own `rmtree` call runs, and asserts it is already gone. Stage the absent-`Keychains` case here as the single statement of its host tests: `test_library_unlinked_before_removal` takes a second deployment whose `micro_deploy()` call runs with `_real_home()` pointed at a temporary directory holding no `Library/Keychains` entry, and asserts there that the helper left the scratch home's `Library` a real directory carrying no `Keychains` symlink and that the handle's `close()` removes the scratch home without raising, while the extended `test_auth_preflight_failure_surfaces_cli_message`, run with that same seam target, owns the absent case's `except BaseException:` assertion that the cleanup still removes the scratch home without raising.
5. Through the `wiki` skill, rewrite the `wiki/entities/cursor.md` passage on the scratch `HOME` so it states that linking `Library/Keychains` alone authenticates, carrying the verbatim phrase `authenticates with only Library/Keychains linked`, and record the 2026-10-26 keychain probe results from Context as a new `wiki/raw/notes/cursor-keychain-login-probes-2026-10-26.md` sidecar carrying its `ingested` and `sha256` frontmatter (hash from the wiki skill's `compute_sha256.py`, written once the note body is final — the login measurement and any failing-branch record the `## Acceptance` items require in this note already in place — and refreshed with that same script whenever the body changes afterwards), listed in that page's `sources:`, with the ingest appends the new `wiki/raw/notes/` sidecar and the rewritten `wiki/entities/cursor.md` passage to `wiki/log.md`, and `wiki/index.md` takes only its `Last updated` bump, its page catalog gaining no entry for the raw note — so the rewritten passage cites that note as its evidence. Keep the passage's skill-copy clause beside the new login clause, naming its `micro-deployed-worker-home-probes-2026-10-08.md` note in an inline markdown link next to the clause, so the passage retains both verified facts the sentence carries. In the same rewrite, cut the older note's whole-`Library` claim as an explicit dated supersession: state that the 2026-10-08 note established that the scratch home's own `.cursor` state takes over once the login works, while the 2026-10-26 probes narrow the login mechanism to `Library/Keychains` alone, so the passage keeps that note's citation for the scratch-home-state fact and cites the new note for the login fact.

**Out of scope:**

- Changing the worker permission flags in `tests/lib/vendor.py` (`--force --sandbox disabled`), since this task removes the reachable data rather than sandboxing the worker.
- Changing how the harness handles a worker that globs its own home, since the narrowed link makes that search harmless.
- Rewriting the archived micro-deploy task linked under Context **Current mechanism.**, whose passages still describe the whole-`Library` link as current; that body stays as delivered under the status discipline the task family applies to archived work.
- Splitting `wiki/entities/cursor.md`, whose oversize state predates this task; this task's wiki edit rewrites the scratch-`HOME` passage in place.
- Linking any real-`~/Library` sub-path that holds Cursor app state, such as `Library/Application Support/Cursor` (whose `User` tree carries `state.vscdb` and workspace storage) or `Library/Containers`, since the Goal's "nothing else of the real `~/Library` is reachable from the scratch home" admits nothing of that kind; the fail branch adds only a sub-path outside those trees.
