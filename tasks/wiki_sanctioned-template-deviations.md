# Make the locked-slot boilerplate check preserve wiki extensions so refinements survive audits

## Goal

After this task, the skill stops giving two opposite instructions about the same difference between a wiki file and its canonical template.

The agent already classifies content that a wiki has and the canonical template lacks as a customization to preserve, as long as it extends the canon without contradicting it. The locked-slot boilerplate check overrules that verdict. It names restoring the canonical text as the remedy, and today the check wins.

This task changes the check to use the insert-only classification that Approach freezes. A pure addition agrees with the agent's preserve path. Any delete or replace still warns. So an owner who adds text inside the template-locked region of their own `log.md` sees it reported as an extension, not as something to restore away. That region, the `log.md` preamble, is the only slot in `VERBATIM_SLOTS` today. A region that deletes or rewrites canonical text still warns. A wiki that means to contradict the canon can declare that, and the declaration is honoured. The agent may no longer revert a declared divergence. When the agent judges a divergence good in general, it reports it as a candidate for the shipped template instead of deleting it in the one wiki that has it.

The owner sees the outcome directly. A rule they anchored in their wiki is still there after an audit. An audit that removed such a rule is no longer reported as a clean run.

This task owns the **mechanism**. It sets how any local divergence from a template is treated, whatever that divergence says. What a log entry should contain by default is a content question, and that question belongs to [wiki_log-scope-wiki-changes-only.md](archive/wiki_log-scope-wiki-changes-only.md). The two tasks ship independently, in either order.

## Context

Two shipped mechanics leave an owner's refinement of a locked region with no path except removal.

The linter locks each region named in `VERBATIM_SLOTS` byte-for-byte against the shipped templates. That tuple holds one slot today, the `log.md` preamble, and `SCHEMA.md` is not a locked slot. `check_verbatim_boilerplate` in [skills/wiki/scripts/lint.py](../plugins/knowledge_management/skills/wiki/scripts/lint.py) walks the `VERBATIM_SLOTS` tuple. It extracts each slot's region from the wiki and from its template, and on any difference it emits a `boilerplate` warn. That warn's message ends `restore the region verbatim or update the template if the change is intentional`. Those are the only two remedies the message offers, and neither one preserves a per-wiki refinement. The first deletes it. The second is unavailable to an owner editing their own wiki, because the template ships from this repo and editing it does not reach a wiki that already exists.

The skill already carries the right rule, but in the wrong place to win. `<hunk_classification>` in [agents/auto_shaper_wiki.md](../plugins/knowledge_management/agents/auto_shaper_wiki.md) walks each block of lines that differs between the wiki's file and the canonical template. It rules that content the wiki has and the canonical lacks is a customization to preserve as-is, when it extends the canon without contradicting it. It surfaces that content for the user only when it contradicts canonical semantics. An owner's added paragraph inside a locked region is an extension by that test, so the classifier's verdict is to preserve it. The `boilerplate` finding overrides that verdict. `<linter_is_truth_for_structure>` makes structural lint output authoritative, and the finding's own message names restoring the canonical text as the remedy. So two mechanisms in one skill give opposite instructions on the same block of differing lines, and the one that wins destroys the owner's work.

`<configurable_zones>` grants `template_log.md` a zone for entries and their bodies, but it deliberately runs the diff on the preamble alone. The preamble is therefore the single region with no configurable zone. The failure is not missing classifier protection, since `<hunk_classification>` already preserves wiki-has and canonical-lacks extensions. The failure is the live `boilerplate` warn. Its message names restore-verbatim, and under `<linter_is_truth_for_structure>` it overrides the preserve verdict.

The agent then acts on that signal. `<scaffold_drift>` in [agents/auto_shaper_wiki.md](../plugins/knowledge_management/agents/auto_shaper_wiki.md) drives its comparison from a line-level diff against each canonical template, and `<linter_is_truth_for_structure>` makes the linter's structural output authoritative. When a restore-instructing `boilerplate` warn is live, nothing in either instruction tells an owner's deliberate addition inside a locked region apart from accumulated drift. The only remediation available is to restore the canonical text.

[wiki_log-scope-wiki-changes-only.md](archive/wiki_log-scope-wiki-changes-only.md) has already landed additive ensure and refresh on `<fix_log_preamble_drift>`. That move inserts absent units, refreshes drifted units by label or greppable stem, and leaves wiki-only lines byte-identical. `<lint_already_covers_prelude>` already routes remediation through that move rather than a wholesale restore. Both sites still treat a surviving owner-line `boilerplate` warn as an expected remaining finding, though. The remaining work aligns those sites, and the related clean-exit and scaffold rules, with classify-as-extension, acknowledge, and declare. Then an insert-only extension is no longer a restore target and no longer blocks as a live warn.

This was observed end to end once, in a wiki managed by this skill. The diagnosis here is a reading of the two instruction blocks named above, not a ruling by the skill's author. The owner added a paragraph to the `log.md` preamble that scoped log entries to changes of the wiki itself. They anchored the same rule in that wiki's `SCHEMA.md` and in the repository's agent instruction files. The next audit read the preamble difference as scaffold drift and deleted the paragraph. The owner caught it mid-run and ordered it restored. Left alone, the audit would have reported a clean run after removing the rule it was asked to maintain. That is the failure mode this task closes, because a silent revert reads afterwards as compliance.

## Approach

1. **Classify the mismatch instead of forcing a verbatim restore.** Rewrite `check_verbatim_boilerplate` so it classifies a mismatch before it emits any restore message. Compare the extracted wiki region to the extracted canonical region with a line-level sequence alignment: a `difflib.SequenceMatcher` opcode walk over lines, with opcodes limited to equal, insert, delete, and replace.

   Treat an **insert-only** result as an **extension**. Insert-only means every canonical line survives in order and the only non-equal opcodes are inserts. Report an extension on a dedicated acknowledged report channel that sits outside the three live severity totals (`blocking`, `warn`, `info`), never as a live `warn` or live `info` Issue. Reuse the acknowledged-section shape that [wiki_lint-accepted-info-suppression.md](archive/wiki_lint-accepted-info-suppression.md) already landed through `Issue.render_acknowledged`, `partition_accepted`, and the report's `ACKNOWLEDGED` section. Name the slot and state that content was added. Emit no `boilerplate` warn and no restore-verbatim instruction.

   Wire the return and reporting path explicitly. `check_verbatim_boilerplate` returns `(live_issues, acknowledged_items)`. `main` extends the shared issues list with `live_issues` only. After `partition_accepted`, append those boilerplate `acknowledged_items` onto the acknowledged list before `render_report`. Insert-only extensions and matching declarations never appear as live `warn` or live `info` Issues, and they never invent a fourth severity.

   Parameterize the acknowledged line marker in `Issue.render_acknowledged`: `(accepted)` for Accepted-finding suppressions, `(extension)` for insert-only locked-slot extensions, and `(declared)` for matching `Declared boilerplate:` honours. Widen the `ACKNOWLEDGED` section header beyond accepted-only wording so it covers those three sources, without implying every acknowledged line was an `Accepted finding:` bullet.

   Supersede in place every `lint.py` comment or docstring that still states verbatim-equality or accepted-only acknowledgment for these slots. Rewrite each one so a single current statement remains:

   - The module docstring paragraph that begins `An info finding the wiki owner has reviewed and accepted` names all three acknowledged-channel sources this step wires (accepted-finding suppressions, insert-only locked-slot extensions, and matching `Declared boilerplate:` honours), and states that each one is reported outside the live blocking, warn, and info totals.
   - The `VERBATIM_SLOTS` section comment, today `this check enforces verbatim equality`, states the classify-as-extension and delete-or-replace-warn contract this step freezes.
   - The `VerbatimSlot` class docstring, today "required to match its canonical template", names a locked region compared under that contract rather than by byte-identical match alone.
   - The `extract_h1_prelude` docstring passage that calls the prelude `"must-stay-verbatim"` names a locked-slot extract under classify-as-extension.
   - The `check_verbatim_boilerplate` docstring, today "warn on mismatch", names insert-only as an acknowledged extension and delete or replace as a warn.
   - The `Issue.render_acknowledged` docstring, today accepted-finding-only, covers the parameterized `(accepted)`, `(extension)`, and `(declared)` markers.
   - The `render_report` docstring, today `Accepted finding:`-only for `acknowledged`, names all three acknowledged-channel sources and the live-count boundary, matching the module-docstring and `ACKNOWLEDGED` header rewrites above.

   Keep today's warn for **any delete or replace** of canonical content, with both remedies named as today. The check does not judge semantic contradiction. That path is the declaration in **Declare a deliberate contradiction.**, together with the agent's existing surface-for-user posture. This step is the cheap half and needs no new wiki syntax, so it leads.

2. **Declare a deliberate contradiction.** This route covers the case that classification cannot settle. Add one labeled bullet per declared slot to the SCHEMA `## Lint` section. Freeze the grammar as `- Declared boilerplate: <slot.label> — <reason>`, where `<slot.label>` is the exact `VerbatimSlot.label` string from `VERBATIM_SLOTS` and `<reason>` is a short free-text explanation. Parse it with the same fence-safe `## Lint` scan used for `Page-check exclusions:` and `Accepted finding:`. Read only outside fences, match the label case-insensitively, and left-anchor on ` — ` so the machine key is the slot-label field and the reason is the remainder. The reason itself is not matched.

   A live bullet suppresses the `boilerplate` warn only when its slot-label field equals that slot's `label` exactly. A live `Declared boilerplate:` bullet whose slot-label field matches no `VerbatimSlot.label` in `VERBATIM_SLOTS` suppresses nothing. It emits one live `SEV_INFO` Issue with category `boilerplate` and path `SCHEMA.md`, naming the unmatched label, and it is not placed on the acknowledged channel.

   Prove per-slot isolation with a Layer 1 fixture that temporarily registers a second test-only `VerbatimSlot` for that case and tears it down afterward. Do not add a second production entry to `VERBATIM_SLOTS`. Document the bullet in [references/template_schema.md](../plugins/knowledge_management/skills/wiki/references/template_schema.md) `## Lint` as a fenced example that mirrors the exclusions bullet, and compose with the two sibling tasks at that section as `## Context` describes.

3. **Honour the declaration in the runner.** In `check_verbatim_boilerplate`, a slot with a matching `Declared boilerplate:` bullet emits no `boilerplate` warn and no Issue in any of the three live severity buckets. Report it on the same non-counted acknowledged list and `render_report` path that **Classify the mismatch instead of forcing a verbatim restore.** wires, again without `Accepted finding:` matching and without emitting into any live severity bucket. Name the slot and the declared reason, so the divergence stays visible without an undo instruction and without inflating the blocking, warn, and info totals or the live `total:` summary. An undeclared remove-or-rewrite divergence is unchanged, with the same warn, the same message, and both remedies still named. An undeclared extension follows **Classify the mismatch instead of forcing a verbatim restore.**, not this warn path.

4. **Take reverting a cleared refinement out of the agent's hands.** Rewrite the agent sites so they follow the check's classification, on top of the additive ensure and refresh path that [wiki_log-scope-wiki-changes-only.md](archive/wiki_log-scope-wiki-changes-only.md) already landed.

   - `<lint_already_covers_prelude>`: Supersede any reading that a still-live `boilerplate` mismatch on the locked slot is a restore-named remediation target once the check has already cleared an insert-only extension onto the acknowledged channel. Keep the landed rule that reporting never licenses a wholesale restore, and that remediating a live restore-instructing warn goes only through `<fix_log_preamble_drift>`. A still-live restore-instructing `boilerplate` warn remains the structural signal for remove-or-rewrite drift in those slots.
   - `<fix_log_preamble_drift>`: Keep the landed additive ensure and refresh form from [wiki_log-scope-wiki-changes-only.md](archive/wiki_log-scope-wiki-changes-only.md). Extend it so an acknowledged locked-slot extension and any declared-slot region stay untouched, the same way wiki-only lines already do. A still-live restore-instructing `boilerplate` warn for remove-or-rewrite drift remains the structural signal.
   - `<lint_clean>`: Supersede the clean-exit exception that treats a surviving `boilerplate` warn on an owner-added preamble line as an allowed remaining finding. After this task, an acknowledged insert-only locked-slot extension satisfies clean exit, because it leaves no live `boilerplate` warn. A still-live delete or replace `boilerplate` warn continues to block clean exit.
   - `<scaffold_drift>`, `<hunk_classification>`, and `<linter_is_truth_for_structure>`: Keep the stronger declared-slot rule. A block of differing lines inside a declared slot is wiki-owned and no repair touches it. State the reason in one clause: reverting an owner's declared refinement destroys a recorded decision while the audit reports success. Separately, an undeclared locked-slot extension that the check reports as acknowledged is preserved the same way `<hunk_classification>` already preserves wiki-has and canonical-lacks extensions, so no restore move fires on it. Rewrite `<linter_is_truth_for_structure>` in place so its "when a check is wrong" passage no longer reads as Accepted-finding-only. Name the three non-overlapping structural routes, and state that each route suppresses or preserves only its own finding class and none substitutes for the others: `- Accepted finding: …` for intentional info-level findings only; acknowledged locked-slot insert-only extensions, which carry no SCHEMA bullet and are visible on the acknowledged channel; and `- Declared boilerplate: …` for intentional locked-slot remove-or-rewrite divergences.
   - `<scaffold_alignment>`: Supersede the customization enumeration so acknowledged locked-slot insert-only extensions and `- Declared boilerplate:` regions sit beside the configured domain, tag taxonomy, declared custom fields, user-added page types, and page-check exclusions, all as wiki-owned customizations preserved on top of the canonical baseline. Acknowledged extensions carry no SCHEMA bullet and are visible on the acknowledged channel. Supersede any reading that scaffold alignment requires verbatim locked-slot equality.
   - `<scaffold_alignment_is_in_scope>`: Supersede the "bring the scaffold forward to match" passage so convergence is additive and does not strip acknowledged locked-slot extensions or declared-slot regions. Extend the preservation list with those two locked-slot routes, alongside the domain, tag taxonomy, declared custom fields, user-added page types, and page-check exclusions.

5. **Report a divergence worth promoting.** Extend `<verify_output>` in [agents/auto_shaper_wiki.md](../plugins/knowledge_management/agents/auto_shaper_wiki.md) so the verify-phase final report names any declared-slot deviation the agent judges generally applicable as a candidate for the shipped template. That is a report line under `<verify_output>`, not an edit. The agent does not modify the templates in this repo from inside a managed wiki. This closes the other half of the gap, because a refinement that only ever lives in one wiki's declaration is invisible to every other wiki generated from the same template.

6. **Teach the workflow once.** Supersede the stale always-warn boilerplate prose in [references/lint_checks.md](../plugins/knowledge_management/skills/wiki/references/lint_checks.md). Rewrite the `boilerplate` table row so insert-only locked-slot additions are classified as extensions on the acknowledged channel rather than a live warn, delete or replace divergences remain a warn with both remedies named, and matching `Declared boilerplate:` honours follow the rule in **Honour the declaration in the runner.** Update the **warn** severity-bucket bullet so a verbatim-boilerplate mismatch is a live warn only for delete or replace, not for an insert-only extension. Supersede `## Iteration loop` so its "If a check is wrong" and `ACKNOWLEDGED` passage names the same three non-overlapping structural routes as the `<inline_iteration_loop>` rewrite below, rather than reading as Accepted-finding-only.

   In [skills/wiki/SKILL.md](../plugins/knowledge_management/skills/wiki/SKILL.md), supersede `<narrow_inline_checks>` so the warn bucket no longer lists every verbatim-boilerplate mismatch unconditionally. Name insert-only extensions as acknowledged-channel and delete or replace as warn. Supersede `<inline_iteration_loop>` so its "check is wrong" and `ACKNOWLEDGED` passage names the three non-overlapping structural routes rather than reading as Accepted-finding-only: `- Accepted finding: …` for info-level findings only; acknowledged insert-only locked-slot extensions with no SCHEMA bullet; and `- Declared boilerplate: …` for intentional locked-slot remove-or-rewrite divergences. Document each locked-slot route's boundary against the info-level acceptance store and the `Page-check exclusions:` walk exclusion, so the three mechanisms do not read as alternatives for one another.

7. **Refresh interim Layer 2 owner-extension contracts.** Rewrite scenarios AS-15, AS-17, and AS-18 in [tests/wiki/layer2/evals.json](../tests/wiki/layer2/evals.json) in place. Each description currently treats a leftover live `boilerplate` warn on the owner insert-only preamble line as expected, and AS-15 names this task as the deferred owner of that classification. Once **Classify the mismatch instead of forcing a verbatim restore.** ships, that interim contract is false, because insert-only owner extensions leave no live `boilerplate` warn. Supersede those description passages so they state that the owner insert-only line is an acknowledged locked-slot extension with no live `boilerplate` warn for that class. Keep each scenario's additive ensure and refresh `log.md` postconditions and grading boundary unchanged.

**Out of scope.** Widening the acceptance store to warn-level findings in general stays with [wiki_lint-accepted-info-suppression.md](archive/wiki_lint-accepted-info-suppression.md) and its `SEV_INFO` boundary. Deciding which slots stay locked stays with [wiki_schema-template-generalization.md](archive/wiki_schema-template-generalization.md).
