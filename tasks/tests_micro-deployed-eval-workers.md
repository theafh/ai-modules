# Micro-deploy the artefacts under test for every staging eval runner through one shared mechanism

## Goal

Every eval runner named under Approach **Adopt in every runner.** loads the skills, agents, and output styles under test from a micro-deployment that the repository's own deploy script builds for that pass from the version under test, and no deployed copy from the user's machine is in its view. One shared mechanism in `tests/lib/` builds that deployment and runs the worker against it, for each of those runners and on both vendors, so a Cursor worker and a Claude worker each load the artefacts through their own native discovery (a skill by name, a named agent, a selected style) in the shape a real deployment gives them. Each pass records which artefact files its worker read, and a pass whose worker read one from outside its micro-deployment fails an integrity check that names the path. The user-visible outcome: an edit to any skill, agent, or style, a dependency such as the base `task` skill included, is measured by the next eval run instead of after the next deploy, and both vendors measure the same deployed shape.

## Context

- **How runners load artefacts today.** Most runners that call `vendor.stage_skill_tree` copy the skill under test into an `artefacts/` directory beside its sandbox (wiki layer 2 also copies the `wiki` hub there), names that copy's path in the worker prompt, and passes its sandbox project as the Cursor `workspace`. No runner stages the other skills its subject reaches by name. Named agents are copied unrendered into the sandbox's `.{claude,cursor}/agents/` by the local `stage_named_agents` copies in wiki layer 2 and `task_auto_check`, and `tests/natural_language/evals/run.py` hands its style to the worker itself. None of them goes through the per-vendor rendering the deploy script applies. `tests/language_humanizer/evals/run.py` stages its copy as a project skill of an isolated root and names that path, a mitigation its comment containing "Traced on 8 October 2026" describes. Each cached runner declares the skills a verdict depends on in `source_roots_for(...)`, which feeds the cache key.
- **What workers read (traced 8 October 2026).** Stream-json read events of real eval runs, with a deployed copy of every repository skill in the user's Cursor and Claude skill directories, showed reads outside the staged set:
  - On Cursor, a `language_humanizer` worker told to read a copy staged outside its workspace read the deployed copy in three of three runs and never opened the staged copy in two of them. A project copy in the workspace did not displace the deployed copy when the prompt named no path.
  - Dependencies resolved outside the staged set. `task_create` (`reconcile-recorded`) read the deployed base `task` skill on Cursor (and ran its deployed scripts) and on Claude, and the rule those evals test lives in that base skill. `skill_doctor` (`scope_hub_family`) read the deployed `ai_instruction_formatting` and `ai_instruction_writing` on Cursor. `guardrail_audit` (`presence_gate`) read the `guardrail` hub from the repository checkout, which its in-repo sandbox can reach.
  - A Claude worker's init event lists every deployed user-level skill.
- **What takes deployed copies out of view (verified 8 October 2026).** On Cursor, a scratch `HOME` whose `Library` links back to the real one authenticates and hides the user's deployed skills, while `CURSOR_CONFIG_DIR` alone leaves them in view, because skill discovery follows the home directory. On Claude, a scratch `CLAUDE_CONFIG_DIR` with `CLAUDE_SECURESTORAGE_CONFIG_DIR` set to the empty string authenticates and hides the user's deployed skills and agents. [The agent_spinner role-definitions task](ai-dev_agent-spinner-role-definitions.md) records that route under **Hiding deployed roles on Claude**. With every repository skill deployed into that scratch home or config directory, both workers loaded the deployed copy by name with no path in the prompt. The evidence is on [the Cursor entity page](../wiki/entities/cursor.md) and [the Claude Code entity page](../wiki/entities/anthropic-claude-code.md), each linking its probe notes.
- **Where each vendor loads each artefact type in print mode.** These facts sit on the same two entity pages:
  - **Skills:** Cursor reads the home's `.cursor/skills/` (and the `.claude`, `.codex`, `.grok`, and `.agents` skill directories beside it), while Claude reads its config directory or the project's `.claude/skills/`.
  - **Named agents:** Cursor reads only the workspace's `.cursor/agents/` (the user's deployed roles did not appear on 4 October 2026), while Claude reads its config directory or the project's `.claude/agents/`.
  - **Styles:** Cursor applies only a project `.cursor/rules/*.mdc` with `alwaysApply: true` (a home `rules/` file was not injected on 6 October 2026), while Claude applies `output-styles/` plus the `outputStyle` key in its config directory's or the project's `settings.json`; with `isolation_args` (`--setting-sources project,local`) that worker reads only project and local settings, so the style file and `outputStyle` must sit under the project's `.claude/` (the Claude Code entity page records that for `--setting-sources project,local`).
- **The deploy script already performs a micro-deployment.** `deployment/deployment.sh --project-dir <dir> --target claude|cursor` copies skills, writes a rendered copy of each agent per vendor, generates the Cursor style rule `.cursor/rules/<style>.mdc`, and for Claude copies the output style and merges `.claude/settings.json`. `--global` writes the user-level layout under `$HOME`, which `tests/deployment/script_tests/run.sh` drives with `HOME` pointing at a scratch directory. `--type` filters artefact types and `--target` vendors, and nothing filters named artefacts. Every run that writes appends to `deployment/deployed_artefacts.log`, which `make uninstall` reads, and the deployment script tests back that log up and restore it around their runs, which concurrent eval passes cannot do safely.
- **Why it matters.** A deployed copy matches the repository only until something changes, which is exactly when an eval matters. The cache sharpens that for dependencies: the key already hashes the base `task` skill, so editing it invalidates the cache, and the re-run then measures the deployed base skill.
- **Shared surfaces.** [The agent_spinner runner-modes task](tests_agent-spinner-runner-modes.md) adds agent staging with its own frontmatter rendering, which the micro-deployment replaces for every agent `discover_artifacts` names with the deploy script's rendering, teaches `build_print_cmd` an optional output format so Cursor can emit `stream-json` in place of fixed `text`, and adds a per-vendor stream-json parser that yields the final message, `session_id`, and vendor-neutral tool records; whichever lands second adopts the other's helper for each shared surface, and the worker-run helper here adopts that parser when present else teaches a minimal one and derives read provenance from those tool records. The shared Pattern A eval-runner task and the cache-key granularity task, both named under **Out of scope:** below, edit `tests/lib/` and the shape of `source_roots_for`; whichever declaration shape exists when this lands is the one that feeds the micro-deployment. The per-runner `tests_*-parallel-evals.md` tasks edit the same `run.py` files, and this task's change there is a call swap either order absorbs. [The wiki layer-2 runner-dedup task](tests_wiki-layer2-runner-dedup.md) also edits `tests/wiki/layer2/run.py` (replacing `stage_named_agents` with `vendor.stage_skill_tree`), and this task's change there is a call swap either order absorbs.

## Approach

1. **Deploy-script support.** In `deployment/deployment.sh`, read an override for the deployed-artefacts log path where `DEPLOYED_ARTIFACTS_LOG` is set, so a test deployment writes its log inside its own scratch tree and `deployment/deployed_artefacts.log` stays untouched. Add `--only NAME[,NAME…]` beside `--type` and `--target`, so a run deploys exactly the named artefacts. Each NAME matches the `name` field of a `name|type|rel_path` line `discover_artifacts` emits: the skill directory basename, or an agent or style file's basename without its extension. Document both in the script's help and header comment, and cover both in `tests/deployment/script_tests/run.sh`.
2. **One micro-deploy helper.** Add `tests/lib/micro_deploy.py`. For one pass it creates a scratch home outside every tree a grader compares, requires a caller-supplied sandbox project (`proj` / `sandbox_proj`) as `--project-dir` and as the Cursor `workspace`, and runs the deploy script with the log override and the runner's declared artefacts. A `--global` run with `HOME` set to the scratch home writes the user-level layout, and a `--project-dir` run into that sandbox project writes the types a vendor loads only at project scope (Cursor's agents and style rules, and Claude's output styles plus project `outputStyle` when the worker keeps `isolation_args`). The helper owns the scratch home and the overlays that hide the user's deployed copies; it does not own host-instruction isolation (`create_sandbox_root` remains create-and-teardown only, and that isolation root is never `--project-dir` or the Cursor `workspace`). It returns a context manager or closeable handle that yields the worker environment for the vendor, built by starting from `vendor.worker_env` and overlaying the per-vendor keys below, that sandbox project as the Cursor `workspace`, and a path map from each declared artefact name to its deployed path under the scratch home or that sandbox project, so every prompt that names a skill, agent, or style path can point inside the micro-deployment:
   - **Cursor:** overlay `HOME` at the scratch home, with the scratch home's `Library` linked to the real one so the stored login keeps working.
   - **Claude:** overlay `CLAUDE_CONFIG_DIR` at the scratch home's `.claude`, with `CLAUDE_SECURESTORAGE_CONFIG_DIR` set to the empty string.
   It preflights the worker against that environment and stops the eval with the CLI's own message when authentication fails, which also covers a platform whose login store sits somewhere other than `Library`. Closing the handle removes the scratch tree, unlinking `Library` first.
3. **One declaration per runner.** Each runner declares once every skill, agent, and style its evals' workers may load, by name or by a path the prompt names, and that declaration feeds both the `--only` list and the cache key's `source_roots`, so what is deployed, what is hashed, and what a worker may read stay one list. Membership follows load reach, not only what today's `source_roots_for` returns: `skill_doctor`'s `source_roots_for` returns only the `skill_doctor` tree, yet Context records that `scope_hub_family` read `ai_instruction_formatting` and `ai_instruction_writing`, so those names enter that runner's declaration. A runner deploys a style only when its evals test that style, because a selected style shapes every reply; today that is `natural_language`, whose evals test the style under test.
4. **One worker-run helper with read provenance.** Add to `tests/lib/micro_deploy.py` a helper that runs a print-mode worker with the vendor's streaming output (`--output-format stream-json` on Cursor, `--output-format stream-json --verbose` on Claude), building the command through `vendor.build_print_cmd` after amending that helper so Cursor's `--output-format stream-json` replaces its fixed `--output-format text` (adopting the optional output-format shape the agent_spinner runner-modes task already carries when present, else teaching the same plain-text-default shape here), so extra arguments and prompt placement keep working. The helper accepts caller-supplied `extra_args` and forwards them unchanged into `vendor.build_print_cmd`. It adopts the agent_spinner runner-modes **Stream parser.** when present, else teaches a minimal per-vendor parser that yields the final message, `session_id`, and vendor-neutral tool records, and derives every path the worker read, globbed, or named in a shell command from those tool records. It decodes partial output through `tests/lib/worker_io.py` on timeout and returns the exit code, the final result text the runners write to `response.txt` today, stderr, and that path list. A shared classifier marks a path as out of set when it names a skill, agent, or style file outside the scratch home and the sandbox project that is `--project-dir` and the Cursor `workspace`. Each runner adds an integrity check named `artefacts_read_from_micro_deployment` that fails a pass with any out-of-set path and records the path list in that pass's verdict.
5. **Adopt in every runner.** Switch every runner that calls `vendor.stage_skill_tree` or a local `stage_named_agents`, and the style staging in `tests/natural_language/evals/run.py`, to the micro-deploy helper and the run helper. Runners that already isolate through `tests/lib/worker_isolation.py` keep `create_sandbox_root` for isolation create and teardown and keep `isolation_args`, pass their sandbox project to the micro-deploy helper as `--project-dir` and the Cursor `workspace` per Approach **One micro-deploy helper.**, and pass `isolation_args` to the worker-run helper as its `extra_args`. Agents that are not among the names `discover_artifacts` emits are staged after the micro-deploy returns through `vendor.stage_agents` when present (the helper the agent_spinner runner-modes task Approach **Agent staging.** adds), else through a minimal copy helper this task teaches beside the other `tests/lib/` helpers, and those names never enter the runner's `--only` list. `natural_language` writes the `nl_load_marker` style into that sandbox project's `.claude/output-styles/` after micro-deploy returns and never puts that name in `--only`; its marker preflight proves the style route with `NL_STYLE_LOAD_OK`. Each adopter rewrites every skill, agent, or style path its worker prompt names onto the micro-deploy helper's path map: `guardrail_audit` formats `{hub_path}` from the map entry for the `guardrail` hub rather than the repository checkout path `stage.sh` prints today, and wiki layer 2's `rewrite_prompt_paths` replaces each of its source paths with the matching map entry rather than a `stage_skill_tree` output. Fold the project-skill staging in `tests/language_humanizer/evals/run.py` into the shared helper; after the worker returns, copy the skill file the path map names for `language_humanizer` into `pass-<n>/sandbox/`, then close the handle, and rewrite `## Isolation from the host` in `tests/language_humanizer/README.md` so it describes that path-map copy rather than project-skill staging. Remove the local `stage_named_agents` copies once no caller remains. Adopters under this step stop calling `vendor.stage_skill_tree` for skill trees; leave the helper itself in place while the agent_spinner runner-modes task still routes `agent_files` through it and proves staging through that path, keeping that adopt-or-teach carve-out for fixture agents.
6. **Tests.** Add `tests/lib/test_micro_deploy.py`. It runs the real deploy script into a scratch tree with no model call and checks the following:
   - The per-vendor layout: skills in the scratch home, Cursor's agents and style rules under the sandbox project that is `--project-dir`, Claude's agents in its config directory, and Claude's output style and `outputStyle` under that same sandbox project's `.claude/` when the worker keeps `isolation_args`.
   - That the micro-deploy helper returns a path map covering every declared artefact for each vendor layout, including the skill under test and at least one additional declared skill.
   - That the helper accepts a caller-supplied sandbox project and deploys project-scoped artefacts into it as `--project-dir`, and that the handle yields that same path as the Cursor `workspace`.
   - That `--only` limits the deployment to the named artefacts, and that `deployment/deployed_artefacts.log` comes out byte-identical.
   - The worker environment per vendor: a returned mapping that keeps every key `vendor.worker_env` sets for that vendor and carries the Approach **One micro-deploy helper.** overlays on top, stream parsing for both vendors from recorded event lines through the adopted-or-taught parser with provenance derived from its tool records, and the classifier on in-set and out-of-set paths.
   - That the worker-run helper forwards a caller-supplied `extra_args` list into the built command (proved with a recorded `isolation_args` list for Claude).
   - That the worker-run helper's Cursor command carries `--output-format stream-json` once and does not carry `--output-format text`.
   - That on a simulated timeout the worker-run helper decodes stdout and stderr through `tests/lib/worker_io.py` the same way `eval_runner.timeout_streams` does.
   - That an auth preflight failure stops the eval and surfaces the CLI's own authentication message.
   - That closing the handle leaves the scratch tree gone, with the scratch home's `Library` unlinked before removal.
7. **Docs.** Rewrite in place, in lockstep, the canonical rule in `tests/CLAUDE.md` (the `### Model policy` passage beginning "Workers path-read the skill under test") and in `tests/AGENTS.md` (`### Skill and agent loading`). One rule remains: workers load artefacts only from the per-pass micro-deployment, deployed copies stay out of view on both vendors, and the provenance check enforces it. Update the staging sentence under `## Vendor switch` in `tests/README.md` to match.

**Out of scope:**

- `tests/trigger_evals/`, which measures the deployed skill tree by design and keeps doing so.
- Changing `tests/lib/worker_isolation.py` or owning host-instruction isolation, since this task controls which artefacts a worker loads, not which host instruction files it reaches.
- The shared job pool and per-job `TMPDIR`, which [the shared Pattern A eval runner](archive/tests_shared-pattern-a-eval-runner.md) owns.
- Narrowing cache keys per eval, which [the cache-key granularity task](tests_eval-cache-key-granularity.md) owns.
