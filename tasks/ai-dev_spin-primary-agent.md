# Trial and promote the spin primary agent

## Goal

The `spin` primary agent earns a place in the `ai_dev` plugin, or the trial records why it does not. The trial runs the inline copy on three delegation jobs and checks whether it loads `agent_spinner` before the first helper, runs the probe and ledger, routes checks through `auto_checker_spinner`, and closes the run. When it holds, `plugins/ai_dev/agents/spin.md` ships as a `mode: primary` agent beside Build and Plan; when it does not, the trial record names the failures and the promotion waits.

## Context

- A trial copy of the agent lives in the global OpenCode agents directory as `spin.md`. It is a `mode: primary` agent that pins `model: seibertgpt/deepseek-v41-flash-high`, carries a system prompt that requires `agent_spinner` before any delegation, and declares a nested `permissions:` list whose one rule allows `subagent` on `*`. It appears in the agent picker beside Build and Plan, is not the default, and is not deployed from this repository.
- The repository's agent sources carry scalar frontmatter only. `scripts/lint_frontmatter.py` reports `indented line without a parent key (nested mappings are outside the accepted subset)`, so the trial copy's nested `permissions:` block cannot ship as written. Capability is expressed through the `readonly:` and `tools:` scalars, as `plugins/ai_dev/agents/auto_checker_spinner.md` does with `readonly: true` and `tools: Read, Grep, Glob`.
- Primary mode is expressed with a vendor-prefixed key. `rewrite_agent_frontmatter` in `deployment/deployment.sh` maps `OPENCODE_mode: primary` to `mode: primary` for the OpenCode target and drops it for every other target, through its `^([A-Z]+)_([A-Za-z0-9_-]+:.*)$` branch, so the source states primary mode without leaking an OpenCode-only key into another harness's agent schema.
- `generate_opencode_agent` reads `description`, `model`, `readonly`, and `tools` from the rewritten source and hard-codes `printf '%s\n' 'mode: subagent'`, so a source mode is dropped today. Its writable branch emits `effect: allow` rules for `read`, `glob`, `grep`, `edit`, `shell`, `skill`, and `subagent`. That set is a superset of the one capability the trial copy's single `permissions:` rule grants, `subagent` on `*`; the trial copy grants nothing else. The same four-key whitelist drops `version`, `background`, `effort`, and `model_reasoning_effort`, so the generated `auto_checker_spinner` carries none of the source's `version: 1.0.0`, `background: false`, `effort: max`, or `model_reasoning_effort: xhigh`.
- The primary agent is meant for the OpenCode target, the only harness whose agent surface expresses a primary mode. Antigravity's generator writes `mainAgent: false` unconditionally, and the VS Code, Cursor, Claude, and Codex generators carry no primary concept, so a deployed copy on those targets stays a non-primary agent.
- The user wants to try the agent from the picker, where it appears, before enforcing it with a prompt hook or moving it into the plugin. This task is the promotion decision after that trial, not the hook.
- The trial's proof surface is a tracked record, not a gitignored eval run. `tests/agent_spinner/RUNBOOK.md` documents how each measurement is run and already holds recorded measurements under its `### Recorded measurements` heading, so it is the natural home for a `## Spin agent trial` section.
- The trial measures the checker route, the follow-up contract, and the stopped-run close, so it runs after [the checker-role task](ai-dev_agent-spinner-checker-role-default.md), [the follow-up task](archive/ai-dev_agent-spinner-followup-contract.md), and [the stopped-close task](archive/ai-dev_agent-spinner-stopped-run-close.md) ship; a trial before them measures the defects those tasks fix.
- Versioning and the generic gates follow the standing repo rules; this task adds only the checks its own change needs.

## Approach

The trial records six checks on each of the three delegation runs, and a seventh check on a fourth, stopped-run job. The first five are the contract checks that set the promotion bar: (1) loaded `agent_spinner` before the first helper, recorded with the ledger row id at load time or the row count then standing (zero), so the ordering is evidence rather than a claim, (2) ran the capability probe with `init --probe`, (3) wrote the phase plan before the first helper, (4) routed checks through `auto_checker_spinner`, and (5) reached a clean `close`. The sixth is recorded beside them: a resumed helper call carried both `agent` and `description`. The seventh is the stopped-run close that Context names: the stopped-run job stops a run mid-wave with `agent_spinner`'s `stop` verb, whose STOP file halts new dispatch and lets running helpers finish, and records the following `close --stopped` exiting 0. Every row also records the permission posture the run ran under, so a run that held only because a broader permission set masked a defect stays visible.

1. Confirm the deployed copies before measuring anything, and record the observed state. The trial runs the globally deployed `agent_spinner` skill and `auto_checker_spinner` agent. Measured on 2026-11-27, both are already current: the deployed `~/.config/opencode/skills/agent_spinner/SKILL.md` diffs clean against its repository source, and the deployed `~/.config/opencode/agents/auto_checker_spinner.md` carries a body byte-identical to its repository source and generated permissions that match that source's `readonly: true` with `tools: Read, Grep, Glob` (`mode: subagent`, an edit deny, read/glob/grep allow rules, and a shell deny because the `tools:` allowlist carries no `Bash`). The refresh is therefore an idempotent confirmation, not a repair: ask the user to run `./deployment/deployment.sh --global --target opencode --only agent_spinner,auto_checker_spinner` (the deploy is user-gated by the standing rule), then record the state it reproduces under the `## Spin agent trial` heading — the repository commit from `git rev-parse --short HEAD`, a clean `diff` of the copied skill against its repository source, and the agent's body-identity and permission-rule comparison above. Record the one measured caveat beside it: `generate_opencode_agent` reads only `description`, `model`, `readonly`, and `tools`, so it drops the source's `version: 1.0.0`, `background: false`, `effort: max`, and `model_reasoning_effort: xhigh`; the deployed checker therefore carries no effort setting and runs at the harness default, so the trial measures it below its source's declared depth and the record says so.
2. Drive the three runs through the picker, the single path. The user runs each job from the agent picker, where `spin` sits beside Build and Plan. The implementer hands the three picker sessions to the user and waits for the three returned sessions — each with its session id and ledger path — before writing any recording step. The three jobs are a per-artifact fan-out audit, a serial implement/audit loop over one task, and a read-only corpus sweep. The serial implement/audit loop is the job that resumes a helper: after the auditor returns, the orchestrator sends the auditor's findings back to the same implementer session, and that resumed call is the one the sixth check reads. Record the permission posture each run ran under as the harness reported it, so the check set is read against the permission set that produced it.
3. Fall back to the headless route only when the picker route is unavailable. The documented fallback is `opencode run --agent spin "<prompt>"`, which takes the agent by name through the `--agent string` flag that `opencode run --help` documents; the implementer drives each job that way and records the session id it reports. When neither route is available — the picker does not list `spin`, and `opencode run --help` carries no `--agent` — the implementer records the probe output under the `## Spin agent trial` heading, creates no promotion artifact, and hands the task to `task_finish` as `deferred` with that reason.
4. Record the three delegation runs and the stopped-run job in `tests/agent_spinner/RUNBOOK.md` under a `## Spin agent trial` heading, one row per run carrying the date, the model, the job, the permission posture the run ran under, each of the six checks for a delegation run (the seventh for the stopped-run job), and the outcome. Name each failure with the ledger row id and its state (`pending`, `dispatched`, `violation`, `accepted`, `inability`, `failed`, `unreturned`, `unknown`, or `dropped`) rather than a session id alone.
5. When at least two of the three runs hold all five contract checks, add `plugins/ai_dev/agents/spin.md` with this frontmatter and the trial copy's system prompt as its body:

   ```yaml
   ---
   # lint: allow-no-h1 — the body opens with its runtime instruction.
   name: spin
   description: "Orchestrating primary agent that runs a delegation job through agent_spinner: capability probe, written phase plan, run ledger, refute-by-default checks through auto_checker_spinner, and a clean close. Use when a job splits into independent units and helpers are available; work inline for a single read or a one-file edit."
   version: 1.0.0
   model: inherit
   OPENCODE_mode: primary
   readonly: false
   ---
   ```

   The `# lint: allow-no-h1` comment is the opt-out `auto_checker_spinner.md` and `auto_writer_spinner.md` already carry: the body opens with its runtime instruction, so it needs no H1. `readonly: false` with no `tools:` allowlist is the settled permission shape: `generate_opencode_agent`'s writable branch maps it to allow rules for read, glob, grep, edit, shell, skill, and subagent, which carries the `subagent` capability the trial copy grants. The model differs deliberately: the trial copy pins `seibertgpt/deepseek-v41-flash-high`, while the promoted source states `model: inherit`, which `is_model_inherit_value` drops from the generated file so the deployed agent inherits the harness's model. The trial therefore measures the pinned model, and the record says so.
6. Make the deployer carry the mode. In `generate_opencode_agent`, capture a `mode` key from the rewritten source beside `model`, `readonly`, and `tools`, and emit it in place of the hard-coded `mode: subagent`, defaulting to `subagent` when the source states none. Update the OpenCode agent row of `deployment/README.md`'s agent mapping table to say the source mode passes through, and extend `tests/deployment/script_tests/run.sh` beside its `^mode: subagent$` assertions with `assert_contains "$PROJECT_DIR/.opencode/agents/spin.md" '^mode: primary$'`, keeping the subagent assertions for the sources that state no mode.
7. Register the agent in `plugins/ai_dev/README.md`'s `## Agents` list, in the root `README.md` layout tree under `plugins/ai_dev/agents/`, and in the deployment harness's deployed-file assertions. Add `spin` to the `description` field of both `plugins/ai_dev/.claude-plugin/plugin.json` and `plugins/ai_dev/.codex-plugin/plugin.json`, and to both marketplace registration descriptions at `.claude-plugin/marketplace.json` and `.agents/plugins/marketplace.json`, beside the `agent_spinner`, `auto_checker_spinner`, and `auto_writer_spinner` entries they already name, because CHARTER.md requires plugin metadata, local marketplaces, and documentation to describe the same shipped component set. Prove four-way version agreement by running `bash tests/format_rust/script_tests/run.sh`, whose `check_plugin_version_lockstep ai_dev` check reads the version from `plugins/ai_dev/.claude-plugin/plugin.json` and requires `.codex-plugin/plugin.json`, `.agents/plugins/marketplace.json`, and `.claude-plugin/marketplace.json` to match it.
8. Rewrite the advisory pin in `tests/agent_spinner/script_tests/run.sh`. Its `check "no agent definition cites agent_spinner"` runs `tree_lacks "$REPO_ROOT/plugins/ai_dev/agents" 'agent_spinner'`, a recursive grep over every agent file, so a promoted `spin.md` — whose description and body name `agent_spinner` — fails it. Narrow the pin so it admits `spin.md` as the orchestrator exception while still proving every helper role cites no `agent_spinner`: keep the directory-wide check on every agent file except `spin.md`, for example by requiring `grep -REil 'agent_spinner'` under `plugins/ai_dev/agents` to match `spin.md` alone and adding a second check that no other file in that directory matches. Record the rationale in a comment beside the check: the pin guards the one-way advisory from the skill to the helper roles; the primary orchestrator is the caller, not a helper, so its citation is the intended direction.
9. After promotion, ask the user to run `./deployment/deployment.sh --global --target opencode --only spin`; the deploy is user-gated by the standing rule. It writes `~/.config/opencode/agents/spin.md`, the same path the hand-written trial copy occupies, so the generated file replaces the trial copy rather than coexisting with it: `generate_opencode_agent` removes the destination and rewrites it, and the deployer records a backup. Record that replacement explicitly in the `## Spin agent trial` section — before the deploy the path held the hand-written copy with the pinned model and the nested `permissions:` rule, after it the path holds the generated frontmatter (`mode: primary`, no `model:` line because `model: inherit` is dropped, and the generated allow rules), and the deploy log names the plugin source. That record is the removal confirmation, and no second file is deleted.
10. When fewer than two runs hold, leave the inline copy in place, record the failures, and hand the task to `task_finish` as `deferred` with the trial record as the reason. Do not add a prompt hook; the hook is a later decision.

**Out of scope:** a prompt hook or any harness-level enforcement; the user is trialling the agent first. Also out of scope: making `spin` the default agent, which would over-trigger on every prompt.

## Acceptance

- `tests/agent_spinner/RUNBOOK.md` carries a `## Spin agent trial` section with three delegation-run rows plus one stopped-run row; each delegation row names the run's date, model, job, the permission posture it ran under, the six checks, and the outcome, and the stopped-run row records `agent_spinner`'s `stop` verb followed by `close --stopped` exiting 0 after a mid-wave stop.
- The `## Spin agent trial` section records the resumed helper call in the serial implement/audit loop — the call that sends the auditor's findings back to the same implementer session — with both `agent` and `description` present.
- The `## Spin agent trial` section records the observed deployed state before the runs — the repository commit; a clean `diff` of the copied `agent_spinner` skill against its repository source; and, for the `auto_checker_spinner` agent, that its deployed body is byte-identical to its repository source and its generated permissions match `readonly: true` with `tools: Read, Grep, Glob` (`mode: subagent`, edit deny, read/glob/grep allow, shell deny) — states that the refresh is an idempotent confirmation, records the measured caveat that `generate_opencode_agent` drops `version`, `background`, `effort`, and `model_reasoning_effort` so the deployed checker runs at the harness default effort, and names the session id and ledger path for each of the three runs.
- The `## Spin agent trial` section states which of the five contract checks hold per run, and `plugins/ai_dev/agents/spin.md` exists exactly when at least two runs hold all five; no promotion artifact is added on a lower count.
- When promoted, `plugins/ai_dev/agents/spin.md` carries the `# lint: allow-no-h1` frontmatter comment, `name: spin`, the dual-audience `description` quoted in the Approach, `version: 1.0.0`, `model: inherit`, `OPENCODE_mode: primary`, and `readonly: false` with no `tools:` allowlist, with the trial copy's system prompt as its body.
- When promoted, `bash tests/deployment/script_tests/run.sh` passes with an assertion that the deployed `.opencode/agents/spin.md` copy carries `^mode: primary$` while its existing `^mode: subagent$` assertions still pass, and `deployment/README.md`'s OpenCode agent row states that the source mode passes through.
- When promoted, `bash tests/agent_spinner/script_tests/run.sh` passes with the rewritten advisory pin, which admits `spin.md` as the only agent file citing `agent_spinner` and still proves every helper role cites none, and the check carries the one-way-advisory rationale in a comment.
- When promoted, the agent appears in `plugins/ai_dev/README.md`'s `## Agents` list and in the root `README.md` layout tree under `plugins/ai_dev/agents/`, and both plugin manifests' `description` fields and both marketplace registration `description` fields name `spin` beside `agent_spinner`, `auto_checker_spinner`, and `auto_writer_spinner`.
- When promoted, `bash tests/format_rust/script_tests/run.sh` passes, its `check_plugin_version_lockstep ai_dev` checks included, so both plugin manifests and both marketplace registrations agree on one version.
- When promoted, the `## Spin agent trial` section records the post-deploy state of `~/.config/opencode/agents/spin.md` and states that the generated file replaced the hand-written trial copy at that path.
- When deferred because fewer than two of the three runs held the contract checks, the task is archived as `deferred` and the RUNBOOK section names the failing checks with the ledger row id and state that show each one. When deferred because neither route was available, the probe output is recorded under `## Spin agent trial`, no `plugins/ai_dev/agents/spin.md` exists, and the task is archived as `deferred` with that reason.
