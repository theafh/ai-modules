# wiki_import

<wiki_import>
  <role>Resource-to-wiki reconciliation editor. Capture the resource the user pointed to as raw source, mine the captured raw for durable knowledge, diff against the wiki, and triage the result before any wiki-page write on an explicit import invocation. A wiki edit that draws on an artifact supplied mid-conversation takes the `<capture_raw_mid_conversation>` branch instead.</role>
  <authority>The `wiki` skill's `SKILL.md` is the source of truth for wiki structure, discovery, orientation, raw capture, ingest, and lint. That hub states each shared rule once and this front end inherits it by citing the hub block by tag, so read the cited block there rather than expecting a second statement here.</authority>
  <orient_first_top>**Read `$WIKI/SCHEMA.md` once at the start of any session that activates this skill.** The schema declares the domain, page-type enum, tag taxonomy, and conventions every classification and write must honor. The `wiki` skill's `<orient_first_top>` block states why that read is never skipped, and its `<resuming_an_existing_wiki>` block owns the index and recent-log pass the orientation step below follows.</orient_first_top>
  <objective>Pull a single named external resource into the wiki end to end: persist the raw, classify each candidate by page type and relation to existing content, surface conflicts between the resource and existing wiki pages, and propose reconciliations the user can accept page by page. That page-by-page proposal belongs to an explicit import invocation; the mid-conversation entry point is `<capture_raw_mid_conversation>`.</objective>
  <policy>
    <resolve_skill_bundle>Resolve `$WIKI_SKILL` before the first bundled tool call and before `$WIKI`. It is the installed `wiki` skill bundle holding the scripts and reference docs this skill invokes. The `wiki` skill's `<resolve_wiki_skill_bundle>` block is the canonical resolution order, so follow it rather than guessing a path. From this skill's own directory the sibling hub is `../wiki`. Every `$WIKI_SKILL/...` path below resolves through that block.</resolve_skill_bundle>
    <resolve_first>Resolve `$WIKI` through the `wiki` skill's discovery flow before reading the resource. Honor exit-2 ambiguity by presenting candidates and asking the user.</resolve_first>
    <orient_first>Read `SCHEMA.md`, `index.md`, and the recent `log.md` entries before diffing, so the diff runs against an understood corpus and domain. The `wiki` skill's `<resuming_an_existing_wiki>` block owns that pass, including its entry-boundary log read.</orient_first>
    <confirm_resource>Confirm the resource pointer (URL, file path, paste, PDF, transcript, meeting note, internal note) and its kind with the user before fetching, and confirm the target slug the confirmed kind lands under. The `wiki` skill's `<capture_raw_source>` block carries the `raw/` bucket list and the edge-case route to `$WIKI_SKILL/references/raw_taxonomy.md`, so settle the bucket from that list rather than restating the mapping here. This pointer-and-kind question belongs to an explicit import invocation; the mid-conversation entry point is `<capture_raw_mid_conversation>`.</confirm_resource>
    <capture_raw>Route the resource through the `wiki` skill's Ingest §1, fetching and converting (URL), extracting (PDF), or filing (paste, meeting, note), into `raw/<kind>/<slug>.md` with the required frontmatter (`ingested`, body-only `sha256`, plus `source_url` for an externally-published source or a relative in-repo `source_path`; a local file outside the repo takes no path, so excerpt it into the body and note its locality). The `### raw/ Frontmatter` contract in `$WIKI_SKILL/references/template_schema.md` is canonical for these field meanings and for how a mislabeled or legacy sidecar reconciles onto them, so cite it rather than restating the moves. Write the sha256 with `python3 "$WIKI_SKILL/scripts/compute_sha256.py" raw/<kind>/<slug>.md`. Never invent the value by hand. On re-ingest of the same source, follow the hub's **Re-ingest compares before it writes** rule in `<capture_raw_source>`, which owns the ordering that keeps the recorded hash comparable to what the source said last time. An owner's in-place edit of a sidecar body, such as a redaction, refreshes the hash with no log entry and reaches the user only, as the hub's `<session_detail_out_of_wiki>` block requires. Both entry points run this block. Excerpt raw text that may carry markdown-sensitive characters (HTML-like tags, backticks, headings) as a fenced text block rather than a blockquote: pick the smallest backtick fence count of three or more that is longer than any backtick run already inside the content, so a four-backtick example takes a five-backtick fence and the tokens stay unparsed.</capture_raw>
    <capture_raw_mid_conversation>The implicit entry point into `<capture_raw>`. When a wiki edit draws on an artifact the conversation supplied and the wiki does not own, a paste, chat-session transcript, meeting note, screenshot OCR, voice memo, or internal scratch, capture it the same way whether or not the user called it an import: classify kind and slug per `$WIKI_SKILL/references/raw_taxonomy.md`, write the `raw/<kind>/<slug>.md` sidecar under the `<capture_raw>` contract, and add its wiki-root-relative path to the consuming page's `sources:` frontmatter. Then return to the calling flow that requested the page write, so that page write completes in the same turn. The pointer-and-kind confirmation in `<confirm_resource>` and the three-H2 proposal with its approval gate in `<propose_then_act>` belong to an explicit import invocation, so this branch runs neither; `<capture_raw>` remains the one capture rule behind both entry points. The `wiki` skill's `<non_canonical_raw_artifact_ingestion>` block owns the boundary against the `## Derived from` channel, so apply it when deciding whether the artifact is captured or pointed at.</capture_raw_mid_conversation>
    <mine_resource>Read the captured raw end to end. Extract durable claims, decisions, definitions, conventions, comparisons, workflows, and named entities. Skip passing mentions, minor details, and material outside the wiki's stated domain in `SCHEMA.md`.</mine_resource>
    <classify>For each candidate, pick a page type from the `wiki` skill's enum and tag it NEW, EXTEND, CONFIRM, or CONFLICT against `$WIKI`. Honor the page-threshold rules from the `wiki` skill: a passing mention does not earn a page.</classify>
    <surface_contradictions>For every CONFLICT, capture both excerpts verbatim, name the disagreement dimension (factual / definitional / scope / recency / source-quality), and offer two or three concrete reconciliation paths.</surface_contradictions>
    <propose_then_act>In an explicit import invocation, emit the proposal and wait for user selections before any wiki-page write. The raw capture in step 4 stays; only the entity, concept, comparison, summary, query, and procedure writes wait. A mid-conversation artifact runs `<capture_raw_mid_conversation>` instead.</propose_then_act>
    <defer_writes>In an explicit import invocation, route approved NEW and EXTEND items through the `wiki` skill's Ingest flow (steps 3 to 6). Route approved CONFLICT items through its contested-page protocol (`contested: true`, `contradictions:` frontmatter, both positions recorded with dates and sources). The mid-conversation entry point is `<capture_raw_mid_conversation>`.</defer_writes>
    <single_resource>Source material for the proposal is the captured raw only. Skip claims the resource did not establish, even when they are true in the broader domain.</single_resource>
    <too_large_to_read_in_one_shot>When a `Read` exceeds the token cap, follow the `wiki` skill's `<too_large_to_read_in_one_shot>` block for the size-then-chunk and locate-then-Read strategies. It applies unchanged to the long transcripts and dense papers this import routinely reads.</too_large_to_read_in_one_shot>
    <list_before_manipulating_unfamiliar_paths>Before writing into a `raw/<kind>/` bucket you have not recently confirmed on disk, list it once (`ls "$WIKI/raw/<kind>/"`). The `wiki` skill's `<list_before_manipulating_unfamiliar_paths>` block carries the rule and why it exists; this note keeps the raw-bucket check at the point of use.</list_before_manipulating_unfamiliar_paths>
  </policy>
  <steps>
    <step>Confirm the resource pointer and its kind (explicit import invocation). If the user supplied only "this link" or "that paper", request the URL or path explicitly before continuing. A mid-conversation artifact enters through `<capture_raw_mid_conversation>`.</step>
    <step>Run `"$WIKI_SKILL/scripts/discover_wiki.sh"` and resolve `$WIKI`. On exit 2, present candidates in walk order and stop until the user picks.</step>
    <step>Read `SCHEMA.md`, `index.md`, and the recent `log.md` entries per the `wiki` skill's `<resuming_an_existing_wiki>` block.</step>
    <step>Capture the resource into `raw/<kind>/<slug>.md` per the `wiki` skill's Ingest §1 (frontmatter, body-only sha256 via `python3 "$WIKI_SKILL/scripts/compute_sha256.py"`, drift check on re-ingest).</step>
    <step>Read the captured raw end to end. Build a list of durable items, each with title, suggested page type, target slug, and an excerpt anchor into the captured raw.</step>
    <step>Search `$WIKI` for each item (index plus recursive grep for 100+-page wikis). Tag NEW, EXTEND, CONFIRM, or CONFLICT. For CONFLICT items, capture both excerpts verbatim.</step>
    <step>Emit one report under three H2 headings: `## New pages`, `## Extensions to existing pages`, `## Contradictions to reconcile`. Skip CONFIRM entries unless the user asked for a full inventory. This proposal is the explicit import invocation's output; the mid-conversation entry point is `<capture_raw_mid_conversation>`.</step>
    <step>On approval, open this batch's work-unit entry in `log.md` before routing any approved write: `## [YYYY-MM-DD HH:MM] import | Source Title — N new, N extended, N contested`. Route each item through the `wiki` skill's matching flow, whose log writes fold into that open entry under the hub's `<appending_to_log>` rule, then run `python3 "$WIKI_SKILL/scripts/lint.py"` and finalize the same entry's counts and file list in place instead of appending a second one. The approval gate belongs to the explicit import invocation; the mid-conversation entry point is `<capture_raw_mid_conversation>`.</step>
  </steps>
  <output_contract>
    <proposal_format>For an explicit import invocation: three H2 sections. Each entry: title, suggested type, target path, excerpt anchor into the captured raw. Contradictions also carry wiki excerpt, raw excerpt, disagreement dimension, and ≥2 reconciliation options.</proposal_format>
    <no_wiki_page_writes_before_approval>During an explicit import invocation's proposal phase, skip every entity, concept, comparison, summary, query, and procedure write. The raw capture is the only write that lands before approval there. The mid-conversation entry point is `<capture_raw_mid_conversation>`.</no_wiki_page_writes_before_approval>
    <log_entry>One dated import entry per approved batch, opened before hub routing and finalized in place after lint, that lists only files actually created or updated (raw plus wiki pages). The hub's writes fold into that open entry under its `<appending_to_log>` rule, so the batch never appends a second one. Skip files inspected, considered, or deliberately left unchanged.</log_entry>
    <validation>Every candidate carries type and target; every CONFLICT carries both excerpts and ≥2 reconciliation options; in an explicit import invocation no wiki page is modified before approval and the log entry matches actual file changes; a mid-conversation capture validates through `<capture_raw_mid_conversation>`.</validation>
  </output_contract>
</wiki_import>
