# Narrow the Cursor scratch home's Library link to Library/Keychains, with the cursor wiki passage rewrite and its keychain-login evidence note

## Goal

Every Cursor eval worker that `tests/lib/micro_deploy.py` prepares gets a scratch home whose `Library` is a real directory holding only the `Keychains` symlink to the real `~/Library/Keychains` on the primary path, plus the fail branch's added sub-path link when `## Acceptance` 5(c) requires one. The Cursor login keeps working, and from that scratch home the only real-`~/Library` paths reachable are the helper's declared top-level `Library` links — `Keychains` on the primary path, plus any sub-path `## Acceptance` 5(c) adds outside app-state trees. Worker file searches over the scratch home then stop walking into other apps' private data (`Library/Containers`, `Library/Group Containers`), which ends the macOS "would like to access data from other apps" dialogs those searches trigger, under whichever app launched the eval.

## Context

- **Current mechanism.** `_link_library` in `tests/lib/micro_deploy.py` symlinks the scratch home's `Library` to the whole real `~/Library`, and `micro_deploy()` calls it for the Cursor vendor so the worker can reuse the stored login. The mechanism shipped with [the micro-deploy task](archive/tests_micro-deployed-eval-workers.md), whose verified finding was that an empty scratch `HOME` leaves the Cursor CLI logged out while a linked `Library` restores the login.
- **Why the whole link causes harm.** A worker that globs its own home (observed: a Glob rooted at the scratch home while resolving the `auto_drift_task` helper-agent name the harness declares, in the `mechanical_lint_ready` and `mechanical_lint_markdown` scenarios of `tests/task_auto_check/evals/run.py`) follows the link into the real `Library`. The Cursor CLI's bundled `rg` then touches every app container, and macOS raises one privacy check per container and process, attributed to the app at the top of the process chain. The link also exposes the user's Cursor app state (`Library/Application Support/Cursor/User/globalStorage/state.vscdb`, workspace storage) to workers, which weakens the isolation the micro-deploy exists for.
- **What the login actually needs (verified 2026-10-26).** The Cursor CLI stores its credentials in the macOS login keychain (account `cursor-user`, services such as `cursor-access-token`) and reads them through `/usr/bin/security`. With `HOME` set to an empty directory, `security find-generic-password -a cursor-user -s cursor-access-token` exits 44 and `agent status` reports "Not logged in". With `HOME` set to a directory whose `Library/Keychains` links to the real one, both succeed (`agent status` reports logged in).
- **Other Library reads in the CLI.** The CLI also looks for `Library/Application Support/Cursor/AgentStores`, falling back to a temporary store when it is absent, and for IDE workspace storage under `Library/Application Support/Cursor/User`, which is optional state. Neither is needed for login, per the CLI bundle's code; the live preflight in Acceptance confirms the fallback works.
- **Cleanup paths that name the link.** `MicroDeployHandle.close` and the `except BaseException:` block in `micro_deploy()` (commented "the scratch home (with its Library link) must not outlive it") remove the `Library` link before deleting the scratch tree, and `_preflight_auth`'s Cursor remedy text says the scratch home "borrows the Cursor login through its `Library` link".
- **Tests that pin the old shape.** `tests/lib/test_micro_deploy.py` asserts the whole-`Library` symlink in the checks labelled "cursor Library linked when present", "Library linked before close", and "Library unlinked before the scratch tree is removed".
- **Wiki record.** `wiki/entities/cursor.md` states that "A scratch `HOME` authenticated once its `Library` linked back to the real one", citing the 2026-10-08 micro-home probe note. Wiki edits run through the `wiki` skill per the repo's standing instructions.

## Approach

1. Rewrite `_link_library` into a keychain-only link, then rename it and its call site:
   (a) Create `scratch_home/Library` as a real directory on every pass.
   (b) When the real `~/Library/Keychains` exists, symlink `scratch_home/Library/Keychains` to it; when it is absent, leave `Library` present and empty (the same "when present" behaviour the current function has).
   (c) Fail branch of `## Acceptance` 5(c), as a path separate from the Keychains-only primary in (a)–(b):
       (i) Create the added link as one top-level entry `scratch_home/Library/<name>`, so `Library`'s entries stay a flat set of links on both paths and the enumeration in `## Acceptance` 1(a) compares link against link.
       (ii) Once that branch fires, the recorded name joins `_link_keychains`'s permanent enrolled set of top-level `Library` links. Represent that set in `tests/lib/micro_deploy.py` as one module-level enrolled-name collection that always contains `Keychains`; when `## Acceptance` 5(c) enrolls a recorded name, extend that same collection in place. Every name in that set — `Keychains` and any hardened 5(c) name — follows the “when present” rule `## Approach` 1(b) states for Keychains: create `scratch_home/Library/<name>` only when the real `~/Library/<name>` exists, and omit that entry when the target is absent.
       (iii) Write the unit checks' literal expected `Library` entry set as the Keychains-only primary (`Keychains`), still as a literal in the test rather than read from the evidence note at run time; only `## Approach` 5(c) rewrites that literal to the permanent enrolled set (`Keychains` plus a recorded name) when the measurement enrolls one. Assert each enrolled expected entry under one presence-guard rule: each enrolled name's entry is asserted only when that name's real `~/Library/<name>` exists (`Keychains` via the module-level `REAL_KEYCHAINS` carrier `## Approach` 4(d) introduces; any hardened 5(c) name via its own real-target `.exists()` guard), and omit that entry from the asserted set when its target is absent.
       (iv) Keep every top-level `Library` entry that exists a symlink resolving into the real `~/Library` under its own name.
   (d) Read the real home through one module-level seam `_real_home()` in `tests/lib/micro_deploy.py` that returns `pathlib.Path.home()`, and point the staged absent-`Keychains` check at a temporary directory through that seam.
   (e) Rename the function to `_link_keychains` and update its call site in `micro_deploy()`.

2. Rewrite both cleanup passages (`MicroDeployHandle.close` and the `except BaseException:` block) in this order:
   (a) Before `shutil.rmtree(scratch_home)`, for every name in `_link_keychains`'s permanent enrolled set of top-level `Library` links (`Keychains` and any hardened `## Acceptance` 5(c) name), when `scratch_home/Library/<name>` is a symlink, unlink that entry first — the same when-present guard the helper keeps for each enrolled name.
   (b) Keep each unlink's existing `except OSError: pass` tolerance so a denied or raced unlink stays as silent as it does today; when an enrolled name has no symlink at that path, skip that name's unlink and continue so `close()` does not raise `FileNotFoundError` that would leak the scratch tree and the `except BaseException:` block does not replace the original exception; then remove the scratch tree with `shutil.rmtree(scratch_home)`.
   (c) With `Library` now always a real directory, leave it to `shutil.rmtree(scratch_home)` and remove `close()`'s directory-shaped `Library` branches — the `library.is_symlink() or library.exists()` probe and its `IsADirectoryError` → `shutil.rmtree(library, ...)` catch.
   (d) Rewrite the block's comment to read `the scratch home (with its Keychains link) must not outlive it`.

3. Rewrite the Cursor remedy string in `_preflight_auth` so it says the scratch home borrows the login through its `Library/Keychains` link; keep the `agent login` and `CURSOR_API_KEY` guidance.

4. Rewrite the four `Library` checks in `tests/lib/test_micro_deploy.py` to the new shape in this order:
   (a) Name the three replacement labels `Keychains linked when present`, `Keychains linked before close`, and `Keychains unlinked before the scratch tree is removed`.
   (b) Assert the Library/Keychains shape and cleanup order `## Approach` 1 and 2 define (unit expected set per `## Approach` 1(c)(iii), enrolled top-level Library symlink unlink before scratch-tree removal for each name `## Approach` 2(a) covers, real Keychains still a directory after close()), and assert that every top-level `Library` entry resolves outside the app-state trees `## Acceptance` 1(a) names, so an app-state landing fails the check.
   (c) Re-point the existing `real Library untouched by close` check to assert the real `~/Library/Keychains` is still a directory after `close()`, and give it the same real-`Keychains` presence guard the section's other present-branch assertions use.

   (f) Stage the absent-`Keychains` case as the single statement of its host tests: `test_library_unlinked_before_removal` takes a second deployment whose `micro_deploy()` call runs with `_real_home()` pointed at a temporary directory holding no `Library/Keychains` entry, and asserts there the absent-case outcomes `## Approach` 1 and 2 define, while the extended `test_auth_preflight_failure_surfaces_cli_message`, run with that same seam target, owns the absent case's `except BaseException:` assertion of that same `## Approach` 2 cleanup outcome.
